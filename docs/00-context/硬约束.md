# 硬约束

## Technology
- 后端使用 Go、Gin、GORM，结构遵循 Router -> Controller -> Service -> Model。
- 前端默认实现位于 `web/`，使用 React、TypeScript、Rsbuild、Base UI 与 Tailwind CSS。
- 数据库代码必须同时兼容 SQLite、MySQL >= 5.7.8 与 PostgreSQL >= 9.6。
- 后端业务代码的 JSON marshal/unmarshal 必须使用 `common/json.go` 中的封装函数。

## Security
- 绝不提交密钥、Token、Cookie、生产凭据或真实用户隐私数据。
- 不绕过鉴权、计费、安全校验、速率限制或上游服务条款。
- 计费与额度计算不得出现负扣费、溢出回绕或未审计的饱和裁剪。

## Architecture
- Relay 请求 DTO 的可选标量字段使用指针类型配合 `omitempty`，保留显式零值。
- 数据库迁移优先使用 GORM 和跨数据库写法，避免单一方言特性。
- 涉及 tiered/dynamic billing 时，先读 `pkg/billingexpr/expr.md`。
- 修改前端可见文案时必须补齐 `web/src/i18n/locales/` 中所有支持语言。

## Upstream Compatibility
- 严格保持上游 NEWAPI 兼容是项目硬目标；新增能力优先采用独立模块、独立路由、附加字段和可选配置，不替换上游既有行为。
- 已存在的 API 路径、请求参数、响应结构、导出列、文件名和错误语义必须保持向后兼容；需要不同合同的新能力必须新增端点，不能复用旧端点并改变含义。
- 组织账单属于只读统计层，不得修改上游预扣、结算、退款、额度、订阅、渠道累计、Relay 或日志写入链路。
- 修改共享模型、迁移入口、公共工具或上游热点文件前，必须证明独立扩展无法满足；确需修改时保持加法式、可回退，并补充兼容回归测试。
- 上游同步发生冲突时，优先保留上游安全、计费和协议语义，再把本地扩展重新落到隔离边界，禁止为减少冲突而静默改变上游合同。

## Upstream Merge
- 上游同步必须执行真实的 Git 合并并生成双亲合并提交；禁止用上游目录树整体覆盖本地、按上游清单删除本地文件，或伪造只有单一父提交的“同步”。
- 同步目标默认是上游最新 RC 标签。操作前必须确认并记录本地起点、目标标签及其剥离后的 commit；存在未完成或错误合并时，先建立可追溯备份，再回到同步前基线重新合并。
- 重叠代码、同一路径且双方均修改的冲突区域，以上游实现和上游语义为准；必须按冲突区域完成合并，不能借“以上游为准”整文件或整目录抹除不冲突的本地内容。
- 上游不存在的本地独有代码、功能、脚本、资源和文档必须继续保留。上游发生目录迁移或模块重构时，应把本地独有内容迁移到新结构并做最小兼容适配，不能因旧路径被删除而遗漏。
- `docs/` 中的本地项目事实、设计、运维和归档文档属于必须保留内容；上游同名文档的重叠内容以上游为准，本地独有文档不得删除。
- 主页面是明确例外：`web/src/features/home/` 以本地定制版本为准；只允许为适配上游依赖、路由或目录结构进行必要的最小修改，不得被上游默认主页覆盖。
- 坚持最小入侵：本地能力优先放在独立文件、独立模块和附加路由中；共享入口只保留使本地能力接入上游新结构所必需的加法式修改，不复制或分叉上游核心实现。
- 合并后必须验证：目标 RC 与同步前本地提交均为新提交祖先；不存在未解决冲突；本地独有文件遗漏数为零；本地文档和主页均被保留；前后端类型检查、构建及相关测试通过。若上游自身存在基线失败，必须单独记录，不能冒充合并成功项。
- 默认只合并到本地 `main`；除非用户明确授权，不得推送远端、创建 PR 或删除备份分支。
