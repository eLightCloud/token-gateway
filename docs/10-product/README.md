# 产品文档

## 目标

说明服务对象、业务规则和可观察的验收结果。

## 放什么

角色与权限、业务流程、产品合同、账单样例及验收。

## 不放什么

接口和实现进 20；部署操作进 40；阶段与发布状态进 50。

## 阅读顺序

1. 先读[用户与角色](用户与角色.md)，再读[核心业务流程](核心业务流程.md)。
2. 按业务选专题，再用[验收标准](验收标准.md)核对跨模块结果。

| 专题 | 说明 |
| --- | --- |
| [组织与账单](组织与账单产品设计.md) / [账单表示例](账单表.md) | 成员、账单窗口、Billing 与 Invoice |
| [用户与组织实时模型折扣](用户与组织实时模型折扣产品设计.md) | 用户规则、组织继承及折后准入；是否生效取决于迁移状态 |
| [代理分销](代理分销与用户专属倍率产品设计.md) | 代理开户、名下客户、双边额度、观测与导出 |
| [Token 对账中心](Token对账中心产品设计.md) | Root 只读对账，独立于组织 Invoice |
| [睿观模型服务](睿观模型服务产品设计.md) | Vantage 受管个人套餐、企业资金与员工 Key 剩余额度 |
| [微软应用身份邮件](微软应用身份邮件产品设计.md) | Root 配置现有 SMTP 或 Microsoft Graph 发信 |

代码存在、环境已启用、生产已验收是不同状态。实际发布证据见各专题引用的计划或验证记录。

## 命名格式

使用简洁中文主题名；索引使用 `README.md`。

## 内容格式

按“用户与场景 → 流程与规则 → 验收标准”组织；索引和样例说明适用范围。 正文只设一个一级标题；当前事实文档包含 `status`、`owner`、`last-reviewed`。

## 编写要求

面向用户可观察结果；明确默认值、权限、边界和未知状态。技术入口和测试夹具用链接引用。
