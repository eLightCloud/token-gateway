## 命名格式

- 业务文档使用简洁的中文名称，例如 `Token对账中心产品设计.md`。
- 同一功能只保留一份当前产品合同，不用“最终版”“新版”等无法稳定引用的后缀。

## 内容格式

至少覆盖“用户与场景 / 流程与规则 / 验收标准”；带 `status / owner / last-reviewed` frontmatter，且只使用一个一级标题。

## 编写要求

- 描述用户可观察行为、业务口径、权限和可验收结果，不写代码文件清单或实施步骤。
- 对于数值口径，明确分子、分母、边界值和无证据状态。
- 与架构或实施方案共享的门禁、枚举和状态机必须同名、同数量、同语义。
