# 代理分销与用户专属倍率产品设计

## 状态与目标

本文是已通过业务讨论确认、尚待实施的第一期产品合同，不代表功能已上线。执行及验证进度唯一维护于[阶段实施计划](../50-planning/2026-11-03-代理分销阶段实施计划.md)，技术工作包见[实施方案](../80-dev/2026-11-03-代理分销与用户专属倍率实施方案.md)，技术合同见[架构设计](../20-architecture/代理分销与用户专属倍率架构设计.md)。

目标是支持一级代理经营：平台管理员给代理 A 分配采购额度，A 创建客户 B 并分配消费额度；B 调用时实时扣个人钱包，A 的采购支出异步批量入账。系统仅管理额度、扣费和记账，不记录实际资金、线下收款、支付凭证、佣金或现金利润。

本期代码只负责按本系统配置、实际用量及原交易快照准确计价、扣费和记账。违规费用沿用本系统现有开关、配置及专属倍率记账规则，不依赖上游商务对账；上游对账由商务人员处理。退款受理、审批及赔付由客服人员处理，本期不新增人工退款 API、页面或审批流程，也不将这些事项列为技术前置或验收阻塞。

单个代理按持续 500 QPS、连续数小时稳定调用设计。账务延迟可以扩大超用，但不能因积压、账务更新时间过旧或汇总任务故障自动暂停调用。数据库无法提交 B 的必要扣费事实时，仍按现有请求失败规则处理，不能跳过扣费调用上游。

## 用户与场景

| 身份 | 业务职责 |
|---|---|
| 平台管理员 | 新建、管理专用代理 A；增减 A 采购额度；配置 A 的模型渠道授权及采购倍率；管理平台直属普通用户 |
| 代理 A | 逐个新建客户 B；增减 B 的可用额度；配置 B 的模型渠道授权和消费倍率；停用恢复客户；查询、导出名下账单 |
| 代理客户 B | 使用现有用户登录和钱包能力，管理自己的安全设置及 API Key，调用已授权模型，查看自己的账单和倍率历史 |
| 平台直属普通用户 | 保留原有分组、钱包、订阅和访问规则；可以由管理员配置用户专属倍率，不受代理上下级授权限制 |

A 是专用代理身份，复用现有用户标识和登录基础，不提供个人钱包消费、订阅购买、个人调用 Key 或下级代理功能。采购额度独立于原生个人钱包。第一期只创建新 A、新 B，不把存量普通用户转换为代理或代理客户，不支持身份互转、客户转移、脱离代理或删除客户。

代理与组织无关系。组织的成员、报表与既有计费行为不因代理功能重定义。不把邀请码作为归属依据。

## 权限合同

| 操作 | 平台管理员 | 所属 A | B |
|---|---|---|---|
| 创建 A、增减 A 采购额度、配置 A 授权和倍率 | 允许 | 禁止 | 禁止 |
| 创建 B | 禁止从公开注册入口创建代理客户；由 A 创建 | 允许 | 禁止 |
| 增减 B 额度、配置 B 授权与倍率 | 禁止，含既有通用管理入口 | 允许，仅名下单个客户 | 禁止 |
| 修改 B 姓名等资料、发起邮箱变更 | 允许，留审计 | 仅开户及激活前流程；不获得激活后的安全凭证管理权 | 按现有个人设置及安全验证规则 |
| 平台级停用 B | 允许 | 不能解除 | 禁止 |
| 代理侧停用、恢复 B | 可查看状态 | 允许，不能解除平台停用 | 禁止 |
| 重置 B 的 MFA | 经独立人工安全恢复流程 | 禁止 | 按已有因素、恢复码及重新绑定流程 |
| 查看 B 的消费用量、费用和额度流水 | 允许审计 | 允许，仅名下 | 仅自己 |
| 查看请求正文、响应正文或客户密钥 | 按原平台权限，不因本功能扩权 | 禁止，含 API、日志和导出 | 按现有自有资源权限 |

管理员可以修改 B 的账号资料，不等于可以修改其额度、授权或倍率。上述业务边界对超级管理员及旧接口同样适用，不能依赖菜单隐藏。A 不拥有代登录或安全凭证重置能力。

## 开户与账户安全

保留当前系统的用户名、用户结构及登录方式，不改成邮箱即账号。所有用户均要求已验证邮箱和已开启 TOTP 二次认证，不能用填入邮箱或邮件验证码代替认证器绑定。

1. 管理员新建专用 A；A 在代理页新建 B，填写现有账号字段及必填邮箱，固定归属。
2. B 收到邮件，验证邮箱、自设密码、自行绑定 MFA 并保存一次性恢复码；A 不设置初始密码。
3. 完成前仅能使用激活、安全配置、必要登录及退出入口，不能创建 Key 或使用正常后台。
4. A 可重发激活邮件、纠正待激活邮箱；旧链接失效。邮箱验证令牌有时效且只能消费一次。
5. 公开注册、邀请、在线充值已由运营手动关闭；代理开户走独立管理入口，不依赖这些开关。服务端仍须阻止 B 使用其他入额路径。

存量用户未补齐邮箱验证和 MFA 时限制正常后台操作，已有 API Key 调用保持运行；旧登录会话和其他后台认证入口也须执行该限制。MFA 不要求每次模型调用输入验证码，不取代 Key 安全保护。

邮箱变更：管理员或用户发起后，新邮箱待验证，验证成功才替换，通知原邮箱；不能直接覆盖为已验证，不自动清除密码、MFA 或恢复码。原邮箱不可用时使用独立人工恢复流程。

忘记密码不清除 MFA。丢失认证器优先使用一次性恢复码；全部丢失由平台管理员经人工核验发起重置，通知用户、撤销旧登录会话、要求重新绑定。MFA 重置默认不撤销 API Key；凭证泄露通过单独、明确的紧急停用或密钥撤销操作处理。人工恢复不授予代登录能力，核验操作规程在安全上线前必须落实。

## 授权与倍率

### 模型渠道授权

精确授权键为“现有对外计费模型名＋实际渠道 ID”，不使用上游映射后的名称新增第二套模型标准，不支持通配符、销售项或分类继承。

- 管理员配置 A 的范围；A 只能从中选择并配置单个 B 的范围。A 看得到模型和具体渠道，B 只能看到模型。
- B 的有效范围为自身保存授权与 A 当前授权的交集，并继续受既有分组、Token、渠道启用状态及路由约束。
- 管理员可通过运营将模型渠道放入 `default`，但代码不强制 `default`，不删除或替换既有分组能力。
- B 创建时可选 A 当时的全部或部分授权，保存为明确选项；A 后续新增授权不自动授予 B。
- A 授权撤销后，保留 B 配置但停止生效；同一授权恢复后，B 原配置自动恢复。管理员提交前看到受影响客户数量、失效或恢复效果提示。
- 授权收回影响新请求，已受理请求按原规则完成；禁止重试绕过该请求准入范围。平台及代理停用另行控制新请求。
- 不提供跨 B 批量授权或倍率修改；单个 B 可以一次选择一个模型的多个渠道。

### 用户专属倍率

这是独立于分组、全局渠道倍率、组织渠道折扣的用户计价配置，对所有用户可配置。管理员管理 A 及直属普通用户，A 管理自己的 B。授权与倍率分开：未配置倍率按 `1`，未授权不可调用。

范围 `0 < ratio ≤ 2`，最多六位小数。允许加价，也允许 B 倍率低于 A 的采购倍率，计费差额允许为负。没有零倍率或免费开关。

设 `Q` 为 B 本次请求经过现有计费规则、分组及渠道等倍率后的费用，尚未应用用户专属倍率：

```text
B 消费额度 = Q × B 的模型渠道倍率
A 采购支出 = Q × A 的模型渠道倍率
计费差额   = B 消费额度 − A 采购支出
```

双方独立使用同一 `Q`，不叠乘 A、B 倍率，不读取 A 自身分组来重算基数，不从 B 已舍入扣额反推 A。额度精度、舍入与退款守恒由架构合同定义；计费差额不是实际资金利润。

修改倍率立即影响新请求，无需 B 确认；已有请求、异步任务、补结算和退款沿用原快照。B 可查看自己的变更历史，不包含渠道；同模型不同渠道的变更对 B 按模型聚合展示，不能用内部渠道 ID 替代脱敏。

## 额度、调用与账务流程

### 额度分配

平台增减 A 采购额度；A 增减 B 未被请求占用的可用钱包额度。不允许直接覆盖，扣减不能通过并发检查漏洞收走已预扣部分。每次记录操作标识、操作人、对象、原因、增减额、前后余额及时间；重复提交不得重复入额。

A 给 B 加额不扣 A，不产生采购支出、消费或计费差额。B 只接受所属 A 的分配和原消费退款，关闭订阅、在线充值、兑换码、邀请奖励、赠额及通用管理员入额等绕过路径。负向额度调整不等同原消费退款。

### 调用准入

1. 检查用户、代理和客户的启停状态及有效授权，B 只能走钱包。
2. 按实际选中渠道与 B 快照倍率预扣 B；换渠道需补足更高预扣，不足则停止重试。最终按实际费用多退少补，沿用现有成功、失败、断流及用量判断。
3. 读取 A 已发布的可用额度状态，不同步逐笔扣 A。已知不足则停止名下所有客户的新调用，不禁用客户登录查账。
4. A 账务积压不触发停用、不增加“数据过旧则拒绝”的规则，继续按已有余额状态准入。已受理请求继续结算，可能形成 A 负余额。B 的现有估算差额补扣也不承诺绝不欠额。

### 异步代理账

A 展示“已结算余额、处理中占用、可用额度”，其中可用额度为已结算余额减处理中占用；各项均有更新时间和待入账状态。

| 已提交业务事实 | A 记账效果 |
|---|---|
| B 预扣或追加预扣 | 增加对应采购预估占用，不计实际消费 |
| 最终结算，包括与预扣相等 | 释放原占用，记录实际采购支出与客户消费 |
| 预扣全额退款 | 释放占用，采购支出为零 |
| 已结算后部分或全额退款 | 按原交易冲回对应支出及差额，不重新应用当前倍率 |
| 退款尚未成功 | 保持待恢复状态，不提前释放或显示已退 |

上述退款项定义已确定退款事实的账务效果，不承诺客服退款入口。既有失败回滚、结算多退少补及恢复重试继续执行；保留部分退款的累计计算、原快照冲销和幂等保护。

任务提交扣额不等于最终消费；一直无结果时沿用现有超时与恢复链路，代理层不另设退款计时器。消费和退款按各自实际发生时间归属账期，退款关联原交易，不删除消费、不回写原账期；汇总执行时间不改变业务时间。

已接受取舍：A 超用无固定金额上限；持续处理故障会扩大超用，采用告警和恢复而非延迟停用。正常约一秒更新是工程目标，不能作为调用放行门槛或未验证的性能承诺。

### 启停

- A 可停用 B：禁止 B 登录与新调用，保留额度、配置和记录，已受理请求继续结算退款；不支持删除。
- 平台可独立停用 B；A 恢复不能解除平台限制。
- 平台停用 A：A 自身账号不可登录，全部客户停止新调用；不批量改写客户个人停用标志。恢复 A 不解除 B 自身限制。
- A 额度不足只影响新调用，不等同停用代理资格；补额或退款发布后按余额恢复。

## 页面与导出

在当前后台构建代理页面，不建立独立站点或替换主页。基础布局、表格、确认、弹窗、格式化及安全设置优先复用项目组件。

| 页面 | 内容 |
|---|---|
| 平台代理管理 | 创建和启停 A、采购额度流水、A 的授权及采购倍率、授权变更影响提示 |
| A 概览及采购流水 | 已结算余额、处理中占用、可用额度、待入账提示及更新时间 |
| A 客户管理 | 单客户创建和激活状态、额度增减、授权、倍率、停用恢复 |
| A 消费账单 | 客户、模型、实际渠道、用量、客户扣额、采购支出、计费差额、结算及退款关联 |
| B 原有消费与安全页面 | 保留个人钱包及日志，新增实际倍率及倍率历史；屏蔽渠道和其他入额入口 |

A 可导出名下客户消费账单和额度流水，使用与页面相同的筛选、权限和计算口径。导出包含账期、业务发生时间、数据更新时间与入账状态，不用未完成账务伪装完整账单；不含正文、密钥或可用认证凭证。可导出已存在的待入账记录，但未保存或尚未生成的结果不得估算填零。

模型广场：未登录维持标准价；登录后展示本人专属倍率，不显示 A 采购倍率。同一模型在有效可用渠道的倍率不同则展示范围，未配置渠道计入 `1`，不显示渠道。全部为 `1` 不展示折扣，小于 `1` 显示折扣，大于 `1` 显示倍数；不展示一个确定的折后价格，不将专属倍率冒充最终价格。

### 导航与页面入口

保留当前侧栏、页头、表格、主题和响应式布局，不重新设计整套后台。导航按业务身份和服务端能力显示，不能通过把 A 提升为系统管理员来开放代理菜单。

| 身份 | 导航及默认入口 |
|---|---|
| 平台管理员 | 新增“代理管理”；现有用户管理增加账号类型和所属代理筛选，按身份收窄行操作 |
| A | 默认进入“客户管理”；提供“消费账单、采购额度流水、账户安全”，采购概览合并在客户管理顶部 |
| B | 保留现有消费概览、模型广场、API Key、消费日志、任务记录、额度和账户安全；移除其他入额与订阅入口 |
| 平台直属普通用户 | 保留原有页面和导航，只增加适用的专属倍率展示与全局安全补齐 |

A 不展示个人消费钱包、订阅、个人调用 Key、渠道管理或系统设置。导航隐藏之外，直接访问 URL 和后台 API 也不能越权。

### 平台代理管理

代理列表提供创建、搜索及状态筛选，展示代理账号、资格状态、可用采购额度、处理中占用和账务更新时间。进入代理详情查看采购流水、授权及采购倍率；增减额度使用独立弹窗，启停使用明确影响范围的确认框。

管理员用户列表仍可查看 B、编辑允许的资料、执行平台停用及独立安全恢复，但不展示 B 的额度调整、商务授权倍率修改、订阅配置、删除或身份转换操作。安全恢复不得混在普通“编辑资料”中。

### A 的客户列表与详情

客户管理以操作为主，不增加一期非必要的经营图表。顶部展示可用采购额度、处理中占用、已结算采购余额和账务更新时间；下方是客户搜索、激活与服务状态筛选，以及创建按钮。

```text
客户管理                                      [创建客户]

可用采购额度          处理中占用          已结算采购余额
账务更新于……；部分记录待入账

[搜索账号或邮箱]    [激活状态]    [服务状态]
账号 | 邮箱 | 激活状态 | 服务状态 | 可用额度 | 操作
```

列表不提供跨客户勾选批量操作。常用行操作为“详情、调整额度”，停用恢复放入更多操作。激活状态区分待验证邮箱、待绑定 MFA 和已激活；服务状态区分正常、代理停用、平台停用。额度不足是调用受限原因，不伪装为账号停用，多个限制同时存在时不能只展示最后一次操作。

客户复杂配置使用可直接访问、可返回列表的独立详情页；创建客户、增减额度及停用确认使用现有弹窗或抽屉布局。详情分四个页签：

| 页签 | 展示与操作 |
|---|---|
| 基本信息 | 账号、邮箱、激活情况和服务状态；待激活时重发邮件或纠正邮箱；不提供激活后的密码、邮箱和 MFA 接管操作 |
| 模型授权与倍率 | 同一工作区完成当前 B 的显式授权及精确模型渠道倍率配置 |
| 消费明细 | 当前 B 的模型、实际渠道、用量、客户扣额、采购支出、计费差额和退款关联；可导出 |
| 额度流水 | 当前 B 的额度增减、消费暂扣/结算调整及退款，区分业务类型，不把最终消费再次累加成一次钱包扣款 |

额度调整仅“增加、扣减”，填写正数额度和必填原因，展示预计前后余额；最终结果以服务端提交值为准。禁止覆盖、重复提交与扣减已预扣部分。失败保留输入，明确余额变化或权限变化原因。

### 单客户模型授权与倍率工作区

左侧搜索并选择模型，右侧显示其渠道、客户授权、客户倍率和生效情况。A 能查看自己有权配置的具体渠道；历史保留但上级当前已撤销的项以只读失效状态展示，不作为新授权选项。

| 渠道 | 客户保存授权 | 客户倍率 | 生效情况 |
|---|---|---|---|
| 渠道甲 | 已选 | 0.90 | 生效 |
| 渠道乙 | 已选 | 0.85 | 上级授权已撤销，配置保留 |
| 渠道丙 | 未选 | 未配置 | 未授权 |

“未授权”“已授权但倍率未配置，按 1”“上级撤销导致失效”必须分别呈现。支持对同一 B 选择一个模型的多个渠道，不能扩展成跨客户批量功能。显式保存后对新请求生效；离开未保存页面有提示，并发版本冲突提示刷新对比，不能静默覆盖。

管理员撤销或恢复 A 的授权时，提交前显示受影响客户数量和自动失效/恢复说明；不删除客户历史配置。倍率输入显示允许范围和精度，错误靠近字段，不只给一个泛化失败提示。

### 账单与异步状态

A 消费账单按客户、模型、时间和状态筛选，展示客户扣额、采购支出、计费差额、退款关联，并可进一步查看当笔实际渠道。A 的采购流水另行记录管理员调额、占用变化、采购扣减和退款，不能把占用当作采购费用。

账单使用两个独立状态维度：

- **业务状态**：处理中、已结算、部分退款、已退款；处理中只显示预估占用，不能计入已结算支出或差额。
- **入账状态**：待入账、已入账；表示代理汇总处理进度，与请求是否完成不同。

账务更新时间、待入账标记与筛选区一起常驻展示；延迟使用普通提示，不使用阻塞弹窗、全页错误或停用状态。未产生最终结果显示“待结算”，不填零假装免费；已有结果只是未汇总时可展示结果并标明待入账。表格汇总不能静默合并不同状态。

已确认代理额度不足时，A 显示“采购额度不足，客户新调用受限”；B 保留自己的余额和登录查账能力，只显示调用受限及联系代理的提示，不公开 A 的余额。代理资格或客户账号停用按登录限制单独处理。

页面与导出共享筛选、业务时间口径及状态定义，导出标明数据更新时间和截止条件，不能把暂扣、最终消费和退款重复加总。

### B 的消费界面与安全补齐

B 的额度页保留余额及入额/消费/退款记录，移除充值、兑换、邀请、订阅和扣费来源选择；不创建另一套个人消费日志。模型卡片在现有标准计价信息旁增加专属倍率标记，不替换原有单价。例如统一 `0.8` 显示“专属八折”，`0.7–0.9` 显示“专属七至九折”，混合折扣及加价显示“专属倍率 0.8–1.2”。实际消费详情展示当笔实际采用的倍率，历史仍不显示渠道。

安全未完成时进入用途明确的受限步骤页：验证邮箱 → 首次激活自设密码 → 绑定认证器 → 保存恢复码；存量用户不强制重复设置已有密码。页面说明已有 API Key 继续调用，不把安全补齐做成可忽略的普通通知。恢复过程中仅展示允许的安全操作，不加载正常后台业务数据。

安全中心继续复用现有绑定组件，但不提供普通“关闭 MFA”按钮，改为受验证的因素更换或恢复流程。A、B 均不提供自助删除账号。新客户激活不能顺带开放访问令牌等正常后台能力。

### 交互与可访问性

沿用现有主题、中文英文、数值格式和响应式表格。宽屏表格保留关键列，移动端使用现有卡片列表或详情承载完整字段。状态同时有文字和语义，不能仅靠颜色；输入有可访问标签，弹窗支持键盘与焦点恢复。筛选、分页和详情路径可恢复，加载、空状态、失败重试有明确区别。查询失败不伪装为空列表或零余额。

## 验收标准

| 编号 | 用户可观察的通过条件 |
|---|---|
| P01 | 专用 A、固定归属 B、平台直属普通用户边界清晰，无法互转或越权操作 |
| P02 | 额度增减原子、可追溯、可去重；B 无其他入额路径、无订阅绕过 |
| P03 | 模型渠道授权、部分渠道限制、撤销恢复、新增不继承在页面及实际请求均成立 |
| P04 | `0 < ratio ≤ 2` 与默认 `1` 正确；共同基数、独立倍率、负差额、快照及渠道重试正确 |
| P05 | 预扣、零差额完成、补结算、既有失败及超时退款、重复恢复均账实相符；对已确定的部分退款按原交易准确冲回，不重复或超额退款 |
| P06 | 账务积压不暂停调用；已知 A 不足或停用阻止新请求，已受理请求可完成 |
| P07 | A 仅看名下用量费用；B 的页面、JSON、历史和导出均无渠道信息；敏感内容不泄露给 A |
| P08 | 强制安全补齐覆盖所有后台认证入口；已有 Key 保持调用，恢复及泄露处置语义分离 |
| P09 | 页面与导出同口径、跨月退款独立入账、延迟清晰可见；单代理持续负载及三数据库证据齐全 |
| P10 | 身份导航、客户详情、授权失效状态、安全步骤及双维账单状态可操作且一致；无跨客户批量、覆盖额度、关闭强制 MFA 或代理客户自助删除入口 |

## 一期不包含

多级代理、独立站点、邀请、公开开户、存量身份迁移、客户转移、实际资金与支付、佣金提现、订阅代理计费、通配符、跨客户批量配置、额度池、逐请求同步扣 A，以及因账务积压自动熔断调用。
