# 微软应用身份邮件产品设计

## 状态与文档边界

本文定义 Microsoft 365 应用身份发信与系统配置 UI 的产品合同。独立 Graph 测试邮件已由收件人确认送达，网关的 Graph 发信路径已通过实际受理验证。技术合同唯一见[架构设计](../20-architecture/微软应用身份邮件架构设计.md)，早期 SMTP 方案与验证记录见[实施方案](../80-dev/2026-11-05-微软应用身份邮件实施方案.md)。本专题不改变 new-api 与 QuantumNous 的项目标识。

## 用户与场景

平台 Root 为系统配置专用 Microsoft 365 企业邮箱，使验证码、账号激活、密码恢复、安全变更及运营通知可在无人交互时自动发送。普通管理员、代理、组织管理员和普通用户不能读取、修改或测试系统发信凭据。

应用由租户管理员授权；业务用户不需要登录微软、不需要周期性重新授权，也不需要手动维护访问令牌。系统邮件配置与“使用微软账号登录本系统”的 OAuth/OIDC 登录配置相互独立。

Microsoft 365 模式支持国际版企业租户、单租户应用、Client Secret 和 Microsoft Graph 应用身份发信。个人 Outlook 邮箱、世纪互联及其他主权云、证书或联合身份凭据、用户委托授权不在本次交付范围。

## 流程与规则

### 系统配置入口与表单

沿用“系统设置 → 运行与监控 → 邮件”所在页面及现有 `/system-settings/operations/email` 路径。

认证方式只有两个产品选项：

| 选项 | 用户看到的配置 | 行为 |
| --- | --- | --- |
| 现有 SMTP | 主机、端口、账号、发件地址、密码凭据、传输安全与兼容选项 | 保留现有 PLAIN/LOGIN/NTLM 选择和现有免认证中继行为 |
| Microsoft 365（Microsoft Graph） | Tenant ID、Client ID、Client Secret、发件邮箱 | 后台申请 Graph Token，使用应用身份调用 `sendMail` |

Microsoft 模式提示应用需要拥有发件邮箱的 `Mail.Send` 权限。已保存的 Microsoft 租户、应用、密钥和发件邮箱可以直接沿用。后端按已保存的模式选择发信通道。

切换选项只修改表单草稿，点击保存后整体生效；切回现有 SMTP 时保留原 SMTP 配置，未启用的微软配置也保留，只有显式清除才删除应用密钥。离开有未保存修改的表单使用项目既有离开提示能力；刷新前未保存草稿不自动恢复。

### 密钥保留、轮换与清除

- 读取配置只返回“已配置／未配置”和部署加密能力状态，不返回任何历史密钥，也不用星号字符串充当真实密钥。
- 已配置时输入框保持空白，明确说明“留空保留现有密钥”；输入非空值表示轮换。密钥值不自动 trim，避免改变凭据。
- 清除是单独的显式操作，使用现有确认对话框。活动模式仍为 Microsoft 时禁止清除；可在同一次保存中先切回现有 SMTP，再清除应用密钥。
- 首次启用或切换 Tenant ID／Client ID 时必须输入新密钥，不能默默沿用另一个应用的密钥。
- 部署未提供有效加密密钥时，页面显示部署提示，拒绝保存新的应用密钥；既有 SMTP 服务继续可用。首次整体保存如需将旧 SMTP 密码迁入新配置，也必须先满足部署加密条件；页面应在保存前明确提示。
- 保存、测试和轮换期间显示忙碌状态并防止重复提交；保存失败保留本次草稿，服务端现行配置不变。成功后清空密钥输入及携带密钥的临时提交对象。

配置保存及实际测试发信需要 Root 权限与系统现有敏感操作二次验证；邮件故障不能让验证过程改走邮件恢复来绕过既有验证要求。

### 保存与测试是不同动作

保存执行完整配置校验并一次提交；不依赖微软网络，不因 Token 服务暂时不可达阻止保存。保存成功显示“已保存，尚未验证发信”，不能显示“邮箱可用”。

“发送测试邮件”仅使用已保存配置，要求表单无未保存修改并填写一个合法收件邮箱；不允许自定义标题、正文或批量收件人。此操作会真实发送一封固定测试邮件，按钮附近明确说明。测试不修改系统通知接收人，不触发注册、找回密码等身份业务。

Microsoft 模式的测试结果显示配置检查、Token 获取和 Graph 提交。现有 SMTP 模式仍显示连接／TLS、SMTP 认证和邮件提交，Token 阶段显示“不适用”。受理结果提示查收邮件以确认送达。提交结果不确定时，提示先检查收件箱再重试。

未执行过测试、保存后尚未测试、测试通过、测试失败和结果不确定分别展示；测试结果附配置版本和时间，配置再次保存后旧结果标记为已过期。本次结果为页面会话反馈，不增加持久投递状态中心。

错误在结果区和相关字段附近说明原因及可执行的下一步，不能只弹 toast；键盘可定位错误字段，异步结果通过可访问状态区域播报。窄屏单列、长 ID 可换行或在输入框内滚动，沿用现有主题和设置页样式。

### 发送触发与通知规则

统一邮件发送入口继续服务现有业务：注册验证、密码恢复、代理及客户激活、安全邮箱验证、邮箱绑定／变更、安全通知，以及通过邮件通道发送的额度、通道状态和上游模型巡检通知。本专题只替换认证方式，不新增日常登录邮件、充值成功邮件或营销邮件。

验证与安全邮件继续发送到账户相关邮箱；运营通知继续按现有通知方式、通知邮箱及限流规则决定是否走邮件。本专题不把 Webhook/Bark/Gotify 强制改成邮件，不修改验证码和恢复链接有效期。

## 验收标准

1. Root 能在原邮件设置页面完成应用身份配置、保存、刷新、轮换和测试；普通 Admin 或其他角色无法直接调用相应接口。
2. 首次配置、空白保留、换应用强制换密钥、显式清除和模式切换有一致的前后端校验；取消二次验证不会保存或发信。
3. 保存原子化：任何字段无效、版本冲突或数据库失败时，旧配置完整保留，不能部分启用新模式。
4. 真实租户可收到测试邮件及至少一类身份业务邮件；Token 自动续取后仍可发信。无有效凭据时明确失败，不能回退 Basic 或匿名发送。
5. 页面、接口、浏览器持久存储、审计与服务日志不泄露应用密钥或 Token。
6. 现有 SMTP、通知选择和业务邮件触发行为无回归；中英文文案完整，遗留语言文件不新增 key。
7. 测试通过表示邮件服务已受理该配置版本的请求。实际投递和权限负向验证分别留证。
