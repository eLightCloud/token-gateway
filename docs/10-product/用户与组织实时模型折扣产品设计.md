# 用户与组织实时模型折扣产品设计

## 状态与文档边界

本文维护已确认、待实施的实时消费折扣产品规则，不代表功能已上线。界面合同见 [UI设计](../90-ui-ux/用户与组织实时模型折扣UI设计.md)，技术合同见 [架构设计](../20-architecture/用户与组织实时模型折扣架构设计.md)，工作包与验证状态见 [实施方案](../80-dev/2026-11-05-用户与组织实时模型折扣实施方案.md)。

本专题取代既有专属倍率设计中关于实时消费倍率按渠道独立设价、未配置直接取 1、用户与新增组织实时倍率叠乘的目标表述；不重定义代理身份、授权、采购记账及资金来源。代理采购倍率仍按原业务合同独立处理，不能用本专题的消费倍率继承推导采购费用。

既有组织渠道折扣及事后 Invoice 结算系数保留，不删除、不自动置 1、不改写历史。运营可以另行把旧配置设为 1。本专题新增实时定价能力，不把既有 Invoice 统计改造成资金写入入口。旧组织渠道折扣实际已经参与部分请求计费，不应将所有旧配置统称为仅事后生效；两套配置的技术边界和上线检查见架构设计。

## 用户与场景

- 平台运营为组织统一维护模型折扣，使未配置个人覆盖的组织成员请求按组织规则实时预扣和结算。
- 有现有配置权限的管理员为普通用户设置个人覆盖；代理客户仍由所属代理按既有权限管理，不因加入组织而开放其他配置入口。
- 组织成员查看自己的实际消费倍率和来源，不因本功能获得组织配置、内部渠道或其他成员数据的管理权。
- 折扣属于个人消费定价，不新增组织钱包，不改变钱包、订阅及代理客户资金来源规则。

组织实时规则的查看、编辑、历史及组织默认折扣预览仅限平台 Root；平台普通 Admin、组织管理员和成员均不能管理。用户规则继续沿用现有配置权限，组织配置权不授予修改代理客户个人倍率的权力。

## 流程与规则

### 一模型一倍率，多渠道适用范围

每个用户或组织内，同一模型只能保存一条规则，包含一个倍率和一个非空渠道集合。唯一性是“主体＋模型”；模型使用现有对外计费模型名，渠道使用稳定 ID。

用户和组织实时倍率统一为 `0 < ratio ≤ 5`，最多两位小数，即最小 0.01、最大 5；支持折扣、原价和加价，不支持免费倍率 0。旧组织渠道折扣不随之改变范围。存量个人倍率不符合新范围或精度时必须明确处理，不能自动舍入。

- 允许：组织甲的模型 A，渠道 B/C，倍率 0.8；模型 D，渠道 B/E，倍率 0.9。
- 禁止：组织甲同时保存“模型 A、渠道 B/C、0.8”和“模型 A、渠道 F、0.9”，即使渠道集合不重叠也不允许。
- 增加模型 A 的适用渠道必须编辑同一条规则，新增渠道与原渠道共享一个倍率。
- 渠道集合仅定义折扣适用范围，不授予、限制或改变路由权限；授权、分组、渠道启停、Token 限制及故障切换继续独立执行。

### 逐个实际渠道选择倍率

规则命中必须同时满足模型一致及实际执行渠道属于规则集合。按顺序选取一个倍率，不能相乘：

1. 已启用的用户规则命中：使用用户倍率。
2. 否则组织规则命中：使用当前组织倍率。
3. 否则使用额外倍率 1，沿用系统正常计价。

个人规则停用时保留倍率和渠道范围，保存后恢复继承，重新启用后按原配置生效。用户在其他模型或其他渠道上有配置，不阻断当前请求继承组织。用户显式配置 1 仍是有效覆盖，仅在其选中渠道按原价；删除整条用户规则恢复全部继承，移除单个渠道仅让该渠道恢复继承。

| 配置示例：用户模型 A 覆盖 B/C、0.9；组织模型 A 覆盖 C/D、0.8 | 实际倍率 | 来源 |
|---|---|---|
| 实际渠道 B | 0.9 | 用户 |
| 实际渠道 C | 0.9 | 用户优先 |
| 实际渠道 D | 0.8 | 组织 |
| 实际渠道 E | 1 | 系统默认 |

同一主体同一模型配置倍率唯一，不承诺同一用户对该模型的所有调用倍率相同；实际渠道不同，命中来源和倍率可以不同。

### 实时预扣、结算及生命周期

实时扣费目标是系统基础费用乘选中的一个消费倍率。基础费用继续由既有引擎处理模型价格、分组、用量等规则，旧配置边界见架构设计。

- 先按实际候选渠道匹配倍率，再以折后预估金额执行准入和预扣。预估基础费用 100、组织 0.8、用户无覆盖、余额 85，应允许预扣 80；最终按同一冻结规则对实际基础费用结算。
- 保留既有信任免预扣：满足现有信任条件的请求免实际预扣，最终仍按冻结倍率计费。组织折扣不扩大信任资格，代理客户和强制预扣任务继续执行原限制。余额准入仍按有效折后金额检查；免预扣不代表免费或新授信。
- 请求开始时冻结相关用户与组织规则和版本。配置修改、成员变动或退出组织不重新定价已受理请求，新请求读取最新有效配置。
- 重试换渠道从冻结规则中重新匹配目标渠道；非信任请求发送前补足更高预扣，补扣失败不得发送；信任请求沿既有免预扣策略处理。退款遵循既有消费事实和资金生命周期，不能把未知上游结果当作未消费。
- 异步任务、补结算和退款沿用原请求倍率与来源，不读取当前规则重新定价；最终消费不因预扣与实际金额相等或折后舍入为零而漏记。Midjourney 保持钱包资金和强制预扣合同，不能因普通用户进入新计费链路而选中订阅或获得信任免预扣；其日志同样记录实际倍率、来源和版本。

### 配置行为

选择模型后只能选择实际支持该模型且操作者有权配置的渠道。新增规则至少选择一个渠道，不支持自由输入渠道 ID、通配模型或跨用户批量修改。

新增渠道不自动加入既有规则；“全选”只选保存时明确的渠道集合。停用或模型支持关系变化不静默改写已保存规则，也不允许失效渠道参与调用。

并发修改必须提示配置冲突，不能覆盖他人变更；历史记录倍率、适用范围、操作者及时间。无配置与显式 1 分开显示。旧配置存在同模型多倍率时不得擅自取最小、最大或最新值，迁移前需明确解决冲突。

切换后普通用户的旧消费写接口一律拒绝，包括提交空列表删除；不能返回成功却保留实际生效的新规则。代理采购和客户授权继续沿各自边界处理。迁移仅聚合仍存在且未软删除的消费主体，保留已删除主体的旧记录与历史，不将其不可编辑的配置冲突当作启用阻断；发布版本升级后身份列为 SQL NULL 的普通用户必须正常纳入。

整份保存使用用户或组织的配置总版本，两人修改不同模型也不能相互覆盖。删除全部规则后版本仍保留，重建规则不能恢复旧版本。迁移期间暂停消费倍率配置写入；切换后新请求只使用新消费规则，已受理请求和历史任务继续沿用旧快照，不重复应用旧个人倍率。

## 验收标准

1. 同一用户或组织同一模型只允许一个倍率，前端重复添加和直接 API 绕过均被阻止。
2. 同模型多选渠道共享倍率；未选渠道不会因规则存在而失去路由资格。
3. 用户、组织、系统逐项继承结果符合上表；启用的个人规则即使显式为 1 也优先。停用、删除或移除渠道后恢复继承。
4. 折扣和加价均按生效金额准入，额度不足提示与准入门槛一致；非信任请求真实预扣，符合原信任条件的请求免预扣但仍正确结算；受限 Token、订阅及强制预扣限制继续生效。
5. 修改配置只影响新请求；重试、异步成功/失败、断流、退款和恢复无重复乘倍率或重复扣退。
6. 管理员可查看按渠道的生效预览；无渠道查看权限的最终用户只查看脱敏的倍率、范围和来源。
7. 旧组织配置、历史账单和代理采购记账不因本专题被自动改写；新实时折扣只应用一次。
8. 倍率 0.01、1、5 允许，0、负数、超过 5 或超过两位小数拒绝；组织写入/配置历史/默认折扣预览的 Root 边界由服务端验证。
9. 两人修改不同模型、删后重建及并发转组不导致配置覆盖或混合快照；迁移切换不重复计价。个人历史跨越新旧计价版本时应可连续翻页，不因双方版本号独立而漏掉历史。

## 已固定参数与迁移输入

已确认保留既有信任免预扣、用户与组织实时倍率统一 `(0, 5]` 且最多两位小数、组织实时配置仅 Root 管理。具体存量同模型多倍率和精度冲突必须以迁移前实际数据清单为依据逐项处理；未获明确处理结果不得自动改价或启用迁移。
