# 睿观模型服务产品设计

## 用户与场景

本专题定义 Vantage 受管账户的模型资金、个人套餐与只读账单目标。设计已确认，实现与部署状态只见[路线图](../50-planning/路线图.md#vantage-model-service)；当前代码并未完整提供下述能力。

| 用户 | 业务任务 | 操作入口 |
| --- | --- | --- |
| Gateway 管理员 | 为独立个人或企业资金账户手动充值 | Gateway 管理后台 |
| Vantage 平台管理员 | 审批独立个人的套餐申请或主动配置 | Vantage 平台管理端，由 Gateway 无支付开通 |
| 独立个人用户 | 查看本人钱包、套餐、账单并申请订阅 | Vantage 设置 → 账单 |
| 企业管理员 | 查看企业资金及消费，为员工设置剩余额度 | Vantage 设置 → 账单（本人或企业视图） |
| 企业员工 | 查看本人剩余额度和消费 | Vantage 设置 → 账单（本人或企业视图） |

Gateway 的 `Organization` 仍是既有报表组织，不是 Vantage 企业共享钱包。Vantage 企业对应一个受管账户，员工使用该账户下的独立 Key；本专题不建立组织余额或员工独立钱包。Vantage 页面规则由消费方[产品专题](../../../vantage-ai-center/docs/10-product/40-企业身份与资源设计.md#lighting-plans)拥有；两仓按同级目录核对配套文件，运行时不依赖该目录关系。

## 流程与规则

### 钱包与充值

资金、赠送、充值、预留、扣费、结算和退款由 Gateway 唯一拥有。个人开户沿已有一次性赠送规则，企业开户不自动获得个人赠送。赠送进入原钱包，不另建免费额度钱包，也不按查询重新发放。

管理员在 Gateway 为目标个人或企业账户充值，记录准确账户、金额、操作者、时间及实际入账结果。Vantage 没有充值发起或支付入口；用户余额不足时提示联系管理员。企业管理员修改员工额度不是充值，不改变企业余额。

### 个人套餐

1. 套餐仅面向独立个人，目录、额度、有效期和重置规则使用 Gateway 已维护的配置。企业及其员工不能开通个人套餐。
2. 个人在 Vantage 账单申请订阅；平台管理员收到站内通知，可批准、拒绝或主动配置。申请本身不发放权益，未决申请可由本人撤回，每人至多一项待审。
3. 套餐同步与人工配置不依赖支付合规开关，不对接任何支付、不扣钱包；不要求套餐允许余额购买。Gateway 普通支付流程继续遵守原生支付保护。
4. 每人至多一个有效套餐；管理员可更换、修改到期或结束。更换结束旧权益并新建套餐；同套餐调整到期保留已消费额度；修改以当前配置修订防止覆盖并发变化。无叠加、自动续费、差价或退款。
5. 套餐优先使用；不适用、到期或可用额度不足时，沿原生单次请求规则使用钱包；受管套餐必须允许钱包后备。套餐不提升 Vantage 模型授权。
6. 原生权益、零扣款人工开通记录及幂等回执一起成功或一起失败，钱包余额保持不变。已有历史钱包购买金额仍准确展示，旧扣款意图只恢复，不新增。

### 企业资金与员工额度

企业账户共享资金，员工 Key 默认无限。这里的无限仅指没有员工附加上限，仍受企业真实余额和原生请求准入约束。

企业管理员可以设置员工当前剩余额度，或恢复无限。例：员工过去已消费 80 元，当前设为 100 元后还能使用 100 元，后续消费 30 元则剩余 70 元；此例以汇率未变、无在途请求为前提。既不减历史累计消费，也不进行月度恢复；没有员工资金划拨和回收。历史消费保持只读，设置为零可以阻止该员工后续付费调用。

### 人民币与汇率

Vantage 金额展示与输入统一人民币，换算读取 Gateway 汇率设置。原钱包与 Key 仍按原生 quota 计账：当前钱包和员工剩余额度按当前汇率换算，设置人民币额度时按操作接受时汇率一次换算为原生额度。

例如钱包剩余 10 USD，汇率由 7.0 调为 7.5，当前余额由 70 元变为 75 元；历史消费仍显示发生时确定的人民币金额。套餐当前报价使用当前汇率，历史购买记录固定购买时金额。汇率展示差额不是充值、退款或新的消费，不要求历史人民币收支与当前余额构成固定差额等式。

### 简单账单

Vantage 使用独立「设置 → 账单」菜单，与账号与安全、模型设置同级；企业管理员可切换企业／本人视图，普通人员仅本人，模型配置及成员管理只提供定位跳转。采用账户概览、消费明细和充值记录，不建设完整财务总账或开票系统。所有这些记录（含历史套餐购买）必须在 Vantage 内可查询，不能以跳转 Gateway 或要求用户另登录 Gateway 作为交付；Gateway 管理后台仅供运营充值和排障。

- 概览：个人查看当前钱包与套餐；企业管理员查看企业余额；员工查看本人剩余额度或无限。未提供指标不补零，不增加缺少事实的累计金额。
- 消费明细：时间、模型、人民币金额、套餐／钱包来源；退款明确区分。企业管理员可按员工筛选，员工只看本人。
- 充值记录：个人及企业账户的管理员入账与赠送；已有扣减／覆盖调额按实际有符号变动标明调整，不能伪装充值。员工没有独立充值记录。
- 人工开通保存零扣款记录，在套餐区显示无需支付；历史钱包购买保留原扣款金额。它们不是钱包入账。套餐模型用量与购买支出分别解释，不能相加冒充钱包扣款。

记录不可编辑。失败、未提供和确定为零分别表达；旧消费没有可信历史汇率时标明人民币金额未提供，不以当前汇率补造历史事实。套餐、金额或日志查询失败不能返回伪造空结果。

## 验收标准

| 编号 | 可验证结果 |
| --- | --- |
| VG-01 | 个人／企业绑定唯一；组织报表不变成钱包，个人赠送幂等且企业不误领 |
| VG-02 | 管理员充值可追溯到实际账户与不可变入账事实；员工调额不改变企业余额 |
| VG-03 | 套餐只向独立个人无支付配置；配置修订冲突、禁用套餐明确拒绝，原权益完整保留且钱包不变 |
| VG-04 | 重复／并发代购只扣一次、只开通一次；请求超时后可查询原操作结果 |
| VG-05 | 套餐优先，耗尽／到期后原生钱包后备生效；余额不足拒绝，不改变模型授权 |
| VG-06 | 新员工默认无限；设置 100 元后不减历史 80 元；消费递减且可恢复无限／设零 |
| VG-07 | 额度编辑与在途结算并发不丢费用；Key 不重建、历史用量不清零 |
| VG-08 | 当前余额随汇率变化；同一消费、退款与购买记录的历史人民币金额不被后续配置改写 |
| VG-09 | 个人仅查本人，企业仅查本企业，员工仅查本人 Key 的历史记录；撤销不抹除有权历史 |
| VG-10 | 模型消费、套餐购买与入账不重复统计；日志关闭、历史汇率缺失及查询失败真实可辨 |
