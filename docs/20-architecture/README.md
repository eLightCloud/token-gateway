## 不放什么
- 产品需求与流程 -> 10-product/
- 运维手册与监控 -> 40-operations/
- 一次性排障过程 -> 不进入 docs；已确认结论直接更新本目录，过时历史进入 99-archive/

## 命名格式

- 架构业务文档使用中文名称，例如 `Token对账中心架构设计.md`。
- ADR 使用 `decisions/NNNN-中文短标题.md`，不用一般架构文档代替需要独立审批的架构决策。

## 内容格式

至少覆盖“系统边界 / 当前设计 / 职责与依赖 / 数据或控制流 / 约束与取舍 / 验证策略”；带 `status / owner / last-reviewed` frontmatter，且只使用一个一级标题。

## 编写要求

- 架构文档表达当前可依赖的设计合同，不按提交、日期或排障顺序追加流水账。
- 图与正文必须一致；关键不变式要同时给出失败策略和可验证断言。
- 对现有模块的改动要列明最小接线面与保持不变项，不以复用为由扩大旧模块职责。
