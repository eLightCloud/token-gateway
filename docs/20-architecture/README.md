# 架构文档

## 目标

解释模块边界、数据流、依赖和架构取舍。

## 放什么

系统与部署拓扑、数据模型、接口及关键决策。

## 不放什么

用户体验进 10；开发命令进 30；现场操作进 40；临时实施记录进 50/80。

## 阅读顺序

1. [架构概览](架构概览.md) → [数据模型](数据模型.md) → [架构决策记录](decisions/README.md)。
2. 按变更范围读专题；跨地域配置按[部署架构](部署架构.md)核对目标拓扑。

| 边界 | 专题 |
| --- | --- |
| 组织与报表 | [组织与组织账单](组织与组织账单架构设计.md)、[Token 对账中心](Token对账中心架构设计.md) |
| 请求定价与分销 | [实时模型折扣](用户与组织实时模型折扣架构设计.md)、[代理分销](代理分销与用户专属倍率架构设计.md) |
| Relay 生命周期 | [文本流断开续读](流式断开续读架构设计.md) |
| 管理接合与通知 | [睿观模型服务](睿观模型服务接合设计.md)、[微软应用身份邮件](微软应用身份邮件架构设计.md) |

## 命名格式

使用简洁中文主题名；ADR 另用 `decisions/NNNN-中文短标题.md`；索引使用 `README.md`。

## 内容格式

按“边界 → 职责与依赖 → 数据或控制流 → 约束与取舍 → 验证”展开。 正文只设一个一级标题；当前事实文档包含 `status`、`owner`、`last-reviewed`。

## 编写要求

区分现有代码、部署条件与设计目标；关键不变式要对应失败处理和验证入口。历史决策留在 ADR。
