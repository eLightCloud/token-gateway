# ADR-0003: 代理额度异步记账与用户专属倍率

## Context

业务确认采用专用一级代理：A 创建客户 B、分配钱包额度，调用时分别按各自模型渠道倍率记账。平台只管理额度，不涉及实际资金。单代理需支持持续 500 QPS、连续数小时调用；逐请求更新 A 汇总余额会形成集中写热点。

现有 B 钱包、Token、BillingSession 和结算 journal 可以承载实时扣费，但 journal 完成后会清理；组织不是采购账户，邀请奖励也不能表达该业务。用户已接受代理余额延迟和无固定上限的超用，明确拒绝因账务积压暂停调用。

本 ADR 记录已确认的目标决策，尚未实现，不取代组织折扣 ADR。产品规则见[产品设计](../../10-product/代理分销与用户专属倍率产品设计.md)，技术合同见[架构设计](../代理分销与用户专属倍率架构设计.md)。

## Decision

1. B 保持真实用户钱包扣费；A 使用独立采购账户，专用身份不提供个人消费，不支持多级、转换或客户转移。
2. 复用现有费用结果作为唯一共同基数，A/B 各自应用精确模型渠道倍率。专属倍率可用于所有用户，范围与授权规则由产品合同维护，不改变分组或路由算法。
3. 管理员授权 A，A 授权 B，候选渠道执行有效交集。未配置倍率不等于未授权。运营可以统一 default，但代码不依赖该选择。
4. B 资金事务同步保存请求计价事实、代理事件和持久去重凭据；A 占用及采购余额由后台有界批次原子更新，不逐请求锁 A、不采用额度池。
5. 预扣占用、最终结算及退款分开，零差额完成也产生确认；原快照和操作凭据在恢复及 journal 清理后继续有效。
6. A 账务积压只告警恢复，不自动停用；已发布额度不足、账号或资格停用、授权不足按业务规则限制新调用。必要记账持久化失败不能绕过。
7. 全用户验证邮箱和强制 MFA 通过服务端后台门禁执行；存量 API Key 不因补齐或普通 MFA 重置撤销。凭证泄露处置独立，恢复路径不能绕过认证保证。

## Consequences

请求不再集中写 A 的余额，保留 B 的原生扣费和恢复基础；同时承担持久事件、生命周期去重、批量投影和安全入口完整接线的成本。

代理余额与明细允许延迟，不承诺严格不透支；积压、在途请求和状态传播会扩大超用。资金数据库故障与允许的后台延迟是不同失败类别。性能与三数据库兼容性必须实测，不能根据架构推断已达到容量。

专属业务主体、授权与敏感字段边界必须在旧管理接口也成立；超级管理员资源放行不应绕过 B 商务配置的领域规则。全局安全补齐影响存量后台，应分阶段发布并证明已有调用连续。

实施状态唯一见[阶段实施计划](../../50-planning/2026-11-03-代理分销阶段实施计划.md)，技术工作包见[实施方案](../../80-dev/2026-11-03-代理分销与用户专属倍率实施方案.md)。

## Alternatives Considered

- **充值时扣 A**：模型渠道采购倍率不同，客户尚未消费时无法确定成本；额度分配不是消费。
- **逐请求同步扣 A/B**：即时一致，但单个代理余额成为集中更新行，不符合当前持续调用优先的取舍。
- **代理额度池**：分散热点，但引入预留、回收及分池恢复；用户明确选择保持简单。
- **仅从消费日志事后反算**：日志可清理、异步任务提交不等于最终费用、舍入不可逆，无法作为完整采购事实。
- **账务积压超限熔断**：可限制部分超用风险，但违背业务明确要求，不采用。
- **强制 default 或复用组织**：把运营选择固化为代码或混淆既有组织边界，不能满足上下级独立授权。
