# 架构概览

## 分层结构
系统遵循 Router -> Controller -> Service -> Model 的分层结构。

## 主要模块
- `router/`：HTTP 路由入口，包含 API、relay、dashboard 与 web 路由。
- `controller/`：请求处理与接口响应。
- `service/`：业务逻辑与跨模块编排。
- `model/`：GORM 数据模型与数据库访问。
- `relay/`：AI API 代理与 provider 适配。
- `setting/`、`common/`、`dto/`、`types/`：配置、公共工具、数据结构与类型定义。
- `web/`：React 控制台和本地首页，构建产物 `web/dist` 由 Go 嵌入。
- `relaykit/`：独立 Go 模块，拥有协议 DTO 和转换；鉴权、传输和计费在宿主。
- `pkg/jsplugin/`、`plugins/tasks/`：任务运行时与任务插件；宿主负责轮询、结算和退款。

## 组织扩展边界

详细设计见 [组织与组织账单架构设计](./组织与组织账单架构设计.md)。

组织模块是现有个人账号体系之上的扩展，与个人计费有两个接触面：

```text
个人扣费链路：请求 -> Token -> User -> 个人钱包/订阅 -> Log
折扣接触面：组织渠道折扣作为计价乘数进入请求计价（请求开始固定快照，复用 BillingSession 预扣/结算）
组织汇总链路：OrganizationMember.UserId -> Log.UserId -> 组织报表与 Invoice 月度汇总
```

组织模块维护：

- `Organization`：组织基本信息与当前折扣快照指针。
- `OrganizationMember`：成员、角色和成员有效期。
- `OrganizationDiscountSnapshot`：按渠道独立的组织折扣/加价快照（追加式不可变历史）。
- 组织报表权限。
- 按成员有效期汇总的组织账单视图与 Invoice 派生月度汇总。

组织没有自己的资金路径：预扣、结算、退款、充值和订阅始终由用户自身链路执行，组织折扣只改变计价乘数。组织不参与 Token 鉴权，现有 API 请求不会携带或选择组织，组织归属只由当前登录用户的有效成员关系推导。

## 接口与资金边界

```text
管理请求 → router / middleware → controller → service → model → 主库
模型调用 → Key 鉴权 → 渠道授权与选择 → 请求计价与预扣 → 上游 → 结算/退款 → 日志
账单查询 → 主库成员/财务事实 + 日志库 → 按权限返回明细、汇总或导出
```

- 组织用户接口使用 `current`，跨组织管理接口使用显式 ID；组织报表不写入个人资金事实。
- [实时模型折扣](用户与组织实时模型折扣架构设计.md)在主库阶段为 `active` 后按实际渠道解析用户、组织或系统倍率；旧组织渠道倍率仍是独立计价因子。
- [代理分销](代理分销与用户专属倍率架构设计.md)独立维护代理与客户归属。客户钱包实时扣费，代理采购余额由持久事件异步更新；授权不来自组织成员关系。
- [Token 对账中心](Token对账中心架构设计.md)是 Root 对消费与退款日志的只读视图，与组织 Invoice 分开。

## 文本流生命周期

已建立的按 Token 计费文本流将“客户侧输出”与“上游读取”分为两个正交状态。客户断开后停止写出，但在有界时间内继续取得协议终态与 usage；只有成功终态与完整权威 usage 同时成立才通过原结算入口。详细设计见 [文本流断开续读架构设计](./流式断开续读架构设计.md)。

## 睿观受管模型服务

受管个人和企业资金仍归原生 User／Token／钱包／订阅链路，Vantage 企业不是 `Organization` 资金主体。新增目标 v2 管理接合由[睿观模型服务设计](睿观模型服务接合设计.md)唯一维护；Vantage 负责身份授权及用户账单，Gateway 负责真实财务事实，不改变上面的组织只读边界。实现状态以路线图为准。

## 系统邮件

`common.SendEmail` 是统一发信入口。Root 可配置既有 SMTP 或 Microsoft 365 应用身份；后者通过 Client Credentials 获取 Graph Token 并调用 `sendMail`，Graph 受理与最终送达分开判断。配置和发布验证见[邮件架构](微软应用身份邮件架构设计.md)。

## 部署与验证

主库支持 SQLite、MySQL 和 PostgreSQL。日志默认复用主库，可用 `LOG_SQL_DSN` 分离，独立日志库也支持 ClickHouse。Redis 用于共享缓存等运行状态，权威资金事实仍归主库。多节点目标拓扑见[部署架构](部署架构.md)，运行检查见[运维手册](../40-operations/运维手册.md)。
