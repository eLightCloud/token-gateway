# 睿观模型服务接合设计

## 系统边界

本设计承接[产品合同](../10-product/睿观模型服务产品设计.md)，属于 Vantage 受管命名空间的专用管理接合。Gateway 唯一写入账户资金、Key 额度、套餐及费用事实；Vantage 唯一拥有个人／企业／成员映射和平台／租户管理资格。执行与会话仍归 ZCode。

本文件是新增提供方协议与资金语义的设计权威；Vantage [消费方设计](../../../vantage-ai-center/docs/20-architecture/30-企业身份与资源治理设计.md#lighting-model-service)只引用并接合，不另定义 wire schema。提供方工作树已实现合同及端点，目标部署须先读取合同并验证摘要后接入；实现测试证据归实施方案，不能以工作树完成替代生产开放。

## 当前设计与最小接线

复用 `VantageAccountBinding`、`VantageCredentialBinding`、原生 User／Token、原生订阅创建事务、订阅额度和原生 BillingSession。普通 Gateway 用户、既有套餐自助购买及 `Organization` 统计继续采用原合同；Vantage 的单套餐和管理员无支付配置规则只施加于其受管账户。

当前 `native-token-quota-1` 只有企业 USD 查询和累计限额，不能改变同一路由的字段含义。新增目标合同 `model-service-2`，使用 `/api/integrations/vantage/v2`；迁移期保留 v1，消费方验证 v2 后统一切换，不能失败回退 v1 继续写不同语义的额度。

功能主体放在专用新文件或模块；既有路由、原生钱包／套餐、计费元数据与迁移入口仅作必需接线。配置沿原生订阅创建及分组变更 helper，专用事务只负责账户锁、配置修订与幂等回执，不复制计费结算。无新账本、资金 worker 或组织钱包。

## 职责与依赖

| 边界 | 唯一责任 |
| --- | --- |
| Vantage 后端 | 根据真实平台／租户／本人会话授权，固定目标账户与历史 Key，引入操作标识并保存意图／回执 |
| Gateway 专用入口 | 校验当前集成配置、受管命名空间、账户类型、资源归属与请求合同；不信任前端提供的用户 ID |
| Gateway model／billing | 原生事务、锁、幂等回执、预留／结算／退款、缓存一致性与历史金额 |
| Gateway 管理后台 | 现有个人和企业受管账户充值；可识别账户类型与外部引用，不需要模拟 Vantage 员工 |
| 页面 | 只显示安全投影；不持有原生 Key、集成口令、私密日志及上游字段 |

平台管理员只能无支付配置独立个人套餐；企业管理员只能调整本企业 Key；普通个人可提交套餐申请，不能自行发放权益、充值或调额。集成口令代表应用信任，`actor_ref` 仅是关联 Vantage 审计的不透明引用，不冒充 Gateway 管理员认证。沿现有集成鉴权与凭据保管，不新增用户直连 Gateway 管理 API 的入口。

## 目标公开合同

以下端点统一位于 v2 前缀。提供方以 `pkg/vantagequota/model-service-2.openapi.json` 作为唯一机器结构源，并发布同源版本与摘要；文档表只定义能力，不维护第二份完整 DTO。

| 方法与相对路径 | 能力与范围 |
| --- | --- |
| `GET /model-service-contract` | 当前合同版本、schema 摘要和明确能力；缺能力不能假装就绪 |
| `GET /money-settings` | 当前 USD→CNY 汇率、quota_per_unit、观察时间及变更标识；不返回其他站点秘密配置 |
| `GET /subscription-plans` | 受管个人可申请的有效且允许钱包后备的套餐；目录与支付合规及余额购买开关解耦 |
| `GET /personal-accounts/:subject/funds` | 当前个人原生余额及当前人民币投影 |
| `GET /personal-accounts/:subject/subscriptions` | 当前套餐与有界历史购买记录，含当时购买价格与固定人民币金额 |
| `PUT /personal-accounts/:subject/subscription` | 无支付配置原生套餐；action、plan_id、plan_revision、expected_revision、可选 ends_at、actor_ref、operation_id |
| `POST /personal-accounts/:subject/subscription-purchases` | 仅恢复已接受历史代购，新请求拒绝，不再扣款 |
| `GET /personal-accounts/:subject/operations/:operationID` | 原购买回执；已提交操作的幂等结果不自动过期 |
| `GET /personal-accounts/:subject/usage`、`GET /personal-accounts/:subject/recharges` | 本人模型消费／退款与入账／调额安全投影 |
| `GET /enterprise-accounts/:tenant/funds` | 企业原生余额及当前人民币投影 |
| `GET /enterprise-accounts/:tenant/token-quotas`、`GET /enterprise-accounts/:tenant/credentials/:credentialRef/quota` | 本企业 Key 剩余额度／无限，明确与企业余额约束的区别 |
| `PUT /enterprise-accounts/:tenant/credentials/:credentialRef/quota` | `finite`＋人民币剩余额度，或 `unlimited`；带操作标识与预期修订 |
| `GET /enterprise-accounts/:tenant/operations/:operationID` | 额度设置的原操作回执 |
| `GET /enterprise-accounts/:tenant/usage`、`GET /enterprise-accounts/:tenant/recharges` | 企业记录；usage 可限定已验证归属的 Key；充值仅账户级 |

配置输入固定个人、套餐配置修订、当前权益配置修订、操作标识及操作者关联；只允许 set／cancel 和管理员指定到期，不接收自定额度。assignment_revision 不因汇率变化失效；当前权益 revision 排除消费用量。

金额使用十进制字符串；原生单位与人民币字段分别命名，不能只把 `currency` 标签从 USD 改成 CNY。当前值附换算依据和观察时间；历史值附来源／金额状态，缺失可为空并给固定原因。费用包含 `billing_source`、记录引用和关联标识，不能把套餐用量等值当作钱包实际扣款。精确字段、枚举和精度在单一 OpenAPI 中核定并生成双方类型，现有 v1 schema 不手改为 v2。

查询须有界分页，游标绑定账户、Key、筛选和数据源范围；时间采用带时区的半开区间。SQL 日志使用原生递增 ID；ClickHouse 原生日志 ID 为零，改用原有 billing_operation_id，旧记录仅在 request_id／type／token_id 组合唯一时可读取。相同操作的重复投递合并为一条事实，引用缺失或事实冲突明确返回源不可用，不猜测去重或补造金额。ClickHouse 游标固定已记录日志的时间／引用水位；迟到投递须刷新读取，不承诺跨页看到尚未投递的日志。主库与日志库分别查询，不跨库 JOIN。历史购买直接读订单，入账／调额直接读对应事实，不从管理文本日志猜金额，不为统一列表建设总账。无法关联的企业消费保留在企业视图并标明未关联；不能分配给任意员工。

## 数据与控制流

### Vantage 账单消费

Vantage 后端通过本合同查询，按本人／本企业资格输出安全投影，Vantage 独立「设置 → 账单」页面直接展示概览、分页消费、充值及购买记录，按当前资格选择本人／本企业；模型设置与成员页只负责配置或定位跳转，员工额度编辑也归同一账单页。入口调整不改变本提供方资金／API 合同或扩张查询权限。不得把用户导向 Gateway 管理站点完成账单查询；Gateway 服务间 API 也不返回需要用户登录的后台链接作为记录内容。

### 管理员钱包代购

Vantage 平台会话授权 → 固定个人与报价 → 记录本地意图 → Gateway 集成入口 → 原生钱包购买事务 → 回执 → Vantage 查询确认。

Gateway 在同一事务中锁定目标 User 及当前订阅，先恢复已有回执，再校验输入指纹、当前权益修订和套餐配置修订。不同操作并发串行，至多一个新配置生效。

`set` 更换结束旧套餐并经原生 helper 创建新权益；同套餐仅修改到期并保留已用额度；`cancel` 结束当前权益。原生创建失败通过 savepoint 保留原权益。零扣款 SubscriptionOrder 标记 `vantage_admin`，与回执原子提交；钱包不参与扣款。原生购买次数限制保持，禁用／删除／配置变化保存确定拒绝。

提交后沿原生余额和分组缓存 owner 失效。读取返回配置 revision、开通记录 kind；历史 wallet_purchase 与 admin_assignment 明确区分。人工配置与目录不要求 PaymentSetting 合规确认，不改变 Gateway 普通支付流程的开关或防护。套餐消费与钱包后备仍完全沿 BillingSession。

### 员工当前剩余额度

新员工 Key 首建 `unlimited_quota=true`，回执证明当前原生策略后方可调用；重复开户不能覆盖已有有限额度。设置有限额度在 Gateway 接受时把人民币换算为 quota，更新原生 `RemainQuota` 与有限标志，保留 `UsedQuota` 和历史日志；恢复无限不重建 Key，也不重置用量。有限零值与未提供、无限分别表达。

额度写入复用原生锁、缓存失效与配置修订；只有管理员配置变更改变配置修订，正常消费不造成编辑冲突。设置的“当前剩余”以 Gateway 原子应用时为准，已在途请求后续仍按原生语义结算，不能通过覆盖缓存抹掉预留或返还重复额度。实现前须验证原生在途预扣／结算与设置余额的并发关系，不承诺取消已接纳请求或绝对无透支。Vantage 不通过读取 `UsedQuota` 自行拼出累计上限。

### 当前换算与历史金额

`当前人民币金额 = 原生 quota ÷ quota_per_unit × USDExchangeRate`；人民币设置反向换算，在可信边界使用 decimal 和已有严格范围转换。汇率及 scale 必须有限、正数，非法配置明确拒绝；输入越界／超精度拒绝，不能默默裁剪或退回硬编码汇率。显示精度与内部精度在 owner schema 固定。

新请求在原生计费上下文建立时读取并固定换算快照；最终消费落库时按实际费用固化人民币金额与依据。退款继承原消费的汇率和 scale，部分退款按原始精度处理，不能用退款当天的新汇率。套餐购买、管理员充值／调额和赠送在各自事实提交时保存实际金额及换算依据。

换算元数据附着原有订单、入账、调额、赠送或消费／退款事实及其可靠投递上下文。已存在能满足的字段直接复用，仅补缺少的快照；不新建影子钱包。进程重启、日志异步投递和失败重试须保持同一快照，不在读账单时固定“第一次查询汇率”。旧记录有可信源才可显式回填，否则人民币金额标为未提供；不反推历史汇率。

## 约束与取舍

- v2 未部署时，Vantage 新功能保持未开放；旧能力明确沿 v1 原语义，不混用写合同。目标为两仓组合切换后退出消费方 v1；删除提供方兼容路由须确认无其他调用者。
- 不开放个人自助支付，不创建企业套餐、月度员工预算、完整总账、自动续费或复杂财务导出。
- 人员迁入／撤销沿现有身份生命周期；购买接受前复核固定个人绑定。迁入后不把原个人余额或套餐转入企业，历史读取仍受 Vantage 资格控制。
- 新的金额快照属于本资金接合能力，组织报表仍是只读消费者；不得借组织账单修改计费。原生结算与日志投递的必要加法接线须独立记录兼容面。
- 事件记录关联 ID、账户安全引用、操作种类、结果、固定原因及修订；不记录 Key、口令、prompt、客户正文或完整敏感请求。保留原生预扣／结算观测点。

## 验证策略

逐项覆盖 VG-01—VG-10；重点验证并发配置、零扣款、同套餐保留用量、配置冲突及历史回执恢复、超时后重试、价格变化、部分失败回滚、在途调额、套餐后备、汇率变更后的历史消费／退款不变、不同身份负例和不同资金来源。

涉及模型／迁移／数据库访问必须在真实 SQLite、MySQL、PostgreSQL 验证，最低版本敏感行为覆盖支持下限；新库、代表性旧库升级、重复迁移、索引与原事实保留分别取证。独立日志库与 ClickHouse 覆盖受影响读写／投递路径。单元测试或构建不能代替数据库矩阵；具体任务和已执行证据归[实施方案](../80-dev/2026-10-28-睿观模型服务实施方案.md)。


提供方机器合同唯一源为 `pkg/vantagequota/model-service-2.openapi.json`，由 v2 合同端点发布；Go 生成类型与 Vantage 同源快照均可检查漂移。时间查询为 UTC Unix 秒，半开区间；金额用 CNY 十进制字符串、最多 8 位小数，员工设置输入最多 6 位。当前设置按原生 quota 最小单位换算，不能额外创造分币钱包。集成幂等表 `VantageServiceOperation` 只存请求摘要、回执及换算依据。新字段为原有订单／入账／调额的 MoneySnapshot 和任务私有上下文，消费日志复用 Other 及现有 BillingSource，不增财务聚合账本。
