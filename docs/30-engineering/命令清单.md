# 命令清单

## 文档命令
```bash
task docs:check

```

## 后端命令

```bash
./start.sh
go run . --port 3000
go test ./...
go test ./model ./controller ./router
make contracts-check
```

`start.sh` 在未设置 `SQL_DSN` 时使用本地 PostgreSQL 默认连接；显式设置 `SQL_DSN=""` 时保留 Go 服务原有的 SQLite 模式，数据库路径由 `SQLITE_PATH` 指定。切换前先核对已有数据所属数据库并备份，不得因空字符串被默认值覆盖而连接到另一套账本。

本地数据库选择回归：`bun test scripts/local-postgres-dsn.test.ts`。

### 文本流断开续读回归

```bash
go test ./relay/helper ./relay/channel/... ./relay ./service ./controller
go build ./...
```

```bash
cd relaykit
GOWORK=off go build ./...
```

## 代理分销与客户观测

在仓库根目录执行。需要数据库行为证据时，使用专用隔离库和版本化样本。

```bash
go test ./model ./controller ./router -run 'Reseller|ResellerObservation' -count=1 -v
go test ./service -run 'TestPersonal(TaskLifecycle|QuotaSaturation|OrdinarySubscription)' -count=1 -v
node scripts/reseller_e2e.mjs
```

- 观测矩阵通过 `TEST_RESELLER_OBSERVATION_MYSQL`、`TEST_RESELLER_OBSERVATION_POSTGRES`、`TEST_RESELLER_OBSERVATION_CLICKHOUSE` 指向测试实例。逐一确认命中 SQLite 共库/分库、MySQL、PostgreSQL、独立 ClickHouse 子用例。
- 浏览器回归设置 `RESELLER_PLAYWRIGHT_MODULE`，必要时设置 `RESELLER_CHROMIUM_PATH`。核对五个入口、窄屏、空态、筛选重置和携带客户与请求 ID 的账单跳转。比较另一代理、直属用户和停用客户的结果。前端定向测试从 `web/` 运行 `bun run test src/features/reseller/__tests__/workspace.test.tsx src/hooks/__tests__/sidebar-config.test.tsx`。
- 升级矩阵由 [reseller_s0.py](../../scripts/reseller_s0.py) 生成代表性未修改基线，再将其副本传给 [reseller_s1.py](../../scripts/reseller_s1.py) 的 `--baseline`。记录源提交、镜像版本、快照摘要、重复迁移和恢复结果。按预扣、零差额确认、退款、跨渠道重试不足逐项核对客户钱包/Token 与采购余额/占用；重复投递、乱序和重启后应逐笔一致。容量条件见[路线图](../50-planning/路线图.md#reseller-release)。

## 睿观模型服务

在仓库根目录执行定向回归。为真实库矩阵向 `VANTAGE_BILLING_SQLITE_DSN`、`VANTAGE_BILLING_MYSQL_DSN`、`VANTAGE_BILLING_POSTGRES_DSN` 和 `VANTAGE_BILLING_CLICKHOUSE_DSN` 提供隔离数据库。

```bash
make contracts-check
go test ./service ./router -run 'TestVantage(ModelService|SubscriptionAssignment|IntegrationHTTPContract)' -count=1 -v
```

比较供需两侧合同摘要，确认成功、重复调用、并发和历史快照行为。真实日志库覆盖 ClickHouse 同秒分页、原生 ID 为零和重复投递。跳过某个引擎的子测试时按未验证记录。

## 使用日志和写入保护

在仓库根目录执行定向回归，覆盖原日志接口、游标、禁删、结算提交与收据。数据库矩阵配置 `AUDIT_MYSQL_DSN`、`AUDIT_POSTGRES_DSN`、`AUDIT_CLICKHOUSE_DSN`，只指向可丢弃测试库。收据测试单独使用 `RELAY_RECEIPT_TEST_DSN` 或 `RELAY_RECEIPT_TEST_SQLITE`，已有发布版夹具时设置 `RELAY_RECEIPT_TEST_UPGRADE=true`。

```bash
go test ./controller ./router ./model ./service -run 'Test(PersonalLog|LogExportDatabaseMatrix|LogRetention|ClickHouseLogRetentionPolicy|ChatRelayReceipt)' -count=1 -v
LOG_BENCH_FAULTS_ONLY=true bash scripts/log-read-benchmark/run.sh --full-chain
LOG_BENCH_RATES=50 LOG_BENCH_WRITES=1200 bash scripts/log-read-benchmark/run.sh --full-chain
```

压测脚本使用本地专用 PostgreSQL 容器和合成数据。先保留同步提交与持久化，复跑纯写入基线，再对比读写混合。单独记录响应完成和网关处理结束的延迟、池与锁等待、WAL 等待及对账结果。测试性的存储切换或提交参数属于诊断条件，生产门槛使用目标持久化配置。通过故障用例后核对扣费、日志、恢复次数和幂等回放。

## 系统邮件与运维通知

在仓库根目录执行。浏览器邮件 E2E 使用本地 SMTP、隔离 SQLite 及 Chromium，设置 `NOTIFICATIONS_PLAYWRIGHT_MODULE`、`NOTIFICATIONS_CHROMIUM_PATH`，可用 `NOTIFICATIONS_E2E_OUTPUT` 保留脱敏证据。

```bash
go test ./common ./controller -run 'Test(MicrosoftGraphEmailDelivery|MicrosoftOAuth|EmailDelivery)' -count=1 -v
go test -race ./common ./service -run 'Test(NotificationEmail|Operations)' -count=1
node scripts/notifications_e2e.mjs
```

运维测试使用 `OPS_TEST_MYSQL_DSN`、`OPS_TEST_POSTGRES_DSN`、`OPS_TEST_CLICKHOUSE_DSN` 覆盖真实引擎。分别记录配置与协议测试、浏览器渲染、本地 SMTP、真实租户投递和跨日调度证据。

## 前端命令
默认前端位于 `web/`，优先使用 Bun：

```bash
cd web
bun install
bun run dev
bun run test
bun run typecheck
bun run lint
bun run format:check
bun run build:check
```

仅在维护前端文案时运行 `bun run i18n:sync`；核对差异，仅保留 en、zh 的维护变更。

`go build ./...` 包含嵌入前端的根包；缺少 `web/dist` 时先运行 `make build-web`。
