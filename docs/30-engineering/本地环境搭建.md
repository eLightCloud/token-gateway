# 本地环境搭建

## 准备工具

- Go 版本以根模块和 `relaykit/go.mod` 的 `go` 指令为准；当前均为 1.25.1。
- Bun 用于安装与运行 `web/` 前端。默认一键模式需要 Docker Compose、`curl`、`lsof`。

## 选择启动方式

首次使用宿主机 Go 模式前，运行 `make build-web` 生成 `web/dist/index.html`。当前 `start.sh` 写入的占位页仍在旧目录，不能满足根包的 `go:embed web/dist`；如果 Go 报找不到嵌入文件，先完成这一步。

| 场景 | 命令 | 默认访问 |
| --- | --- | --- |
| 宿主机跑 Go 和前端、Compose 跑 PostgreSQL | `./start.sh` | 前端 `http://localhost:3201`，后端 `http://localhost:3200` |
| 已有可用数据库 | `START_DEPS=0 ./start.sh` | 同上；显式指定 `SQL_DSN` 或确认默认 PostgreSQL 可达 |
| 使用独立 SQLite 练习库 | `START_DEPS=0 SQL_DSN='' SQLITE_PATH=/tmp/token-gateway-dev.db ./start.sh` | 同上 |
| Compose 跑后端和依赖，宿主机跑前端 | `make dev-api`，再执行 `make dev-web` | 前端 5173、后端 3000 |

`start.sh` 默认 `START_DEPS=1`，只启动 Compose 的 PostgreSQL 服务（当前镜像 18.4，宿主机回环端口 54329）。它不会为宿主机后端启动或配置 Redis；若要使用已有 Redis，另设 `REDIS_CONN_STRING`。完整 Compose 后端模式同时包含 Redis。

脚本启动前会停止两个目标端口上的现有监听进程。需保留本机其他服务时，请指定空闲端口，例如 `BACKEND_PORT=3202 FRONTEND_PORT=3203 ./start.sh`。脚本等待后端 `/api/status` 返回 200 后再启动前端；两个进程的输出在 `logs/dev/`，后端应用日志默认在 `logs/backend/`。退出时停止本轮应用和日志跟随，依赖容器保留。

## 手动启动

先按[命令清单](命令清单.md#前端命令)安装和构建前端，生成 Go 嵌入所需的 `web/dist`。配置本地数据库后，在仓库根目录运行：

```bash
go run . --port 3000 --log-dir ./logs/backend
```

另开终端启动开发前端：

```bash
cd web
VITE_REACT_APP_SERVER_URL=http://localhost:3000 bun run dev -- --host 127.0.0.1 --port 3001
```

访问前端并检查后端 `/api/status`。若连接失败，先核对实际 DSN、端口和启动日志；切换已有数据库前确认数据归属，避免误用另一套账本。
