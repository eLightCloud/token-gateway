# NGINX 媒体转发入口配置

## 适用范围

此页用于识别旧部署。当前仓库未接入 `media_via_base_url` 开关或 `/_newapi/media` 入口，不应将旧动态转发配置作为新部署模板。

## 识别现有依赖

1. 在渠道设置备份、入口配置和访问日志中查找 `media_via_base_url`、`/_newapi/media`、`X-NewAPI-Media-URL`，确认是否仍有旧版本实例依赖。不要在排查记录中保存完整签名媒体 URL。
2. 区分渠道 API 地址和任务结果中的媒体 URL。任务创建、查询经过某个反向代理，并不意味着媒体 URL 的获取也使用该出口。
3. 当前视频渠道可按供应商选择 Ark 原生或 OpenAI Videos 兼容的南向协议；已有任务沿提交时固定的协议查询。升级前用受控任务分别验证提交、查询及结果下载，并记录实际访问端和出口。

## 变更验收

仅在确认无存量调用后，按入口变更流程下线旧 location。已有依赖时保留原配置，先验证替代路径的连通、授权、重定向和失败行为。使用实际部署的 NGINX 配置检查和目标网络验收；不能用旧版测试记录证明现行链路可用。
