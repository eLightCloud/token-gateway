# 监控告警

## 文本流断开续读

客户断开后，应同时观察客户侧结果和上游终态，不能只按 `completion_tokens=0` 或 `client_gone` 判定请求成败。

重点日志字段：

- `stream_status.end_reason`：首个已确定的客户/传输结束原因；`client_gone` 只表示客户侧 Context 已结束。
- `stream_status.upstream_result`：续读后的上游结果，包括 `terminal_success`、`protocol_failure`、`usage_missing`、`incomplete_eof`、`scanner_error`、`handler_error`、`idle_timeout` 和 `drain_timeout`。
- `stream_status.upstream_error`：上游错误详情，不覆盖客户侧 `end_error`。
- 请求总处理时长与首事件时间：用于观察客户断开到上游终态的 tail，不将单点 FRT 等同于客户侧的端到端等待。

发布后应按实例观察：

- 上游连接数、请求处理时长和 goroutine 是否持续增长；
- `usage_missing`、`incomplete_eof`、读取/处理错误、`idle_timeout` 和 `drain_timeout` 的分布；
- `client_gone + terminal_success` 是否持续保留非零输入、输出和协议支持的缓存分项；
- 失败或 usage 不完整的请求是否被错误写入普通成功消费日志。

高优先级告警条件：连接或 goroutine 持续增长、`drain_timeout` 异常增加、上游错误未及时结束、或同一请求出现重复结算证据。达到任一条件时，按 [运维手册](./运维手册.md) 的“文本流断开续读”流程停止放量或回滚。

## 组织账单后台构建

- 分开观测用量快照、Invoice 和源日志投递。关注构建状态、发布时间、队列原因、失败率及 DB 查询压力；同一筛选下旧结果持续无更新时，先查日志投递及任务恢复。
- 区分消费结果可用与钱包事实待核对。导出待生成、期初余额缺失或账期不闭合均不能作为零值处理；按[运维手册](运维手册.md#用量与-invoice-重算)重算和验收。

## 代理采购发布

- 从代理管理诊断查看持久事件积压与发布健康：待处理数、最旧事件时间、最近成功或失败、批次耗时。发布器在检测到积压最旧时间超过 30 秒时记录告警。
- 积压告警用于排查消费器和主库，不能当成代理停用或拒绝调用的条件。检查新旧投影的额度、占用及事件关联后，再使用现有诊断或重建流程。

## 邮件提交

区分配置失败、Token 获取失败、Graph 拒绝、受理和结果不确定。按关联 ID 与配置版本定位，不记录密钥、Token、验证码或正文。受理后还需由租户投递记录或收件结果确认送达。

## 运维通知

| 信号 | 触发及恢复 | 排查 |
| --- | --- | --- |
| 磁盘 | ≥90% 持续 30 秒触发，低于 85% 持续 5 分钟恢复 | 核对数据库、日志和应用数据路径是否共享同一底层磁盘 |
| CPU | ≥80% 持续 2 分钟触发，低于 70% 持续 5 分钟恢复 | 核对进程与容器资源口径、数据库与后台任务负载 |
| 内存 | ≥70% 持续 2 分钟触发，低于 65% 持续 5 分钟恢复 | 核对容器限制、采样是否有效及异常增长 |
| 服务、任务与账务 | 观察持续请求失败、无可用渠道、异步任务超时、账务恢复积压和明确的账务一致性异常 | 按节点、模型、请求 ID 或操作 ID 联查任务状态、持久日志和账本 |

同类持续资源提醒有 60 分钟冷却。缺少有效采样时保留异常判断，日报在资源不足或采样无效时可以暂停。恢复事件有限尝试结束后关闭；投递结果不明时先核对收件端。机器、网络或邮件通道整体故障时，应用内通知可能无法送达。查看 `operations_daily` 系统任务结果、邮件投递列表及跳过原因，按[运维手册](运维手册.md#运维通知预览与启用)处理。

## 使用日志读写压力

- 分别观察读取繁忙与超时、发送到上游前的准入、结算提交、日志补投和页面可见延迟。检查主库及日志库连接池等待、锁、WAL 同步、CPU、I/O，关联最老待补投时间和状态。
- 先用同拓扑纯写入建立对照，再判断读取的影响。单通道热点与 WAL 提交等待可放大池压力；应用池未排队时仍要核对数据库连接耗尽。索引命中后继续观察堆读取和写入成本。
- 发现资金或消费事实不一致、重试积压持续增长或写入尾延迟越线，停止放量并按[灰度步骤](运维手册.md#使用日志灰度)处理。
