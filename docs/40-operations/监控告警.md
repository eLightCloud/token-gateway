# 监控告警

## 文本流断开续读

客户断开后，应同时观察客户侧结果和上游终态，不能只按 `completion_tokens=0` 或 `client_gone` 判定请求成败。

重点日志字段：

- `stream_status.end_reason`：首个已确定的客户/传输结束原因；`client_gone` 只表示客户侧 Context 已结束。
- `stream_status.upstream_result`：续读后的上游结果，包括 `terminal_success`、`protocol_failure`、`usage_missing`、`incomplete_eof`、`scanner_error`、`handler_error`、`idle_timeout` 和 `drain_timeout`。
- `stream_status.upstream_error`：上游错误详情，不覆盖客户侧 `end_error`。
- 请求总处理时长与首事件时间：用于观察客户断开到上游终态的 tail，不将单点 FRT 等同于客户侧的端到端等待。

发布后应按实例观察：

- 上游连接数、请求处理时长和 goroutine 是否持续增长；
- `usage_missing`、`incomplete_eof`、读取/处理错误、`idle_timeout` 和 `drain_timeout` 的分布；
- `client_gone + terminal_success` 是否持续保留非零输入、输出和协议支持的缓存分项；
- 失败或 usage 不完整的请求是否被错误写入普通成功消费日志。

高优先级告警条件：连接或 goroutine 持续增长、`drain_timeout` 异常增加、上游错误未及时结束、或同一请求出现重复结算证据。达到任一条件时，按 [运维手册](./运维手册.md) 的“文本流断开续读”流程停止放量或回滚。
