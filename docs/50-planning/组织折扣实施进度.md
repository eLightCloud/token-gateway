# 组织折扣实施进度

## 背景与目标

为组织引入请求级渠道折扣：系统管理员（Root）为组织按渠道独立配置折扣，计费请求固定使用开始时的折扣事实，历史以不可变快照保留供审计。`Log.Quota` 直接记录折后额度，组织 Invoice 继续聚合 `Log.Quota`，不二次折扣。

本功能取代早期的"组织合同计费"设计（合同名称、组织全局倍率、版本状态机、创建/归档生命周期、成员只读入口），该实现未进入提交主干即被全栈简化为组织折扣。

## 已确认产品决策

| 决策点 | 当前取值 |
|---|---|
| 领域名称 | 仅"组织折扣"，全栈无"合同"概念 |
| 配置粒度 | 每渠道独立折扣；未配置为 `1.0` |
| 折扣范围 | `0 < ratio <= 1`，最多六位小数；`0.8` 表示按原价 80% 计费 |
| 既有倍率 | 全局渠道倍率、用户组倍率、充值价格均不变 |
| 权限 | 仅 Root 可查看和修改折扣及历史；普通 Admin 直接请求 API 得 `403` |
| 修改方式 | 多项编辑后整批保存、原子生效（完整替换语义，空集合清除全部） |
| 并发 | `expected_snapshot_id` 条件更新乐观锁；冲突返回 `409`，失败事务不残留快照 |
| 历史 | 只追加、不可变；无编辑、删除、归档或恢复 |
| 请求一致性 | 首次计费解析一次性加载完整快照；异步任务、重试、退款复用同一事实 |
| 预扣 | 按未打折价格预扣，渠道确定后按实际折扣结算差额 |
| 旧数据 | 合同表均为测试数据，不迁移、无兼容层 |

## 关键风险与回滚

| 风险 | 缓解 |
|---|---|
| 只改名称残留两套计费语义 | 合同模块/字段/兼容层全部删除，折扣快照为唯一实现 |
| 请求期间改价导致账单漂移 | 请求开始固定快照；日志与异步上下文持久化实际应用倍率 |
| 并发保存丢失修改 | 快照 ID 条件更新，`RowsAffected != 1` 整体回滚 |
| 渠道重试重复叠加折扣 | 每次从未应用折扣的基准计算，复用同一内存映射 |
| TEXT 容量或 JSON 兼容 | 保存前 65,535 字节限制；损坏 JSON（含非法值域）失败关闭并返回 500 |
| quota 转换溢出/精度漂移 | 定点整数倍率 + `common.QuotaFrom*Checked` 饱和系列；解析范围校验先于整数转换 |
| 未打折预扣高于折后费用拒绝请求 | 已接受的简化取舍，不改为最低折扣预扣 |
| 结算或退款中途失败 | `TaskSettlementJournal` 先保存提交时事实，再由唯一模型事务同时更新资金、令牌、可选任务额度与 `Applied`；失败整体回滚，恢复器重放同一事务，不重算价格、不分步补账 |
| 日志写入失败 | journal 保存日志 payload，`billing_operation_id` 唯一键保证重放只写一次；日志完成前 journal 不删除 |
| 失败任务退款失败 | 退款不再 claim-first；任务额度清零与钱包/订阅、令牌退款同事务。`billing_recovery` 使用既有 SystemTask（15s 调度，并在即时失败时主动入队）覆盖统一任务与 MJ progress=100% 死角 |
| 开启批量更新后进程崩溃 | BillingSession 的预扣、回滚与 journal 结算直接写主库并在提交后失效缓存；批量队列仅保留非余额事实的既有用途 |

回滚：代码回滚后所有请求倍率退化为 `1.0`；`organization_discount_snapshots` 为追加式表，无需数据回滚。旧合同测试表（`organization_contracts`、`organization_contract_channel_ratios`）由明确的开发/测试清理步骤删除，不在应用启动路径执行破坏性删除。
