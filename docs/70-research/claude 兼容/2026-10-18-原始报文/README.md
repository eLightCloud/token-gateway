## 如何对照

1. 打开 [逐项索引](索引.md)，找到同一用例的 `lighting__` 与 `upstream_bare__` 两行。
2. “请求 JSON”是发出的请求体；“原始正文”是服务端返回的 JSON 或 SSE 正文；“记录”含地址、非认证请求头、HTTP 状态、响应头、时间和解析结果。
3. 普通结构看 `basic_json/basic_sse`；停止信息看名称含 `stop` 的用例；思考和工具字段看 `signed_tool_seed_json/sse`；签名篡改看 `signature_`；会话绑定看 `binding_`。
4. 流式字段以 `.raw` 为准。旧聚合器没有收录结束事件同级的 `context_management`，不要把 `.result.json` 中这个字段的遗漏当作服务端丢字段。独立复核结果见 [字段与签名核查](raw/field_signature_audit.json)。

不同请求生成的签名、消息 ID 和工具 ID 允许不同。签名正例使用各端各自新生成的值，不能对两个请求文件整体做字节相等判断。
