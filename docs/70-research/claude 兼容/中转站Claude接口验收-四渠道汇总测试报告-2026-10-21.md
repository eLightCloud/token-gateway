## 三、统一修正的误判与无效对照

| 用例 | 原判断的问题 | 修正后的判断 |
| --- | --- | --- |
| **TC03：模型权限** | 不存在的 `claude-fable-9-9` 返回 400，被当成权限识别失败 | 改为 **INCONCLUSIVE**。先证明资源存在，再用有权/无权身份对照；同组 ✘ 也不代表缺失、无效凭据均放行 |
| **TC09：SSE** | 缺 `[DONE]`、起始停止字段为 null 被判失败 | 撤销该 FAIL；`2023-06-01` 已移除 `[DONE]`。完整字段仍须逐项验证 |
| **TC25：延迟工具** | 全部工具都设为延迟加载，400 被算不支持该能力 | 此 400 正确。须至少保留一个非延迟工具；不支持旧 beta 的错误不能直接证明功能不可用 |
| **TC29：采样** | `temperature=0/2.5`、`top_k=40` 的 400 算合法请求被拒 | 撤销对应误判。`top_p=1` 涉默认值兼容，版本/模型表述需冻结后重判；非法值被 200 接受仍保留问题记录 |
| **TC31–33：签名** | 有效正例失败，却把负例被拒算验签通过、把修改文字失败另算缺陷 | 校验正确性与修改文字分支均缺对照；保留正例回传失败记录。omitted 空文字合法，改显示文字不等于改签名 |
| **TC39/40：缓存** | 一次未命中推成“从不命中”；首次已读中却因冷写为 0 判失败 | 改为待核；固定前缀、账号/路由、作用域与 TTL 后重测。已有读取保留为观察结果，不能认证缓存费用真实性 |
| **TC43：模型上限** | 请求在预扣费层被 403 拒绝，却算模型上限验证失败 | 改为 **INCONCLUSIVE**；未触达模型校验。负数上限仍生成的记录另行保留 |
| **TC46：错误类型/追踪** | HTTP 200 没有 `error.type` 算 `<nil>`；要求 request ID 必须写进错误 message | 成功体不需要错误字段；ID 检查响应头 `request-id` 和错误体顶层 `request_id`。真实错误体为 `<nil>` 仍是合同差异 |
| **TC46：请求大小** | 1 MB 请求成功就算未拒绝超大请求 | 撤销该 FAIL；官方 Messages 上限为 32 MB，除非有已声明的渠道更小限制。已发生 400 的错误格式可独立判断 |
| **TC27/61：摘要信号** | 摘要为空直接算 display 失效或训练信号损坏 | 改为待核；adaptive 可不产生思考，部分进度块在任何 display 下都可为空。公开摘要和签名不等于完整原始思维链 |
| **TC50/53/55/56：传输及扩展** | 慢读缺终态、URL 下载失败、空正文、beta/schema 组合 400 或标签为“非法 schema”的 200，直接算功能故障 | 补读循环/超时、可控来源、实际 schema 与合法单变量对照；本次不判能力实现失败，也不凭普通成功样例证明约束生效 |
| **TC05/44：缺接口** | 因接口缺失或返回 OpenAI 格式直接标 N/A | 完整 API/模型发现交付时属于差异；若不承诺该能力，记录范围。缺计数接口不等于 Claude Code 必然不能运行 |

## 四、更新后的渠道结论

| 渠道 | 应保留的问题或风险 | 撤回/降级的结论 | 客户判断 |
| --- | --- | --- | --- |
| **OpenRouter** | 停止命中值缺失、部分损坏签名放行、非法数量仍生成等具体记录 | 撤回“权限识别失败”和“缺 DONE 导致 SSE 不合格”；延迟加载与部分参数拒绝正确，1h 冷写结论待核 | 不因这些误判排除该渠道；也不能把它当官方标准答案，核心差异仍需验证 |
| **快快号池** | 原记录停止与签名往返可用；非法参数放行及实际错误类型有差异 | 撤回“缓存系统性失效、费用必然损失”；缓存及 strict 组合待核 | 可作为核心工具链候选，先补固定路由缓存与合法 strict 对照，尚非完整通过 |
| **快快官转** | 有效签名回传 400、停止命中值缺失、实际错误类型异常的记录 | 撤回“合法采样参数大面积被拒”；原样签名正例未过时，其他签名分支不能认证；计费拦截和扩展能力待核 | 优先核对正例原件并重测；确认问题前不盲目放宽采样校验，暂缓承诺多轮思考工具兼容 |
| **图灵号池** | 已记有效正例成功，但五类损坏签名、强制工具选择及非法参数仍被放行，保留高优先排查 | 1 MB 成功不扣分；空摘要、成功体无错误字段和未核验 schema 不算确定故障 | 优先取得单字段签名对照原件；若确认放行需修复。不能据现有记录宣称验签“完全失效”或正式兼容 |
| **numspirit** | 已核实历史基本签名拒绝通过，但显式绑定、零上限和错误格式仍有差异；22 日入口受阻 | 不继承其他渠道结论，不把旧 ccmax 结果当当前主模型结果，也不把 TLS 失败算字段/签名故障 | 保留候选，先恢复连接并固定当前 Key/路线复测；历史成功不等于当前可交付 |

**选型应围绕客户必选功能，不再按旧总通过率排序。** 多轮工具场景先补有效签名/损坏签名/绑定完整对照；成本敏感场景单独验缓存；依赖 strict、结构化输出及压缩的客户先确认合法能力组合。真实 Claude Code、账号轮换和故障恢复未完成前，不承诺完整兼容。
