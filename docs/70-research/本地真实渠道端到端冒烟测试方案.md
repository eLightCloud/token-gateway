# 本地真实渠道端到端冒烟测试方案

## 1. 目标与覆盖

在隔离的本地 eLight 网关上，以客户 API Key 请求已配置的真实渠道，验证文本、图片、Seedance Mini 4 秒视频三类链路。每个成功用例都要关联实际选渠、客户结算和浏览器中的同笔记录，媒体还要实际解码或播放。管理端渠道测试、直连供应商和模拟上游各有单独用途，均不能作为客户链路通过证据。

快速冒烟基准为两次文本请求、一次文生图、一次参考图编辑、一次视频创建，另做只读检查和确定性拒绝用例。按需增加插件图片、Responses 或其它拟发布入口，提前计入调用上限。发布验收按「客户模型 × 渠道 × 入口 × 版本」记录，每个拟发布组合至少有一次真实成功和一次确定性失败。只有涉及上游错误转换或失败退款时，另取可控的真实上游拒绝或终态失败证据。

本文是待执行的本地方案。取法自 `/Users/randy/code/refeiner/yuan-gateway/docs/50-planning/2026-11-06-本地真实渠道端到端冒烟测试方案.md` 的真实调用、数据和 Browser Use 三层核验。本项目的入口、任务生命周期和计费口径以本仓库代码为准。参考项目的执行结果独立记录。

## 2. 环境与执行前检查

1. 记录网关和前端版本、Git HEAD、工作区差异摘要、实际 Origin、主库与日志库的方言/版本、Redis 隔离情况。复用已确认的隔离实例。新启动时只导入必要渠道、定价、插件及测试身份配置，确认解密可用，确保没有历史在途任务被第二个实例接管。SQLite 的在线副本使用一致性备份，外部数据库使用原生一致性导出。根目录的数据库文件不能证明实例正在使用它。
2. 当前 [启动脚本](../../start.sh) 默认后端 `3200`、前端 `3201`，启动前会清理目标端口的监听进程。先核对占用，另选空闲端口启动，按实际需要显式指定 `BACKEND_PORT`、`FRONTEND_PORT`、`FRONTEND_HOST=127.0.0.1`、`START_DEPS` 和数据源。未指定 `SQL_DSN` 时脚本解析本地 PostgreSQL 默认连接。如需 SQLite，显式设置 `SQL_DSN=""` 并指定隔离的 `SQLITE_PATH`。核对 `LOG_SQL_DSN`、`REDIS_CONN_STRING` 和任务轮询、结算恢复及消费日志是否生效。脚本可开启批量写入，账本取数要等实际刷盘。
3. 对后端 `GET /api/status` 及前端代理的同一路径做无凭据预检，两处都应返回预期的 JSON。用浏览器登录本地前端并确认身份、版本和 API 目标。开发前端位于 `web/`，代理按 `VITE_REACT_APP_SERVER_URL` 指向受测后端。原生 `/doubao/...` 请求直发本地**后端** Origin，当前开发代理没有配置 `/doubao`。发布前需要复核嵌入式前端时，先在 `web/` 执行 `bun run build`，再构建并启动同版本网关。不要把开发占位页视为正式构建。[开发代理配置](../../web/rsbuild.config.ts) · [网关嵌入入口](../../main.go)
4. 准备普通用户 A、与 A 独立的用户 B、只读核验所需的管理员会话。首轮用个人钱包、有限额客户 Key、固定测试分组及正价模型，排除其它并发流量、充值、人工调整及订阅回退，记录信任旁路是否实际生效。使用测试分组和 Key 的模型限制固定目标范围，尽量只留一个合格的真实目标渠道。登记网关重试与渠道回退策略，预算覆盖它们可能产生的外发次数。客户请求走正常分发，执行后由受控证据确认实际命中。[模型发现和 Relay 路由](../../router/relay-router.go) · [启动连接选择](../../scripts/local-postgres-dsn.ts)
5. 按用例登记公开模型、实际渠道别名、协议和插件版本、允许的参数、单次及全轮费用上界、轮询截止时间、预期拒绝语义、媒体交付模式和证据入口。预算覆盖预扣、在途和结果未知的创建，同时区分客户 quota 与可能产生的供应商费用。每个新 POST 前检查余量，付费创建串行。缺真实账号、路由、配置、授权或价格上界的必测项标 `BLOCKED`。
6. 使用无敏感提示词和自有参考图。若选用 URL 输入，提前确认对应上游可以访问。仅在受控环境注入凭据，报告、截图和工具输出中使用别名。下载、重定向和播放器验证期间，客户 Key 不得发往外域，签名 URL、制品访问令牌、原始上游响应、Cookie 和 DSN 不进入证据包。

| --- | --- | --- |
| P0 | `GET /api/status`、A 的 `GET /v1/models`、A 会话下的 `GET /api/pricing` | 模型在客户可用范围内，核对 `/pricing` 的单位、分组或已配置的渠道价格变体。记录钱包、Key 与日志基线。无业务扣费。 |
| T1 | `POST /v1/chat/completions`，`stream: false`，短提示词和已确认支持的低输出上限 | 客户收到非空文本。实际渠道、映射、有效组和该笔 usage 可核验，消费日志与钱包/Key 净扣费一致。 |
| T2 | 同一入口 `stream: true`。确认支持时加 `stream_options.include_usage: true` | 按 SSE 读取增量和协议终止标记，记录首包与终止时间。记录真实 usage 或该链路采用的估算来源，结算完成后核对同笔日志。连接结束后未重复收费。 |
| I1 | `POST /v1/images/generations`，`n: 1`，批准的最小规格 | 按实际 URL/Base64 结果取得一张可解码图片。确认走普通 Relay 还是 `openai_image` 插件，并用实际用量或适用计数规则复核本笔。 |
| I2 | `POST /v1/images/edits`，一张自有参考图、一次输出，按已选渠道支持的 multipart 或 JSON 输入 | 图片可解码且能从图像内容确认参考输入生效。若本次价格单列参考图用量，核对用量来源、分项和总额，区分字段缺失与显式零值。 |
| I3 | 本轮发布 `openai_image` 插件时，用 I1 或 I2 选一个支持的插件模型，覆盖上游异步时的请求内等待 | 客户最终收到同步图片结果，后台持久任务与结算证据可关联。若配置和预算允许 I1/I2 直接承担该覆盖，则无需新增创建。上游即时完成时检查结果按合同交付，任务日志可见，历史预览按实际保留策略处理。只有实际发生请求内轮询才计入异步上游覆盖。 |
| V1 | `POST /doubao/api/v3/contents/generations/tasks`，Seedance Mini，`duration: 4`，使用下文模板。用 `GET /doubao/api/v3/contents/generations/tasks/{id}` 有界轮询 | 客户响应 `id` 与平台任务一致，实际映射为 Mini。任务完成、资金对齐、实际制品可取并播放。用媒体探测和浏览器验证输出时长。 |
| N1 | 分别用无 Key、明确排除该模型的 Key 发送合法 T1 请求 | 分别按已登记的入口语义判定鉴权/授权错误，无 Provider 创建、预扣或消费。检查错误类别及业务副作用。 |
| N2 | 对每个拟发布协议选择已由本地校验证实的非法输入。例如图片传负 `n`，原生豆包视频将 `content` 传为对象 | 用合法 Key 和模型提交，应在入口得到预期 4xx，无外发、扣费或任务创建。校验失败日志可合法存在。 |
| N3 | B 的 Key 读取 A 的 V1 原生详情、`GET /v1/tasks/{id}`、`GET /v1/tasks/{id}/artifacts`，并用不含 `access` 参数的受保护制品路径测试内容授权 | B 无法取得 A 的私有任务、媒体或有效链接。独立 B 会话在前端同样看不到记录。签发给 A 的限时链接属于持有者凭据，须单独按签名的作用域与有效期合同验收。 |

### 图片路径

共享图片入口由宿主协议注册，未被插件认领的模型走普通 Relay。现有 `openai_image` 插件合同从客户端看是同步的。若供应商返回任务，宿主在请求内轮询，超过 `TASK_PLUGIN_PROTOCOL_TIMEOUT_SECONDS` 时返回 `504 task_timeout`，已受理任务继续由后台结算。参考方案的 `Prefer: respond-async`、202/Location 和 `Idempotency-Key` 重放不作为本项目图片验收条件。即时交付可能标记 `result_discarded`，验收以创建响应内的可解码图片、可关联任务日志及正确的未保留提示为准。若为轮询后保留的结果，再按已提供的制品入口验证读取。[图片路由](../../router/task-plugin-protocol-router.go) · [插件 API](../plugin-api/v1.md)

普通 Relay 的图片按实际计费分支核对，不能用响应数组元素数直接代替图片数。若结果同时带同一图片的 URL/Base64，按本项目图片计数规则核对一次。纯提示词条目不构成媒体。插件按实际执行插件的用量 schema 核对，区分供应商报告、载荷推导与请求估计。只有历史详情确实记录了分项时才核对该分项。未观察到真实参考图或缓存计价正样本的专项结论单列。[计费规则](../../.agents/rules/billing.md) · [OpenAI 图片响应处理](../../relay/channel/openai/relay_image.go)

### Seedance Mini 4 秒

V1 选本地公开模型，管理员在受控侧确认实际渠道绑定 `doubao` 插件及 Mini 映射。仓库内置插件登记的候选为 `doubao-seedance-2-0-mini-260615`，支持的分辨率档位列有 `480p`、`720p`。运行前仍须通过目标渠道已有合同确认四秒和所选分辨率可用。没有可用配置时标 `BLOCKED`，保留四秒范围。把模板中的模型和分辨率替换为本轮批准值。

```json
{
  "model": "<本地公开 Mini 模型>",
  "content": [{"type": "text", "text": "固定镜头拍摄一只蓝色纸风车缓慢转动"}],
  "duration": 4,
  "resolution": "<批准的分辨率>"
}
```

核对请求确实发送 `duration: 4`，以 `ffprobe` 或等效工具读取实际媒体时长并与浏览器播放结果比对。若容器存在时间基偏差，按已确认合同记录允许范围。使用 `GET /v1/tasks/{id}/artifacts` 获取可见制品。默认按渠道实际提供的媒体代理或交付路径检查 GET、HEAD 和受支持的 Range。若启用了 `StoreGeneratedVideos` 且任务绑定了存储配置，再核对执行阶段成功、已落对象和实际签名播放，验证刷新后仍能获取可用交付链接。末帧仅在本轮要求且相应合同提供时单独核验。Seedance 的估算 Token 与完成用量分开记录，实际费用以本笔有效配置和结算事实复核。[豆包插件](../../plugins/tasks/doubao/plugin.js) · [通用任务路由](../../router/task-router.go) · [Seedance 转存](../../service/seedance_video_storage.go) · [存储交付](../../service/seedance_video_delivery.go)

## 4. 数据与金额核验

每轮生成 `run_id`，每项使用表中 `case_id`。请求标记仅放在无敏感提示词或本地执行记录内。保存服务端 `X-Oneapi-Request-Id`、测试账号/Key 别名、时间及适用的公开任务 ID。同步用请求 ID 查日志，插件任务用公开 ID 关联任务及 `other.task_id` 等实际保存的资金引用，必要时核对管理员投影中的任务执行请求 ID。补扣、退款日志可能使用不同的关联标识。若同步图片未返回任务 ID，通过请求 ID 及日志的任务关联查证。仅时间相近、金额相等或「没有错误日志」不能证明唯一关联或无外发。[请求 ID 中间件](../../middleware/request-id.go) · [任务管理投影](../../controller/task.go) · [任务计费日志](../../service/task_billing.go)

| 时点 | 读取与断言 |
| --- | --- |
| Before | 读取 `users.quota`、有限额 Key 的 `tokens.remain_quota`、适用统计、当前价格与任务/日志基线。记录价格模式、资金来源、组及适用折扣。 |
| Accepted | 若路径可观测，记录实际渠道/插件、持久任务、已观察到的预扣与定价快照摘要。即时结果或过短的中间态按实记录观察缺口。 |
| Settled | 等待适用任务终态、资金与消费日志落地。对照 `tasks`、实际资金与日志事实，重复只读查询，核对任务状态、费用、账本变动和可用制品。观察到结算恢复 journal 时，确认相应的资金和日志最终收敛。已清理的 journal 可以没有记录。 |

优先使用现有会话接口，例如 `GET /api/user/self`、`GET /api/log/self?request_id=…`、`GET /api/task/self?task_id=…` 及对应管理员读接口。钱包和统计读数须在缓存及批量落库收敛后对照。需要只读查库时使用最小权限和列白名单，主库与日志库分别核查。私有快照仅在受控进程内提取必要事实。报告只写匹配结论、数量、quota 差额和脱敏引用。[会话 API](../../router/api-router.go) · [日志类型与字段](../../model/log.go) · [任务结算恢复](../../service/billing_recovery.go)

对隔离个人钱包与有限额 Key，分别计算期初减期末余额，与本轮该主体实际承担的净扣费逐笔核对。按路径区分初扣、补扣和实际退款，排除诊断记录、组织统计、重复投影及已被最终额度包含的预扣。`used_quota` 按对应路径的累计和退款语义单独核验。在途预扣另列。退款按类型和资金方向核对，重点排查重复扣费、重复退款、无依据的信用及饱和裁剪。

复算以该笔冻结或实际留存的价格、计价用量、有效组倍率、适用的折扣与原舍入规则为准。区别按次、传统倍率、文本表达式和插件用量表达式。插件用量表达式的结果已经是美元金额，Token 字段的百万单位换算按表达式本身。组倍率和折扣按原合同只计一次。原始 quota 精确核对，界面金额按显示精度核对。`/api/pricing` 用于核对当前报价。历史缺少复算字段时单列证据缺口，供应商账单有延迟时单列待对账。[计费表达式](../../pkg/billingexpr/expr.md) · [额度转换](../../common/quota_math.go)

## 5. Browser Use 同笔验收

1. 用 Computer Use 或现有浏览器自动化打开本轮前端并登录 A。完成前置状态检查后进入 `/pricing`，定位用例模型，核对单位、规格或分组。报价页与实际费用详情分开记录。
2. 到 `/usage-logs/common`，用请求 ID 定位 T1/T2/I1/I2 的消费记录并展开详情，核对费用、单位、数量及已记录的计价分项。异步差额或退款按数据核验取得的关联证据找对应记录。对比中文和英文显示，保留同一笔的脱敏截图。
3. 到 `/usage-logs/task`，以平台任务 ID 查找 V1 及适用的插件图片。刷新后确认状态和制品行为一致。实际播放视频并拖动，校验显示时长和下载。有保留的图片打开预览。即时交付且未保留的图片核对任务记录和提示，媒体本体通过客户创建响应检查。
4. 到 `/wallet` 核对个人钱包余额变化，以消费日志为逐笔费用入口。若本轮含组织账单，再到 `/organization/logs` 或 `/organization/invoice` 验证同一数据的只读汇总。账单归属、时间范围和延迟按该功能合同验收。
5. 用独立管理员会话打开 `/channels`、`/task-plugins` 和日志页面，核对真实渠道、插件版本及仅管理员可见的诊断。B 使用独立会话检查任务与消费列表的隔离。若工具不能开独立会话，则显式登出后再登录 B 并确认身份。仅切标签页不能隔离身份。

浏览器记录路由、用例与请求/任务别名、可见值和脱敏截图。截图避开媒体签名、账号信息和上游诊断原文，不导出完整 HAR。浏览器不可操作或同笔记录无法关联时，该界面维度标 `BLOCKED`。[日志页面分区](../../web/src/features/usage-logs/section-registry.tsx) · [日志查询](../../web/src/features/usage-logs/api.ts) · [钱包路由](../../web/src/routes/_authenticated/wallet/index.tsx)

| 实时模型折扣、代理分销或组织账单 | 使用同模型同渠道的普通账户和指定账户对照，核对实际命中范围、结算快照和页面。代理采购账与客户钱包分别核对。组织账单是只读投影，按已发布合同核对汇总和权限。[实时模型折扣架构](../20-architecture/用户与组织实时模型折扣架构设计.md) · [代理分销架构](../20-architecture/代理分销与用户专属倍率架构设计.md) · [组织账单架构](../20-architecture/组织与组织账单架构设计.md) |
| 持久化、事务、迁移或恢复 | 按项目规定在真实 SQLite、MySQL、PostgreSQL 执行验证，记录精确版本、命令和结果。迁移覆盖新库、代表性旧库升级和重复启动，适用时加日志库。真实渠道冒烟至少覆盖目标部署的方言，单次 E2E 不替代数据库矩阵。 |

## 7. 中断、恢复和结论

- 每个创建前保存脱敏发送意图。POST 超时、断开或结果不明时停发，凭已取得的请求 ID、账号与已确认的任务/日志证据定位，检查可能存在的预扣、已创建任务与后续结算。恢复只做查询和核验。重发须有明确的幂等合同。查询暂时失败可在截止时间内重试 GET，记录轮询超时和在途责任。
- 真实烟测只覆盖实际观察到的链路。并发、崩溃窗口、重复通知和恢复时序由隔离的确定性回归保护。真实上游失败时核对当前路径的退款或保留额度。生成成功但交付异常时分别报告业务、资金与交付结论，按现有恢复流程处理。
- 达到预算上限、发现意外选渠、重复创建或结算、泄漏时停止后续创建。保留后台轮询和结算条件及待处理清单。结清后按既有流程停用临时 Key 或分组，受控清理本地下载，资金与历史审计按现有流程保留。
- 首轮可人工执行。若后续固化，可在 `scripts/` 增加独立 Bun 执行器，复用公开 API 和会话读接口，按「预检 → 串行 API → 数据 → 浏览器 → 报告」执行，支持用公开任务 ID 恢复只读查询。该入口待实现。

报告对每项分别记录 API、资金、媒体、UI 结论及证据索引。结果使用 `PASS`、`FAIL`、`BLOCKED`、`NOT_APPLICABLE`。缺配置、关联或超时未得终态的必测项用 `BLOCKED`，`NOT_APPLICABLE` 仅用于经确认不在本轮发布范围的扩展项。所有必测项证据完整且通过、真实费用在预算内、无未解释资金差额，才报告本轮通过。未测渠道、上游账单对账状态、三库验证范围和生产灰度状态各自列出。

```text
run_id / 版本与差异摘要 / API 与前端环境 / 数据库版本 / 客户及上游预算
case_id / 客户模型 / 渠道与插件版本 / 请求 ID 别名 / 公开任务 ID 别名
HTTP 与终态 / 计费来源及前后 quota / 媒体结果 / UI 结果 / 脱敏证据索引
待处理任务 / 未验证范围 / 供应商待对账 / 最终结论
```
