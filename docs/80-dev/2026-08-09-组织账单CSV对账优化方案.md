# 组织账单 CSV 对账优化方案

## 问题与目标

当前 Invoice 专用 CSV 混入组织 ID、内部时间戳、结算规则来源和原始 quota，且用户列缺少可直接用于财务对账的真实姓名。本次优化的目标是把该导出收敛为面向财务对账的白名单格式，同时保持账期金额、结算系数和结算后金额口径不变。

## 当前实际情况

已通过截图和现有代码确认以下现状：

- 文件头导出组织 ID、账期、时区、开始时间戳、结束时间戳和币种；
- 模型类别汇总导出账号、折前合计、结算系数、规则明细、结算后金额和折前额度；
- AI 模型消费汇总导出账号、合计、占比和折前额度；
- Invoice 聚合结果中的显示名经过脱敏，不能直接满足财务实名对账。

用户已确认目标口径：组织 ID 改为组织名称；删除时区、开始时间戳和结束时间戳；用户列增加真实姓名；删除规则明细和折前额度（quota）。

## 优化方案

- 文件头仅保留组织名称、账期和币种；组织名称从主数据库当前组织记录读取。
- 两张交叉表在账号表头上方增加“真实姓名”表头行，真实姓名与账号列一一对应；真实姓名取用户 `display_name`，为空时保留空单元格，账号表头继续承担稳定识别与回退职责。
- “模型类别”和“模型”表头行中的用户列严格取 `users.username`，不得用 `display_name` 替代；本地 Invoice 验收脚本使用 `invoice_demo_admin`、`invoice_demo_member` 这类明确的账号型用户名，避免把中文测试用户名误认成真实姓名。
- 真实姓名只在已有组织管理员/系统管理员权限保护的 Invoice CSV 导出路径读取；Invoice 页面与 JSON API 继续使用脱敏显示名。
- 模型类别汇总保留折前合计、结算系数和结算后金额，删除规则明细与折前额度。
- AI 模型消费汇总保留合计和占比，删除折前额度。
- 金额继续输出无货币符号的六位小数，账期聚合与结算算法不变。

验收以 CSV 结构测试和组织 HTTP E2E 为准：必须验证组织名称存在，真实姓名行与账号行严格对齐，且组织 ID 元数据、时区、时间戳、规则明细、脱敏姓名及 quota 列均不存在。
