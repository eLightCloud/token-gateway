# Rc40 上游合并与验证

## 问题与目标

将官方 `v1.0.0-rc.40` 合入本地，主页和样式以本地为准，通用业务逻辑以官方为准，本地扩展通过最小接入保留。此次仅更新代码，不部署或推送远端。

## 当前实际情况

- 本地基线：`73ee44f90`，已包含 rc.31 和本地 OpenAI 断流修复。
- 上游目标：`v1.0.0-rc.40`，提交 `0aec08fee811ec6136828fda790551b49e410301`；rc.31 到 rc.40 共 163 个提交。RC 是预发布标签，不将其描述为正式稳定版。
- 在独立工作树进行合并。原工作区未提交的 NGINX 文档、视频方案和运维 README 保留；两份 AGENTS 中已有的中英文语言范围要求随合并保留。

### 经确认补齐组织折扣接入

本地基线已有组织折扣管理及结算模块，但主请求未调用快照加载入口。用户确认在本次补齐后，新请求会按已配置的组织渠道倍率实际收费；既有任务仍使用各自保存的计费上下文。

- 新增独立 `service/organization_discount_request.go`，现有请求准备、任务提交和图片预扣流程仅增加必要接入。
- HTTP 和 Responses WebSocket 每次请求在预扣前加载一次完整快照，包括“无折扣”的结果；同次请求重定价和渠道重试复用该快照，下一次请求读取最新配置。加载或解析失败拒绝请求，不退化为原价。
- 普通请求、图片数量调整及任务重试按已有准入规则处理：折扣不降低原价准入门槛，加价须补足预扣；重试只增加必要差额，最终失败幂等退款。
- 即时完成与异步任务的表达式结算均应用已固定倍率，并在任务及管理员日志中保留快照 ID、渠道和倍率。倍率采用 decimal 计算，避免 `500 × 0.29` 被浮点截断为 144。
- 保持既有 Midjourney 独立计费边界；此次不为其引入组织折扣。
