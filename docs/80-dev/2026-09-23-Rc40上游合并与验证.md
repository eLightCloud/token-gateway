# Rc40 上游合并与验证

## 问题与目标

将官方 `v1.0.0-rc.40` 合入本地，主页和样式以本地为准，通用业务逻辑以官方为准，本地扩展通过最小接入保留。此次仅更新代码，不部署或推送远端。

## 当前实际情况

- 本地基线：`73ee44f90`，已包含 rc.31 和本地 OpenAI 断流修复。
- 上游目标：`v1.0.0-rc.40`，提交 `0aec08fee811ec6136828fda790551b49e410301`；rc.31 到 rc.40 共 163 个提交。RC 是预发布标签，不将其描述为正式稳定版。
- 在独立工作树进行合并。原工作区未提交的 NGINX 文档、视频方案和运维 README 保留；两份 AGENTS 中已有的中英文语言范围要求随合并保留。

## 优化方案与合并结果

| 边界 | 处理结果 |
| --- | --- |
| 主页、样式、品牌配置 | 保留 `features/home/` 的本地页面、`lighting-home.css`、`local.css`、本地 favicon、亮色主题和品牌解析。主页数据 hook 接入上游共享查询；导航最小接入管理员更新入口。 |
| 上游业务能力 | 接入 rc.40 的 Responses WebSocket、请求计费准备、响应模型观测、审计日志、安全设置、模型定价与任务插件修复等变更。 |
| 组织、Invoice、Token 账单和对账 | 本地业务模块和导航保留；操作审计改用上游独立 `AuditLog`，测试覆盖组织回填和失败审计。 |
| 管理员调额 | 采用上游权限检查、事务锁定与缓存差额更新，保留本地 int64 余额与账单事实；持久化 `UserQuotaAdjustment` 放入独立本地文件，同一事务记录操作人、前后余额和差额。 |
| 资金结算与恢复 | 保留本地事务流水、幂等扣退费、恢复任务和大额余额。音频结算移除重复入口，统一通过本地流水提交；rc.40 的固定价格及图片预扣规则保留。 |
| 异步任务 | 采用上游任务结果保留策略及即时完成用量规则；通过本地快照函数保存计费上下文和已有折扣事实。 |
| 断流 | 保留本地客户端断开后的受限排空。SSE 断开后必须有成功终态及完整上游用量才能结算，否则退款；同时使用上游 Responses 用量累计器与状态分类。原生 WebSocket 使用 rc.40 的连接与结算逻辑。 |
| 数据库 | 保留本地 MySQL/PostgreSQL 迁移适配及 bigint 钱包字段，合入上游新模型和迁移。 |
| 国际化 | 合并 en/zh 的上游新文案和本地扩展文案，五个遗留语言文件保持原基线。 |

### 既有缺口，未改变收费行为

本地基线已经存在组织折扣管理、快照读取及结算函数，但 `LoadOrganizationDiscountSnapshot` / `ResolveOrganizationDiscountSnapshotForChannel` 没有被主请求定价流程调用。因此，保留这些模块不等于当前请求已实际加载组织折扣。本次保留原有收费行为；是否补齐加载入口需要单独确认，因为会使已配置折扣影响实际收费。该问题并非本次合并引入。

### 数据库矩阵

真实实例：SQLite **3.50.4**、MySQL **5.7.44**、PostgreSQL **9.6.24**。外部数据库均为此次专用 Docker 测试实例，不访问业务数据库。

每种引擎均执行以下 3 组完整 `model.InitDB()` / `model.InitLogDB()`，主库和独立日志库均覆盖：

1. 合并版创建新库，随后连续启动两次。
2. 合并前本地源码创建代表性旧库，再用合并版升级及重复启动。
3. 官方 rc.40 源码创建代表性已发布版本数据库，再用合并版升级及重复启动。

共 **9 组通过**。验证既有中文数据、用户/Token 超 32 位余额、消费日志和本地组织/调额数据保留，重复用户名与 Token key 仍被唯一约束拒绝；升级后的两次启动得到相同的列和索引快照。

此外，设置专用 `TEST_MYSQL_DSN` / `TEST_POSTGRES_DSN` 等测试环境变量后执行：

```sh
go test ./model ./service ./controller -count=1 -v -run 'TestMigrationSchemaStability|TestMigrate.*MySQL|TestMigrate.*PostgreSQL|TestUserSessionPreviousRefreshHashMigrationConfiguredDatabases|TestRequestPolicyDatabaseMatrix|TestSystemTaskHistoryDatabaseMatrix|TestInferencePresetSettingsAndDatabaseRoundTrip|TestFixedPriceBillingDatabaseMatrix|TestPreConsumePolicyDatabaseMatrix|TestAuditDatabaseMatrix'
```

以及分别设置 `TEST_MANAGE_USER_DIALECT=mysql/postgres`、`TEST_MANAGE_USER_SEPARATE_LOG_DB=1`、`TEST_TASK_DB_DIALECT=mysql/postgres`：

```sh
go test ./controller -count=1 -v -run 'TestManageUserQuota|TestImmediateTaskSettlementDatabase'
```

结果均通过，覆盖预扣、图片加量限制、文本/音频固定价格、结算退款、审计迁移、管理员调额及账单事实。

运行证据和一次性完整迁移脚本保存在 `/tmp/rc40-*.log`、`/tmp/rc40-migration-results/`、`/tmp/rc40-migrate.go`、`/tmp/rc40-run-migrations.py`。首次 MySQL 业务测试使用的测试库默认 latin1，导致中文日志插入失败；改用 utf8mb4 专用测试库后全部通过，未为测试环境问题修改生产逻辑。
