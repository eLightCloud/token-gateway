# 代理分销与用户专属倍率实施方案

## 问题与目标

在现有 new-api 上实现专用一级代理、客户钱包消费、模型渠道授权、用户专属倍率、异步采购账及账户安全补齐。目标负载是单个代理持续 500 QPS、连续数小时调用，消费器延迟不阻断业务。

业务规则唯一见[产品设计](../10-product/代理分销与用户专属倍率产品设计.md)，技术合同唯一见[架构设计](../20-architecture/代理分销与用户专属倍率架构设计.md)，取舍见 [ADR-0003](../20-architecture/decisions/0003-代理额度异步记账与用户专属倍率.md)。本文维护技术工作包、接线和验证方法；分阶段执行顺序、进入/退出条件、执行状态及验收证据唯一见[阶段实施计划](../50-planning/2026-11-03-代理分销阶段实施计划.md)，不重复维护第二套进度或业务规则。

## 当前实际情况

### 已核对的代码事实

- `BillingSession`、`PreConsumeBillingBalances` 与结算 journal 已有 B 资金和 Token 的事务边界；当前没有代理采购账户或完整代理事件链。
- 完成的 journal 会被删除，不能作为长期代理账；任务已有最终费用确认入口，零差额路径也需要代理接线。
- 普通钱包部分补扣允许欠额，存在信任预扣旁路；不能直接承诺新客户按折后实际渠道严格预扣已经满足。
- 分组模型渠道能力由 `Ability` 与渠道选择器维护，存在缓存、数据库、指定渠道、亲和及重试路径，不能只改默认随机选路。
- 管理权限有超级管理员放行；B 的专属商务边界必须在领域层覆盖通用管理接口。
- TOTP、恢复码、`AuthFlow` 和用户会话基础已存在；尚未证明所有登录方式、旧会话和后台凭证满足强制邮箱/MFA。
- 当前前端真实入口为 `web/`，有 `features/users`、`features/pricing` 和 `features/security` 等基础。部分旧工程文档仍引用 `web/default/`，本专项命令以当前 `web/package.json` 为准，不顺带改无关文档。

### 用户提供的运营事实

运营已手动关闭公开注册、邀请和在线充值；可由管理员在业务上将渠道模型统一到 `default`。这些是运营现状或选择，不是新增代码假设，不能替代代理授权及入额路径的服务端控制。

### 本次文档交付状态

初始设计交付只包含设计及入口登记；后续 S0 已增加并运行现有行为基线测试、隔离数据库工具及恢复核对，这些不是代理业务实现或新功能验收。代理功能、安全合规及 500 QPS 容量仍不得据此宣称通过。S0 的实际执行、复验结果与未关闭门槛仅见阶段实施计划，下列工作包不维护第二套进度。

### W0：接线核对与前置证据

输出以下有界清单作为 W1–W3 编码依据：

1. **扣费路径**：文本/流式、Responses、图片、音频/Realtime、统一异步任务，以及目标部署实际启用的旧任务入口；标记预扣、发送前补扣、最终确认、退款和恢复位置。
2. **计价基数**：各路径在新增专属倍率前的实际 `Q`、估算 `Q`、舍入方式、组织/分组/渠道倍率所在位置。默认 `1` 必须保留现有行为，不重写表达式。
3. **管理绕过**：用户更新/角色/删除、通用调额、充值补单、兑换、奖励、订阅、批量 API、管理 PAT、Key 创建及用户模型列表。
4. **安全入口**：密码、OAuth/OIDC、Passkey、旧会话、邮件绑定/找回、TOTP、恢复码及管理员安全重置；核对 auth version 与 API Key 的耦合。
5. **运行环境**：生产计划数据库及版本、实例数量、Redis 开关、日志库、实际渠道/协议、硬件及并发模型。使用非生产账号和合成业务数据。

不得把未接入的计费入口默认为已支持。目标部署所有开放给 B 的入口必须闭环；未验证入口不得发布为可用，需记录限制及后续验证，不能用静默绕过计费维持表面可用。

### W1：身份、配置和流水

新增代理领域模型、迁移注册和访问层，复用 `User` 与密码/会话基础。不存在代理关系的存量用户保持原样；专用 A 不取得个人消费权限；B 初始额度为零，开户邮件激活。

新建 B 和归属同事务，唯一关系防止重复绑定。人工额度操作以客户端操作标识/服务端持久凭据防重复，减额原子验证可用额度；事务提交后更新或失效缓存，不能覆盖并发扣款。

按模型渠道保存显式授权和用户倍率。可编辑配置使用乐观锁，历史保存操作者与修订；记录 `1` 与未配置可在显示上归一，但不能因此丢失明确授权。没有二级代理、跨客户批量配置或角色转换接口。

迁移要同时覆盖普通与快速启动注册；新表、字段与索引在三库实测，禁止用开发库手工建表代替迁移。

### W2–W3：请求计费和恢复

专属上下文放新的宿主领域文件，必要时加到 `RelayInfo`、价格数据和任务私有快照。不得在宿主外的 `relaykit/` 引入数据库或代理模型依赖。

请求准入加载归属、授权与相关模型的倍率修订；渠道选择过滤有效范围，实际渠道确定后从快照匹配。不要每次请求扫描全平台配置；缓存须区分用户、模型、修订，不把 B 私有倍率缓存到匿名响应。

代理客户仅钱包，发送前按折后预估额度执行真实预扣，覆盖受限 Token；禁用其信任旁路。更贵渠道补预扣原子失败就不发送。保留既有预估外最终补扣行为，不宣称能预测最终费用。

预扣、最终扣款、退款和对应代理事件在各自资金事务内提交。新增持久请求/生命周期收据解决预扣后崩溃、重复完成及 journal 清理后重放。任务提交仍为处理中，必须覆盖最终费用等于预扣的确认入口，不能只监听非零 delta。

对于已退款的迟到结果，沿原终态判断处理；不新增另一个超时退款器。部分退款按原累计目标计算冲销；消费与退款业务时间分开保存，操作发生时间不能在每次恢复时刷新。

### W4：代理投影和持续调用

复用现有 SystemTask 调度基础评估后台入口，新增专用处理器；实际调度频率需达到持续吞吐目标，不能沿用低频恢复扫描后宣称约一秒更新。

消费器选取有索引的持久待处理集合，以有界批次合并同 A 的变化。A 汇总与事件入账标记同事务；同请求顺序检查，事务提交乱序不会被最大 ID 水位跳过。失败重试、消费者重启和多实例抢占均不重记。

正常约一秒发布是初始优化目标，批量大小和扫描频率根据实测调整。积压告警不改变准入，不能添加最大账龄停用开关。已发布 A 可用额度不足则拦截新请求，补额/退款发布后恢复；资格停用、客户停用与额度不足不混写。

指标至少包括：事件产生/处理速率、待处理数及最老年龄、发布延迟、批次事务耗时、失败重试、A 余额和占用、负余额、B 预扣延迟、数据库锁等待、缓存状态、查询及导出耗时。指标不能记录敏感请求或凭证。

### W5：安全补齐

安全规则依据架构文档列出的 OWASP 官方来源。实施时重新核对最新稳定 ASVS，并记录所用版本及准确 requirement ID、适用路径、实现和验证结果；不能用“有 MFA”代替整体认证控制验证。

复用现有身份方式，A 同样走邮箱验证、自设密码和 MFA 激活。B 的邮箱由持有人验证，不将 A 填写等同身份核验。邮件不可达可重发/纠正待激活地址，不能用固定初始密码绕过激活。

服务端普通后台接口限制未完成安全配置的用户，包括旧会话和管理 PAT；必要激活/登录/安全 API 按用途允许。Key relay 与后台认证分类，已有 Key 不因强制补齐或普通 MFA 重置中断。近期身份验证、令牌过期/一次性、CSRF、登录/邮件/恢复速率限制和安全日志脱敏均纳入回归。

平台资料修改不能调整 B 的额度、授权、倍率。管理员改邮箱发起待验证流程；MFA 重置使用独立权限及人工核验记录。上线前确定人工核验依据、责任人和通知流程，这属于运维实施前置，不虚构用户已确认的具体核验材料。

### W6：当前页面扩展

新增代理 feature、API 客户端、路由与导航，原 users/pricing/security 模块只做最小调用接入。不要直接把管理员用户列表开放给 A，也不复用带敏感字段的通用管理 DTO。

实施前必须读取 `web/AGENTS.md`、项目 `shadcn-ui`、React 性能及 i18n 技能，检查组件实现和调用例后再选用。优先候选：

- `web/src/components/data-table/`：分页、列表、筛选及工具栏；
- `web/src/components/dialog/`、`confirm-dialog`：额度调整、停用和授权恢复影响提示；
- `web/src/features/users/components/user-quota-dialog.tsx`：评估复用现有额度交互，去掉代理业务不允许的覆盖模式；
- `web/src/features/pricing/components/model-card.tsx`：通过新专属倍率展示组件最小接入；
- `web/src/features/security/`：安全补齐和现有绑定流程；
- `@/lib/format`、`@/lib/currency` 和 `toIntlLocale`：沿用当前单位与格式化规则，不把记账金额解释为线下实收。

这是候选清单，不代表已经完成组件能力评估；保留新增通用实现时需记录具体缺口。新增/修改文案只维护 `en`、`zh`；模型卡片覆盖未登录、倍率全 `1`、单折扣、加价、混合范围及语言切换。

代理导出采用专用 DTO 和有界分页，与页面同筛选、同计费口径。B 的详情、原日志、嵌套 other、倍率历史、模型列表、任务接口及导出均做渠道脱敏。A 不返回请求/响应正文、Key 或认证秘密。

产品设计“页面与导出”章节拥有页面行为，架构“前端身份与路由接线”拥有数据和守卫边界。按以下顺序落地，不另建平行 UI 规格：

|---|---|---|
| W6.1 导航与准入 | 平台代理入口、A 默认客户管理、B 受限消费导航；普通用户兼容 | 不提权 A；直接 URL、嵌套导航、后退及重载均受控；受限页不启动业务查询 |
| W6.2 平台代理管理 | 代理列表与详情、采购调额、授权/倍率、启停及影响提示 | B 通用行操作移除商务编辑、删除和订阅；资料修改及独立恢复仍可用 |
| W6.3 单客户工作区 | 客户列表顶部三项采购指标；创建抽屉；四页签详情；额度弹窗 | 无跨客户批量，无覆盖；客户切换不串草稿，余额并发变化以服务端为准 |
| W6.4 授权及倍率 | 模型选择、渠道行授权及倍率、保留失效配置、未保存与冲突提示 | 未授权、默认 1、上级撤销三种状态区分；范围、精度和失效恢复正确 |
| W6.5 消费与采购账 | 按客户/模型/时间/状态筛选、双维状态、原交易退款、更新时间和导出 | 待结算不填零、待入账不当处理中；暂扣/结算不重复加总；延迟无阻塞 |
| W6.6 B 原消费界面 | 受限额度组合、实际倍率和历史、模型卡片倍率范围 | 不请求支付/订阅/奖励数据；匿名缓存隔离；所有出口无渠道信息 |
| W6.7 安全步骤 | 邮箱、首次设密、MFA 和恢复码；因素更换/恢复 | 不开放完整安全中心其他操作，无关闭强制 MFA、无 A/B 自助删除；旧 Key 保持调用 |

#### 已核对的组件能力差异

- 原 `UserQuotaDialog` 固定调用管理员 `adjustUserQuota`，提供 `add/subtract/override`，没有原因输入；不能直接导入用于 A。先评估增加兼容的模式限制、原因和提交回调是否适合公共 API；若不适合，新客户 feature 组合现有 Dialog、表单和确认能力，记录这一具体缺口，不能复制通用交互或改坏普通用户管理。
- 原 Users 页面组合通用编辑抽屉、删除和管理操作；A 需要名下查询、固定身份、邮件激活和独立商务能力，不整页复制，也不直接赋予管理员页面权限。
- 原 Wallet 顶层初始化多种支付/奖励 Hook；在挂载边界选择 B 的受限视图，避免条件隐藏后仍发无权请求，不重构原支付状态机。
- 原 Security 页面含访问令牌和删除卡片，TwoFA 卡片含关闭入口；复用具体绑定组件，补齐步骤和完整安全中心分开编排。
- `SectionPageLayout` 已有标题、动作和面包屑槽位，`DataTablePage` 等已有响应式表格能力，`ConfirmDialog` 已有加载和危险确认；新增 feature 优先组合，不另做同类布局或确认弹层。

以上只证明候选的部分能力已核对，不代表组件兼容扩展或 UI 已实现。实现前仍需核对当前 props、调用方和测试，保证对原页面无回归。

#### UI 验收场景

按平台管理员、A、B、直属普通用户分别验证桌面和窄屏，覆盖：加载、空数据、查询失败、旧数据显示、权限变化、并发保存冲突、未保存离开、重复提交、激活重发、平台与代理双重停用、账务积压和多渠道倍率范围。状态文字与颜色一致，表单有 label 和字段错误，弹窗键盘及关闭后焦点恢复正确；日期/数字格式、中英切换和导出同口径。

UI 证据应记录实际页面截图及关键操作结果，不能把源码分析或表格组件已有测试视为新页面视觉验收。仅访问页面即可触发的无权后台请求也应计为缺陷，不以“用户看不到按钮”解释。

## 验证计划

### 行为与账务回归

优先扩展现有合适测试，按稳定合同组织，不为每层调用机械新增测试文件。新 Go 测试使用 testify require/assert。核心场景：

| 场景 | 必须断言 |
|---|---|
| 标准基数 100，A 为 0.8，B 为 0.9 | B 最终 90，A 支出 80，差额 10，共同基数只算一次 |
| B 低于采购价、倍率边界及非法输入 | 负差额允许；拒绝零、负数、大于 2、超精度和非有限值；未配置为 1 |
| 原价预扣不足但折后足够 | B 可按实际渠道的折后费用准入；更贵渠道补足失败不发送 |
| 请求期间改倍率、异步任务跨配置修改 | 所有后续结算及退款沿原快照 |
| 预扣后全退、最终相等、部分退、跨月退 | 无占用残留；原账期不改；累计冲销不超过原费用 |
| 预扣崩溃、结算中崩溃、日志库失败 | 不丢资金事实；恢复同操作不重复，日志库失败不抹除主库事件 |

### 持续负载与故障注入

验收工程基线建议使用单 A、多个真实数据库客户账户、持续 500 QPS 至少 3 小时，约 540 万次请求；这是后续待执行的测试规模，不是本次结果。客户数、并发数、模型费用、流式/异步比例、失败和退款比例使用明确 fixture 和目标业务分布，禁止空转计数或 log-only 假压测。

使用可控上游以区分网关瓶颈与供应商速率限制，并另做真实目标渠道联调。至少同时覆盖：

1. 正常消费器持续运行，事件处理长期跟上产生速度，查询和导出并发运行。
2. 人为停止消费器一段时间后恢复，调用不因积压停用，积压可追平且净额一致。
3. 代理余额由已发布正值变不足，再补额恢复；验证在途结算与允许超用。
4. 进程或消费器重启、主库短暂事务失败、Redis 不可用、日志库不可用和退款重放。
