# 用户与组织实时模型折扣实施方案

## 问题与目标

实现已确认的 [产品规则](../10-product/用户与组织实时模型折扣产品设计.md)、[架构合同](../20-architecture/用户与组织实时模型折扣架构设计.md)及 [UI合同](../90-ui-ux/用户与组织实时模型折扣UI设计.md)。长期规则由对应文档拥有，本文件仅维护实施步骤、基线、风险和验证证据。

目标是每个用户或组织每模型一个倍率、多选适用渠道，实际执行渠道按用户、组织、系统顺序匹配。折后预扣和结算一致，范围不限制路由，显式 1 覆盖而删除恢复继承。既有组织配置和代理采购能力保留。

## 当前实际情况

### 实施前已核对的代码基线

| 位置 | 事实及缺口 |
|---|---|
| `model/reseller_config.go`、`model/reseller_pricing.go` | 配置按用户/模型/渠道逐项保存；普通用户加载时过滤倍率 1；不能表达新的一模型一倍率及显式原价覆盖 |
| `service/reseller_pricing.go` | 个人倍率在收到的费用基数上另行计算，不能直接把新组织倍率放入同一条叠乘链 |
| `model/organization_discount.go`、`service/organization_discount*.go` | 旧组织规则按渠道保存；已进入实时计费，低于 1 的组织折扣保留保守原价预扣，不等于本专题折后准入 |
| `relay/request_billing.go`、`service/billing_session.go`、`controller/relay.go` | 估价、选渠道、预扣及重试接线需要确保先匹配实际渠道再按折后目标准入 |
| `service/task_billing.go`、`service/reseller_task_billing.go` | 已有任务计价快照、journal、退款恢复；需扩展来源和版本，保留旧任务行为 |
| `web/src/features/reseller/config-editor.tsx` | 当前逐模型渠道行编辑，可同时保存一个模型多种倍率；需改为按模型聚合的实时规则编辑 |
| `web/src/features/organizations/discount-panel.tsx` | 旧组织渠道折扣 UI，继续保留；新增实时入口，不能替换其合同 |
| `web/src/components/multi-select.tsx`、模型选择器、数据表/Dialog/ConfirmDialog | 现成选择和编辑能力可组合，无需新增通用控件 |

### 已完成的独立修复

额度不足消息已改用 `requiredQuota`，在 `service/task_billing_test.go` 增加折扣与加价用例，且断言余额达到提示金额时通过。观察到修复前两例失败，修复后 `go test ./service -run 'TestPersonal' -count=1` 通过，`git diff --check` 通过。该修复已纳入本次实现；完整交付证据见下方实施记录。

### 已确认决策与迁移待取证

已确认：规则唯一性、静态渠道适用范围、不限制路由、逐渠道来源继承、显式 1、删除恢复、无新倍率叠加及折后实时预扣/结算。

追加确认：保留原信任免预扣资格，最终按冻结倍率结算；用户与组织实时倍率统一 `(0, 5]`、最多两位小数；组织实时规则及管理预览仅平台 Root。旧组织渠道折扣范围保持原样，用户管理权限不变。

迁移前待取证：旧同模型多倍率、不能精确转换到两位小数及新范围外记录的实际清单与处理结果，旧接口消费者和实例清单。需要依据真实数据逐项处置，不在当前文档阶段虚构冲突或要求用户决定不存在的数据。

重试按冻结配置重新匹配目标渠道，非信任请求补扣成功才发送；信任请求保留原策略。新增渠道不自动纳入。通过边界用例验收，不将“同模型一个配置倍率”误测成“所有请求价格相同”。

## 优化方案

### W0：固定合同与迁移输入

- 按已确认上限、精度、信任与 Root 权限核对 ADR-0002/0003 中旧倍率、共同基数及保守预扣的适用边界；需要 ADR 时按目录标准另行记录，不直接改写历史结论。
- 只读检查存量用户同模型渠道倍率：相同倍率可聚合，多个倍率必须列出冲突供运营确定；不自动最低价、最高价或最后写入胜出。
- 检查未覆盖渠道、现有显式 1、授权与倍率共表、旧非 1 组织配置及全部精度/范围冲突。迁移不把授权删除等同删除折扣，也不把采购倍率当作消费倍率迁移；不自动舍入到两位小数。
- 固定新 API 请求/响应/冲突语义和快照格式；新能力用独立端点。按架构切换合同盘点旧消费写调用方、冻结所有实例写入、备份、转换、校验、统一启用新读取和关闭旧消费写入口；登记旧接口迁移提示并验证既有授权/采购入口独立可用。
- 切换前检查所有节点和任务消费者支持新旧快照。切换过程中不能保证一致读取时停止新请求准入，不容许旧节点继续按旧个人倍率处理新请求。
- 分别演练迁移前失败、迁移后未启用失败、启用后失败；启用后保留兼容新快照的修复版本，不恢复旧数据库覆盖新交易。不得将可回退偷换成随时部署旧二进制。

### W1：独立领域存储与配置接口

- 在新专用文件维护实时规则、渠道集合、版本、历史和领域校验；上游原文件仅最小迁移注册与路由接线。
- 唯一约束按主体类型/主体 ID/模型键建立。用户/组织实时倍率保留现有百万分制单位，新值为 `10000..5000000` 且为 10000 的整数倍；范围/两位小数校验在服务端执行。旧快照继续按原范围/精度解释，不新增单位转换层。
- 为每主体建立持久配置头和单调总版本，整份保存以 `expected_revision` 条件更新；配置头、规则、渠道和历史同事务写入。删除最后一条规则保留配置头，重建不重置版本；响应返回本事务保存结果。
- 删除/移除显式表达继承，保留倍率 1。历史失效渠道允许保留与移除，不能新增非法模型渠道关系。
- API 提供模型候选、对应渠道候选、规则读写/历史及生效预览。组织管理全部仅 Root，指定成员预览额外验证当前成员关系；用户规则沿原资源边界。返回字段白名单，不泄露渠道密钥。写失败不提交半份配置。
- 完成真实三数据库新建/升级、重复启动、唯一约束和并发保存测试后，才能宣称存储兼容。

### W2：唯一解析器与请求计价

- 独立解析器在主库同一一致性快照事务中冻结组织关系、双方配置头、相关模型规则/渠道和缺失事实；MySQL/PostgreSQL 为 Repeatable Read，SQLite 为 Serializable。涉及旧组织基础倍率时一并冻结其快照；所有查询使用同一 `tx`，不借全局 DB 或事务外旧缓存读取部分数据。
- 实际选渠道之后按折后金额准入；普通非信任请求真实预扣，符合原 `shouldTrust` 条件的请求免实际预扣、最终结算扣费。保留原代理客户/任务/订阅限制，不因来源变化扩展免预扣资格；覆盖钱包、订阅及受限 Token。
- 对比文本、图像、音频、Responses、WebSocket、Realtime、任务插件和 Midjourney 的估价、用量及结算入口，逐项登记接线，不能只在文本最终结算乘倍率。
- 换渠道重新匹配冻结规则；非信任请求需要增加预扣则先原子补扣，失败不发送，信任请求沿原旁路。低目标在原结算流程释放，未知上游结果保留既有恢复责任。
- 对旧组织倍率与新实时倍率分别标注来源，禁止新用户和组织倍率相乘、重复进 `OtherRatios`，不取消旧配置或重算表达式。
- 新消费倍率计算支持到 5，不能直接套用现有 `PersonalQuota` 的上限 2 校验。计费入口按快照版本区分新规则与旧事实，复用 quota 安全转换和累计目标舍入，不把新范围放宽到代理采购配置或旧协议中。

### W3：任务、退款、审计与历史兼容

- 扩展请求/任务快照版本，持久化实际渠道、选中倍率、来源、规则版本及必要基数；新配置或成员变动只影响新请求。
- 任务提交、最终成功/失败、预扣等于结算、折后舍入零、迟到结果及崩溃恢复沿原持久事务/journal 完成；不新增第二套资金写入链路。
- 退款按原倍率及累计目标计算，覆盖钱包、订阅及 Token，一次或重复恢复都精确守恒。
- 旧任务按旧快照处理；旧用户配置和历史不在启动时被静默重价。日志记录生效来源/版本并保持现有 admin/root 分区和客户脱敏边界；代理采购和消费金额分开验证。

### W4：共用实时折扣编辑器

- 新增专用业务组件实现一模型一行、一个倍率、多选渠道，用户和组织入口共用；不将组织编辑塞入旧渠道折扣组件。
- 复用 `MultiSelect`、模型选择器、表格、Dialog、ConfirmDialog、状态组件和格式化工具；全选与已选摘要采用组合。
- 提供来源生效预览、原价与继承区别、删除提示、静态全选、失效渠道、保存冲突、未保存退出及主体切换隔离。
- 用户页预览用户草稿及其组织继承；组织页默认预览明确标注“无个人覆盖”，可由 Root 选择一个当前成员查看其个人覆盖后的结果。携带预览上下文/版本和时间，草稿、成员或后台版本变化时刷新；预览不是未来请求价格承诺。
- 普通最终用户只显示获准的倍率/来源，不借预览扩大渠道可见权限。新文案仅更新 en/zh，加载 i18n 技能后实施翻译。

### W5：回归与发布验收

| 回归范围 | 必须保护的行为 |
|---|---|
| 规则/继承 | 用户命中、组织命中、系统 1、用户覆盖其他渠道、显式 1、移除渠道/删除、同模型重复倍率被拒绝；0.01/1/5 允许，0/负数/超过 5/超两位小数拒绝 |
| 配置并发 | 两人改不同模型后提交者 409；删除全部/重建总版本不回退；事务失败无部分写入；保存响应是本次版本 |

| 路由/重试 | 折扣范围不限制路由；自动分组、指定/亲和渠道、缓存/数据库选择一致；跨来源重试补扣不足不发送 |

| 工作包 | 实现与边界 |
|---|---|
| W0 / 迁移 | 数据库统一 `legacy → frozen → active` 状态；Root 显式冻结、校验并启用。旧同模型多倍率或精度/范围冲突返回用户、模型、渠道、倍率与原因，保持冻结，不静默选值或舍入。冻结阶段允许恢复旧配置；启用后不支持回退旧二进制。 |
| W1 / 存储与管理 | 新增专用规则、配置头、历史和迁移状态表；主体/模型哈希键唯一，一个倍率配多个渠道。整份保存带总版本 CAS；删除最后一条规则后版本仍递增。组织配置、候选、历史、成员和预览均仅 Root；用户权限沿原边界，代理只管理自己的客户。 |
| W2 / 计价 | 同一主库一致性事务读取用户、组织关系、双方规则和旧组织基础因素；按实际渠道使用用户、组织、系统优先级。显式 1 保留，规则不增加路由限制。新消费版本允许 `(0,5]`、最多两位小数，采购及旧快照仍按旧校验解释。 |
| W2 / 资金 | 非信任请求按折后金额预扣，原信任旁路保持；跨渠道重试按冻结事实选择来源，需要增加额度时原子补扣，失败不进入后续发送。原订阅至少 1 个 quota 的来源固定预留保持，最终舍入零时释放，不扩展信任资格。额度不足提示使用实际所需金额。 |
| W3 / 结算 | 沿用原账本和持久 journal，扩展来源、规则版本、计价版本和组织 ID；支持任务成功/失败、迟到恢复、零费用及幂等退款。日志来源进入原公开字段白名单，未新增第二条资金写入链。旧任务 JSON 未新增必填字段。 |
| W4 / UI | 用户与组织共用按模型编辑器，模型唯一、渠道多选、搜索全选、失效渠道保留/移除、显式原价说明、删除确认、409 草稿保留、退出保护和版本历史。组织默认预览无个人覆盖，可选择当前成员；显示预览版本与时间。桌面表格、移动卡片均已实查。 |
| W4 / 原入口 | 启用后旧消费倍率编辑隐藏；代理客户授权仍可独立编辑，旧接口只接受保留原倍率的授权变更，新授权行只接受中性倍率 1。代理采购入口和旧组织渠道因素保持。组织切换页签保留未保存草稿。 |
