# 代理与客户开户错误提示修复方案

## 问题与目标

平台管理员创建代理、代理创建客户以及开户后发送账号邮件时，界面应告知操作者可以修正的具体原因和已完成的步骤。开户后邮件投递失败时，保留已创建账号和待设密状态，支持恢复后重发。

## 当前实际情况

- 用户名和邮箱占用已有独立错误码。服务器对其他字段校验失败统一返回参数错误。开户和发信使用不同的邮箱校验，符合格式的邮箱仍可能在发信时被平台规则拒绝。
- 客户开户后的自动发信提示覆盖邮箱策略、冷却等服务端原因。现有缺配置提示仅覆盖管理员代理开户时的空 SMTP 主机。
- 手动重发时先提交待激活邮箱更正并作废旧链接，再发信。发送失败响应没有标明邮箱已更新。当前的重发状态提示共用了链接过期文案。
- 权限不足、代理未完成激活和代理已停用共用提示。重发目标不存在或不在操作者的管理范围内时共用 404，防止泄露账号归属。

## 优化方案

1. 开户由后端按字段返回稳定错误标识，覆盖用户名、邮箱、显示名称、手机号与备注。邮箱格式和平台邮件规则在创建前校验。前端复用现有表单错误和焦点处理，保留用户名和邮箱冲突原有错误码。
2. 授权后的开户和重发请求区分当前操作者的未激活、停用和权限不足，以及目标账号无法继续开户、邮箱需要修改和一分钟重发冷却。邮件配置缺失、配置不可用、连接失败、认证失败与投递被拒按已知原因分类。平台管理员获得可操作的诊断，代理端使用适合自身权限的文案。未知投递故障使用通用提示。
3. 重发接口在更正已提交而发信失败时明确标记部分成功。页面展示发信失败原因和邮箱已更新状态，并刷新列表或详情。客户开户后的自动发信通知同时显示账号创建成功和服务端发信原因。
4. 权限和账号归属由服务端验证。链接仍按原规则过期、单次使用并在邮箱更正或发信失败后失效。响应和审计只使用固定诊断标识，避免收件地址、链接、凭据和服务商原文进入错误内容。参照 [OWASP ASVS 5.0.0 §16.5.1](https://github.com/OWASP/ASVS/blob/master/5.0/en/0x25-V16-Security-Logging-and-Error-Handling.md#v165-error-handling)、[认证指南](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html#authentication-and-error-messages)与[密码恢复指南](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)。

## 评审跟进

- 更正后重发绑定本次提交的规范化邮箱。创建发信流程和确认投递时都检查当前地址。地址变化返回现有冲突码，更正事务会同时作废可使用和待确认的旧链接。
- 新签发的链接使用待投递用途。邮件服务确认接收后，服务端才将其切换到可激活用途。失败后的清理写入即使失败，该链接也无法用于激活。原有可激活链接沿用既有有效期和单次使用规则。
- 邮箱更正和发信失败分别记审计。失败审计记录操作者、目标账号、失败状态和固定码。创建接口默认自动发信失败时保持创建成功响应，并在 `data.activation_mail_error` 提供 `code`、`message` 和 `message_key`。
- Resend 区分密钥缺失和解密失败。对服务商明确标记的密钥停用、挂起或权限错误，使用认证失败诊断。仅解析允许的错误类型，日志和响应使用固定诊断。
- 开户表单从服务端读取冲突字段和消息键。更正弹窗在发信等待期间保持邮箱只读并可聚焦，收到字段错误后焦点可回到邮箱。
- 评审回归覆盖发信失败且清理写入失败、投递确认前邮箱被另一操作更正、部分成功的双审计、默认自动发信诊断、Resend 403 与解密失败、拒绝更正后的焦点。SQLite 3.50.4、MySQL 5.7.44 和 PostgreSQL 18.4 均通过，开户回归使用独立日志库。

  ```sh
  done
  ```

  MySQL 和 PostgreSQL 的本地测试连接分别通过 `TEST_MYSQL_DSN` 和 `TEST_POSTGRES_DSN` 提供。
