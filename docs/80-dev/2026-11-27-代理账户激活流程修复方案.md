# 代理账户激活流程修复方案

## 问题与目标

平台管理员创建代理后，收件人通过一封用途明确的激活邮件进入开户流程。代理在一次连续操作内自行设置密码、验证邮箱并绑定 TOTP 认证器。设置密码后直接进入绑定步骤，无需再次输入密码或先去登录。管理员启用仍是正常登录的独立条件。

## 当前实际情况

以下为修复前基线。

- 创建和重发均签发有效期为 10 分钟的激活链接，指向 `/account-activation`。代理账户邮件复用「安全设置」文案，并额外插入一个指向 `/sign-in` 的「登录」链接。[邮件实现](../../service/security_link_email.go#L25)
- 提交密码后，服务端验证收件邮箱、保存密码并将代理标记为 `security_pending`，前端随即跳转到登录页。现有 TOTP 绑定依赖登录会话。新代理默认未由管理员启用，无法通过正常登录进入绑定步骤。[密码提交](../../model/security_completion.go#L242) · [页面跳转](../../web/src/features/security-completion/activation.tsx#L80) · [开户默认状态](../../model/reseller.go#L203) · [登录门禁](../../model/reseller_boundary.go#L98)
- 现有邮件集成测试覆盖创建、重发、语言与有效期，并把「继续安全设置」作为预期。现有 MFA 回归覆盖绑定状态与激活状态的事务一致性。这些测试可用作变更前的基线。[邮件回归](../../controller/user_manage_test.go#L688) · [激活事务回归](../../controller/security_enrollment_test.go#L2283)

## 优化方案

### 代理激活邮件

平台管理员创建代理后自动发信，以及管理员手动重发代理激活邮件，统一使用代理开户文案。邮件保留用户名、有效期和防转发提示，正文只提供一个「激活账户」入口。具体操作由激活页面逐步引导。

> **激活您的代理账户**
>
> 用户名：yangjie02
>
> 请点击下方按钮激活您的代理账户。此链接将在 10 分钟后失效。
>
> **激活账户**
>
> 此链接仅供本人使用，请勿转发。

### 连续激活

1. 点击邮件链接打开「激活代理账户」页面。链接使用随机、一次性的激活令牌，与账户及用途绑定。密码由用户在页面首次设置，与邮件链接及其令牌无关。打开页面或由邮件扫描器预览链接时，账户状态不变。
2. 提交密码后，服务端在同一事务内消费激活令牌、验证邮箱、保存密码哈希、推进至 `security_pending` 并签发短时的首次 MFA 绑定凭据。页面直接显示认证器绑定步骤，提交有效的 TOTP 验证码后再显示结果。正常完成激活只需在设密步骤输入密码。
3. 绑定凭据绑定代理账户、当前邮箱、认证版本和首次绑定用途。服务端只接受它用于发起与确认本次 TOTP 绑定。复用现有验证码校验、密钥与恢复码存储及重放防护。成功确认时，在同一事务内消费绑定凭据、启用 MFA 并将代理推进至 `active`。该凭据不能换取普通登录会话、调用业务接口或变更已有 MFA。
4. 激活完成后，结果页根据管理员启用状态显示「账户已激活」或「账户已激活，等待管理员启用」。正常登录继续检查管理员启用和账户安全状态。平台停用、邮箱变更或认证版本变化时，服务端拒绝继续使用旧凭据。
5. 激活链接在设密后即失效。如果页面刷新或用户离开，允许在同一浏览器内凭仍有效的绑定凭据继续。若凭据已过期或丢失，提供专门的续办入口，核验当前邮箱及已设置的密码后再签发凭据。该例外路径不重置密码，不复用已消费的激活链接，也不要求管理员先启用账户。

本次覆盖平台管理员创建的代理账户及其首次激活。代理创建的客户继续按现有启用和 MFA 策略处理。密码恢复、安全邮箱验证和已有 MFA 的替换流程继续使用各自的入口。

### 服务端约束

- 激活令牌和绑定凭据短时有效，成功消费与状态变更原子提交。旧邮件链接在重发或更正邮箱后失效。错误验证码可在凭据有效期及限速范围内重试。并发提交只能成功完成一次。
- 对激活、续办与绑定操作实施限速和通用失败响应。审计记录账户、事件和结果，排除可用令牌、密码、认证器密钥、验证码和恢复码。凭据通过 HTTPS 传输，避免进入日志和 URL 查询参数。
- 参考 OWASP ASVS 5.0.0 的 7.2.1、7.2.4 和 7.4.2，分别核对服务端验证、正常认证的会话签发与失效，以及账户停用后的失效行为。一次性邮件令牌与 TOTP 校验参考相应指南。[ASVS 5.0.0 会话管理](https://github.com/OWASP/ASVS/blob/v5.0.0/5.0/en/0x16-V7-Session-Management.md) · [认证指南](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html) · [密码恢复指南](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html) · [MFA 指南](https://cheatsheetseries.owasp.org/cheatsheets/Multifactor_Authentication_Cheat_Sheet.html)

## 验证门槛

- 邮件回归覆盖创建与重发的中英文文案，核对唯一的激活入口、10 分钟有效期及旧链接失效。邮件正文不出现「登录」链接或通用「安全设置」标题。
- 浏览器走查覆盖管理员尚未启用、已启用两种情况。用户点击链接后直接设密并完成 TOTP 绑定，中途无登录跳转或再次输入密码。核对等待启用提示、绑定中断后的续办和完成后的正常登录。
- 接口回归覆盖错误验证码、链接与凭据的过期和重放、跨账户或用途使用、邮箱更正、平台停用、已有 MFA、并发确认和事务回滚。验证激活凭据无法访问后台、签发正常会话或绕过启用条件，并确认审计内容不含凭据。
- 按项目要求在真实 SQLite、MySQL 和 PostgreSQL 上验证涉及事务与持久化的改动，记录引擎版本、命令和结果。

### 评审修订

- 每次绑定使用独立的短时 Cookie。标签页只保留公开流程编号，服务端同时验证编号、凭据、代理账户、邮箱和认证版本。普通安全链接刷新时继续显示通用失效提示。成功页复用设密后登录参数，已有浏览器会话时仍可打开登录表单。
- 公网激活和续办要求 HTTPS，仅本机回环保留开发用 HTTP。反向代理终止 TLS 时，`ServerAddress` 应为 HTTPS 公网地址，设置 `SESSION_COOKIE_SECURE=true` 并将该地址列入 `SESSION_COOKIE_TRUSTED_URL`。`TRUSTED_PROXIES` 应包含实际终止代理，代理必须覆盖 `X-Forwarded-Proto`。
- 激活和续办先锁用户再操作流程记录，与人工恢复一致。续办重发作废上一枚链接。已确认目标账户时，续办密码验证失败记录脱敏审计事件。新增回归覆盖错码和错密码耗尽、已有 MFA、流程编号错配，以及确认绑定与人工恢复并发。

### 使用 ./start.sh 的本地实际验收

使用 `./start.sh` 直接启动前端 `http://localhost:3201` 和后端 `http://localhost:3200`，连接现有本地 PostgreSQL。通过实际 Chromium、网关 API 和回环 SMTP 完成 **9/9** 项验收。

- 前端和后端均可访问，临时管理员通过正常 MFA 登录。
- 两封邀请邮件均只有一个激活链接，正文无登录链接。代理设密后直接进入 TOTP 绑定。同一浏览器并行激活两个代理时，刷新后仍回到各自的绑定流程。
- 管理员启用前可完成 TOTP 绑定并看到待启用提示。启用后，代理可用刚绑定的 MFA 登录并访问客户工作区。绑定凭据丢失后，通过实际续办邮件和已设置的密码完成激活。
- 客户请求未授权测试模型时，实际网关返回 `503 pricing_channel_unavailable`，本地测试上游收到 0 次请求。

实际运行发现并修复了两个问题。

1. **开发代理端口改写导致激活返回 403。** 前端代理将请求的 `Host` 改为后端端口，旧校验因此误拒绝来自前端端口的合法请求。回环 HTTP 现在校验浏览器来源与配置的公开地址一致，同时要求请求的目标主机与连接对端均为回环。注册路由回归覆盖跨端口开发代理通过、其他来源与公网对端被拒。[传输校验](../../middleware/agent_activation.go#L33) · [路由回归](../../router/agent_activation_test.go#L40)
2. **React Strict Mode 复用已取消的 MFA 请求。** 首次挂载发起的请求被取消后，重新挂载时共用 GET 去重返回了已取消的请求，绑定对话框无法打开。MFA 材料请求使用独立的取消周期，跳过共用 GET 去重。Strict Mode 回归和实际浏览器设密后的绑定流程均通过。[MFA 请求](../../web/src/features/security-completion/agent-activation.tsx#L163) · [前端回归](../../web/src/features/security-completion/__tests__/enrollment.test.tsx#L242)

修复后，`go test ./router ./controller -run '^Test(AgentActivationTransportOnRegisteredRoutes|AgentActivationKeepsMFAInsideOnboarding)$' -count=1` 通过，激活页面测试通过 13 项，TypeScript、lint 和格式检查通过。验收期间临时使用回环 SMTP，并为同一 IP 下的多账户测试提高限流阈值。验收后恢复原邮件配置和默认限流，停用临时管理员、测试 API Key 和测试渠道，再次以默认参数执行 `./start.sh`，前后端均通过可用性检查。
