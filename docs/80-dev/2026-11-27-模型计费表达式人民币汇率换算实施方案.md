# 模型计费表达式人民币汇率换算实施方案

## 问题与目标

所有模型统一以美元计价和结算。上游以美元报价时，管理员直接在表达式里填美元单价。上游以人民币报价时，管理员在表达式里保留人民币原价，引用后台统一配置的人民币兑美元换算规则。人民币报价需要覆盖按 token 和按次两种计费方式。

汇率调整后，引用汇率的表达式从新请求开始按新汇率计算。已经开始预扣的请求沿用本次请求锁定的汇率，保证预扣、重试和结算口径一致。这里的“国内模型”和“国外模型”描述常见的上游报价场景，由管理员按实际报价币种显式编写表达式。

## 当前实际情况

- 系统已有 `USDExchangeRate` 配置，含义为 `1 USD = X CNY`，站点货币支持人民币金额展示。早期可视化定价支持将人民币输入换算为美元常量。当前模型定价编辑器已撤销 CNY 输入，人民币原价由 v2 表达式保存。先前保存的美元常量仍按原美元值计费。见[汇率配置](../../setting/operation_setting/payment_setting_old.go)和[金额输入换算](../../web/src/features/model-pricing/pricing-amount-input.tsx)。
- 计费表达式当前没有可引用的汇率函数。普通 token 系数以 USD／百万 token 为单位，`fixed(amount)` 的参数以 USD／次为单位。固定价校验要求金额为有限、非负的数字字面量，并校验表达式内部缩放后的值。见[表达式规范](../../pkg/billingexpr/expr.md)、[编译环境](../../pkg/billingexpr/compile.go)和[固定价格校验](../../pkg/billingexpr/fixed.go)。
- 预扣快照已保存表达式及其哈希、额度换算基准等信息，结算时重新求值。图片补扣和任务用量也有直接运行表达式的入口，需要和通用结算一起核对。现有 task usage 入口和 Realtime 入口限制使用 `fixed()`。见[计费快照](../../pkg/billingexpr/types.go)、[通用结算](../../pkg/billingexpr/settle.go)、[图片计费](../../service/image_billing.go)和[任务提交计费](../../relay/relay_task.go)。
- 已接入金额快照的账务流水会在 `money_snapshot` 保存汇率、额度换算基准和人民币金额。现有分档计费日志还没有记录表达式实际使用的汇率。旧版令牌、组织账单会按查看或导出时的配置折算历史额度，存在汇率更新后重估旧账期的问题。见[金额快照写入](../../service/billing_money_snapshot.go)、[计费日志](../../service/log_info_generate.go)和[导出金额格式化](../../service/billing_export_amount.go)。

## 优化方案

### 表达式语法

在 `v2:` 表达式中增加 `cny_to_usd(amount)`。它将人民币金额除以本次计费锁定的汇率，返回美元金额。后台的 `USDExchangeRate` 是唯一汇率配置，含义为 `1 USD = X CNY`。表达式通过换算函数引用这项配置。调整该值还会影响 CNY 金额展示，以及使用当前汇率的 CNY 导出。CUSTOM 使用自己的展示汇率，计费函数始终引用 `USDExchangeRate`。人民币和美元价格可以在同一表达式内按各自报价方式书写。

```text
# 美元 token 单价，USD／百万 token
tier("base", p * 1.00 + c * 4.00)

# 人民币 token 原价，CNY／百万 token
v2:tier("base", p * cny_to_usd(7.30) + c * cny_to_usd(29.20))

# 美元按次单价，USD／次
tier("request", fixed(0.10))

# 人民币按次原价，CNY／次
v2:tier("request", fixed(cny_to_usd(0.73)))

# 人民币按张原价，CNY／张，继续使用现有图片数量因子
v2:tier("image", fixed(cny_to_usd(0.73))) * image_count
```

| 人民币原价 | 1 USD = 7.30 CNY | 1 USD = 8.00 CNY |
| --- | ---: | ---: |
| 输入 ¥7.30／百万 token | $1.00／百万 token | $0.9125／百万 token |
| 输出 ¥29.20／百万 token | $4.00／百万 token | $3.65／百万 token |
| 固定价 ¥0.73／次 | $0.10／次 | $0.09125／次 |

### 编译与校验

- 在 `pkg/billingexpr/` 内实现语法校验和求值。新增逻辑放在专用文件，由现有编译、固定价校验和运行入口接入。保存原始表达式，编译缓存按表达式复用，实际汇率随每次求值传入。
- `ParseExprVersion` 识别 v2，编译环境仅在 v2 注册换算函数。v1 和 v2 沿用各计费入口已有的美元单位和额度换算规则。新版解析器对未知版本返回明确错误，前端解析和回写保留 v2 前缀。
- `cny_to_usd()` 接受一个有限、非负的数字字面量，保留显式零价。编译阶段检查原始 AST，包括未选中或可能被优化掉的分支。运行阶段检查汇率为有限正数以及折算结果有限、非负。配置缺失、无效或换算溢出时返回明确错误，防止按错误价格预扣或发送上游。
- `fixed()` 同时接受原有美元字面量和 `fixed(cny_to_usd(人民币字面量))`。折算后的美元价仍须通过 `fixed()` 内部百万倍缩放的有限性校验。`fixed()` 继续受现有价格叶子、条件分支和数量倍率规则约束。trace 中的 `fixed_price` 保持为乘数量或其他倍率前的美元单价。
- 保存校验和模型价格预览使用同一个后端换算入口。预览以当前汇率为准，收费沿用原有的额度换算、分组倍率、舍入和饱和保护。在价格运算中保留原有精度，界面展示可以按现有规则格式化。

### 请求预扣与结算

- 首次执行引用汇率的表达式时，由宿主通过与配置更新同步的读取入口取得节点已生效的 `USDExchangeRate`，按现有配置规则校验并冻结在请求级状态。运行时函数通过求值输入取得该值。每个节点应用新配置后，后续开始计费的请求使用新值。
- 同一请求的预扣、渠道或分组重试使用同一个请求级汇率。异步任务换渠道时仍可重建每次尝试的表达式快照，请求级汇率随成功尝试持久化。图片数量重估、流式结算、任务重算和分段结算使用计费快照中的汇率。旧快照中的美元表达式继续按原逻辑执行。依赖汇率的表达式缺少快照值时按现有求值错误路径处理。
- 引用汇率的计费流水必须记录实际参与折算的汇率。复用 `money_snapshot.exchange_rate` 作为账单中的汇率字段，取值来自实际用于求值的计费快照。预扣、结算、退款和重放沿用同一值。继续记录已扣额度、匹配档位，按次价格保留美元单价。账单逐笔展示或导出历史汇率及金额时使用该记录的快照，跨汇率汇总先按各笔快照计算。无快照的历史记录在详情中标记为历史汇率不可用。导出明细保留按导出时显示配置产生的金额，历史汇率和历史 CNY 金额留空，且逐行标明主金额的来源。
- 按次表达式覆盖当前支持 `fixed()` 的 HTTP／SSE 计费入口。采用 task usage 表达式的异步任务按次报价可使用 `v2:tier("request", cny_to_usd(0.73))`，该入口的表达式直接返回美元。任务旧式按次价格字段和 Realtime 的 `fixed()` 支持沿用各自现有入口约束。

### 管理后台与兼容性

- 模型可视化定价在 CNY 展示模式下只提供美元录入，CUSTOM 录入保留。上游价格同步的汇率乘除仍按已有的独立批量调整操作执行。在原始表达式编辑器说明中提供 token 和按次的人民币示例。预览至少显示人民币原价、当前汇率及折算后的美元单价。无法无损转换的人民币任务定价保留原始表达式编辑，禁止切换为默认零价草稿。模型定价和供应商独立定价均展示后端折算预览。
- 已保存的美元价格、内置美元定价和旧版按次配置继续使用原有单位和规则。管理员可以显式把有人民币原价的模型改成引用汇率的表达式。先升级所有执行表达式的节点再保存 v2 定价。旧节点只识别 v1，解析 v2 时可能返回通用语法错误。

### 验证与完成条件

- 表达式回归覆盖 token 和按次人民币报价、原有美元写法、人民币和美元混写、显式零价、条件分档和按张数量。校验覆盖负数、动态参数、缺少汇率、零或非有限汇率，以及折算或固定价缩放溢出。
- 端到端核对两次汇率下的新请求。用同一请求跨越汇率更新验证预扣、重试、结算及日志能对账。补充图片数量变化、异步任务首次失败后换渠道重试、任务完成重算、旧快照和原有固定价限制的回归。
- 验证改汇率后重新查看或导出旧账单，逐笔记录的原汇率和历史金额保持一致。覆盖缺少快照的旧记录、同一账期多种汇率，以及 CUSTOM 模式下单独修改展示汇率。
- 验证后台预览与实际计费的 USD 结果一致，保存后重新打开保留人民币原价和函数，原有美元表达式与可视化输入可继续编辑。实施后记录实际运行的测试命令与结果。若实施改动涉及数据库行为，按仓库约定完成 SQLite、MySQL 和 PostgreSQL 实例验证。

### 实施结果

- v2 求值、请求级汇率快照、模型价格预览、历史明细展示及导出已实现。异步任务重试可重新选择渠道价格，成功尝试的计费快照和账务记录沿用请求首次锁定的人民币汇率。
- 令牌和组织账单的明细 CSV 包含历史汇率与 CNY 金额。组织完整账单 CSV 另列有快照记录的历史小计和缺失记录数。令牌汇总和组织用量快照累计已记录的历史金额并统计缺失记录。分组保留原始额度。组织用量按发布的代次导出，已有代次若没有历史汇总，需要重新生成用量快照。
- 已使用真实 SQLite 3.50.4、MySQL 5.7.44、PostgreSQL 18.4 验证定价配置写入、系统汇率更新、预览和组织历史账单读取。MySQL 与 PostgreSQL 定价矩阵使用 `TEST_MYSQL_DSN` 和 `TEST_POSTGRES_DSN`，组织矩阵另配置 `TEST_USAGE_{MYSQL,POSTGRES}_DSN` 及对应 `_LOG_DSN` 分离日志库。生产 schema 无变更。

### 复审修复

- 系统汇率复用现有事务选项写入入口。数据库失败时保留旧值，成功后再更新节点内存并触发同步。
- v1 按原作用域解析局部名称。v2 汇率依赖来自原始 AST 中的有效函数调用，保存校验、美元预览和求值在选档前都检查全部人民币价格。固定价应用相同的百万倍缩放边界。
- 消费和退款详情均使用历史金额组件。无快照时显示原始额度及历史汇率不可用。已存在的快照及日志 JSON 结构继续兼容，生产 schema 无变更。
- 验证包括实际选项写失败、跨汇率历史汇总和来源列、发布代次导出不随当前汇率改变、v1 局部名称、休眠档位固定价溢出、CUSTOM 输入回退及任务编辑模式保护。

三库复测使用 SQLite 3.50.4、MySQL 5.7.44、PostgreSQL 18.4。读写验证使用隔离数据库，组织验证使用分离的日志库。

```sh

go test -v ./model -run '^TestOrganizationUsageDatabaseMatrix/(sqlite|mysql|postgres)/(log_pages|published_totals)$' -count=1
go test ./controller -run '^TestOrganizationE2EUsageSnapshotScopesAndChannelProjection$' -count=1
```

上述三库矩阵与组织导出端到端测试通过。前端 45 个测试文件共 775 项通过，类型检查、改动文件 lint、i18n 同步和生产构建通过。定向 Go 用例和 `go vet ./pkg/billingexpr ./model ./controller ./service` 通过。全量 Go 回归排除工作区已知的代理激活路由权限覆盖测试后通过，执行命令为 `go test ./... -skip '^TestAccessTokenRouteRulesCoverEveryDashboardRoute$'`。
