# 渠道诊断成本归账与组织历史金额切片实施方案

## 问题与目标

- 渠道诊断会真实调用上游，可能发生采购费用。费用归平台运营，由管理员账单管理。发起人用于审计。渠道诊断不扣用户钱包、订阅额度或组织额度，客户账单与组织用量均按客户请求统计。
- 组织账期的历史人民币金额来自计费当时保存的快照。同一批计费事实下，调整系统汇率不改变历史汇总。已经覆盖的组织用量切片在切换成员、模型或渠道后，可以直接用于历史金额汇总。
- 保留无快照明细的现行导出决定。金额按导出时的显示配置折算，并明确标注来源。历史汇率和历史人民币金额留空，该展示金额不计入历史汇总。

## 当前实际情况

- 渠道测试会请求真实上游。成功路径调用 `RecordConsumeLog`，记录 `Model test`、token 用量与按网关模型价格算出的诊断额度。手动单测使用发起人的用户 ID，定时检测和手动批量检测共用任务入口，使用 root 用户作为测试上下文。部分上游调用后的失败路径在写消费日志前返回。见[渠道测试与结算](../../controller/channel-test.go#L480)和[批量与定时检测](../../controller/channel-test.go#L1139)。
- 客户对账、组织用量和组织结算各自读取消费日志。由于诊断目前也写成普通消费，发起人若处在组织计费窗口内，组织的请求数、额度或账单来源统计也可能包含这类诊断。管理端现有「上游」视角展示按渠道统计的用量。该页面没有通用的供应商扣款依据。见[令牌账单筛选](../../model/token_bill.go#L162)、[组织用量扫描](../../model/organization_usage_bucket_scan.go#L51)、[组织账单钱包来源汇总](../../model/organization_invoice_wallet_aggregate.go#L52)和[对账视角说明](../../web/src/features/reconciliation/index.tsx#L180)。
- 组织用量按时间切片保存额度、请求数和 token 数，切片聚合行按用户、模型、渠道和日志类型区分。历史金额在组装快照时，根据覆盖切片再次读取原始日志的 `other`。因此已经覆盖的区间仍可能在新筛选或新一代生成时重复扫描。额度查询和金额扫描分开执行，记录数相同也无法单独证明两者使用了完全相同的一批日志。历史金额读取失败时，该次组织用量仍可发布，历史金额标为不可用。见[切片结构](../../model/organization_usage_stats.go#L136)、[历史金额读取](../../model/historical_bill_totals.go#L55)和[组织快照组装](../../model/organization_usage_rollup.go#L253)。
- 已有汇率方案实测覆盖汇率写入失败、新请求按新汇率、已存历史净额保持不变，以及无快照导出的金额来源。新工作沿用这些账务结果。见[原方案实机复验](../99-archive/2026/11/2026-11-27-模型计费表达式人民币汇率换算实施方案.md#实机复验)。

## 优化方案

### 工作包一：渠道诊断成本归管理员账单

#### 记录与归属

1. 在现有日志体系新增明确的渠道诊断类型，复用管理端对账页面，新增「渠道诊断成本」视角。平台是费用归属方。手动单测、手动批量保存实际操作者，定时巡检和自动恢复保存系统任务标识。批量记录保留任务与单次尝试的关联。
2. 在实际派发边界建立尝试记录。每次向上游发起真实调用生成唯一尝试 ID，保存发生时间、触发方式、渠道、实际发送的上游模型、端点、网关与上游请求 ID、可取得的实际用量和请求结果。本地校验失败且未派发的记录留在诊断侧。派发后超时、取消、断流和响应解析失败仍保留可核对记录，缺少金额依据时标为待确认。
3. 记录写入和状态补全以同一尝试 ID 幂等处理。重试写入失败的诊断记录时，只补日志。新的真实派发使用新的尝试 ID。诊断成本记录独立于客户消费日志开关，写入失败要可告警和追踪。
4. 客户明细、汇总、分组、CSV、用量统计和组织结算共用诊断排除口径。诊断日志仅在具备相应管理权限的视角可查。保留当前测试成功判定和渠道健康状态处理。

#### 金额与来源

| 来源 | 入账状态 | 金额依据 |
| --- | --- | --- |
| 供应商账单或可核对的扣款记录 | 已对账 | 保存原币实付金额、币种及凭证引用 |
| 上游响应明确报告费用及币种 | 上游报告 | 保存上游金额、币种及关联请求 ID，后续可与供应商账单核对 |
| 有独立采购价及足够的实际用量 | 估算 | 按渠道实际采购价计算，记录使用的价格版本和计量依据 |
| 缺少足够证据 | 待确认 | 金额留空，计入待确认笔数 |

- 网关按客户模型价格计算的诊断额度保留为排查信息。采购成本使用供应商证据或独立采购价。采购价估算支持按次和按 token，采用上游实际计量单位，不应用客户分组倍率。显式零成本需要明确的免费或零扣款依据。
- 入账数据保存原币金额和币种。统一美元展示时，保存入账所用的汇率、来源和美元折算值。汇率配置变化后沿用已保存的折算结果。多币种记录缺少可靠换算依据时，仍可按原币统计。
- 管理端汇总及 CSV 展示成本金额、原币、来源、状态和待确认笔数，支持按渠道、上游模型、触发方式和来源筛选。同一尝试从估算或上游报告升级为已对账后，汇总按最新有效依据计一次。已有供应商账单凭证的更正应保留审计记录。
- 首批接入覆盖诊断归账、经核验可直接读取的上游费用及待确认状态。供应商费用字段按实际支持的渠道接入。独立采购价估算和额外的供应商账单接入按下一阶段实施。当前没有通用渠道成本字段可直接视为实付金额。

#### 历史诊断记录迁移

1. 抽样核对旧版写入特征。确认消费类型、`TokenId=0`、`TokenName="Model test"` 和诊断内容标记同时匹配的记录。分类规则集中实现并供所有账单与用量读路径复用。证据不足的记录在迁移核验中单独列出。
2. 已确认的旧诊断记录在管理员账单标为「历史诊断，成本待确认」，原有诊断额度只作排查。客户与组织的查询不再计入这些记录。上线前先输出影响笔数、用户和账期范围，迁移支持幂等重跑。
3. 仅失效受影响的组织切片，按新口径重新生成并发布新代次。旧组织用量在新代次完成前按现有机制保留并标注状态。已出具账单保留原件，需要更正时走账单更正流程。

### 工作包二：组织历史金额随用量切片保存

1. **扩展现有切片聚合行。** 按现有用户、模型、渠道和日志类型维度保存历史人民币小计、有快照笔数和缺快照笔数。金额读取日志中已有的快照并用精确十进制累加。保留组织用量当前的消费统计口径，令牌对账继续处理其已有的退款口径。
2. **在创建或重建切片时计算金额。** 保留现有额度 SQL 聚合。对未计算历史金额的切片，在同一次构建中按相同成员窗口、半开时间范围和诊断排除口径，分批读取用量键和快照字段。两个阶段使用同一来源版本和待投递检查。持久化前核对聚合行的覆盖和笔数，发现来源变化时重试切片。额度和金额随同一切片版本提交，避免组合不同版本的数据。
3. **筛选和汇总复用聚合行。** 组装组织快照时，对精确覆盖的切片应用同一成员、模型、渠道过滤，再从聚合行汇总金额与覆盖笔数。移除组装快照时逐切片回读原始日志的路径。组织汇总导出继续读取所选已发布代次，明细导出继续使用逐笔金额来源。
4. **区分覆盖状态。** 成功读取且确实没有快照的记录计入缺快照数。尚未补算的旧切片显示待补算。日志已清理且无法完成重建的范围显示无法恢复，保留可用的原用量和已有发布结果。金额只覆盖部分切片时，显式显示覆盖范围或笔数。使用空值或明确状态表达未核实金额，避免与已核实的零金额混淆。
5. **增量补算和失效。** 旧切片按现有后台构建预算分批、可重试地补算。迟到日志、成员计费窗口变化和诊断重分类复用来源版本及切片失效机制。保持日志保留期之外的既有用量可读。首阶段聚合到现有切片，无需给全量日志加金额列或全库回填。

### 切换顺序

先上线诊断分类、管理端归账和客户侧排除，核对确认的旧诊断影响范围。再发布金额切片结构和增量补算，使历史切片使用修正后的记录集合。切换前后保留未完成代次的可读状态。部署涉及持久字段时，按兼容部署顺序滚动升级，旧数据在新代码中可读，历史金额字段尚未计算时保留明确状态。

### 验证与完成条件

| 方面 | 必须验证的行为 |
| --- | --- |
| 诊断归属 | 手动单测、手动批量、定时和恢复均进入管理员账单。组织成员发起诊断时，钱包余额、订阅和组织可用额度保持原值，客户账单和缺快照计数均无变化。 |
| 派发与幂等 | 区分未派发、真实成功、派发后超时和重复落库。写入重试不会再次调用上游。新一次真实尝试可以单独对账。 |
| 真实上游 | 用支持费用凭证的真实渠道核对金额、币种和请求 ID，用只有用量回执的真实渠道验证待确认状态。验证按次或 token 采购价估算以及同一笔升级凭证后的去重。 |
| 历史一致性 | 覆盖同一账期多种汇率、缺快照、诊断混合记录、乱序到达、组织计费窗口变化、待补算旧切片和已清理日志。调整汇率后，同一批事实的历史汇总与有快照明细保持一致。无快照明细仍标注按导出时配置折算。 |
| 数据库与升级 | 在真实 SQLite、MySQL 和 PostgreSQL 及分离日志库验证迁移、首建、重建与导出。涉及 schema 时，覆盖新建库和旧版本样本升级，至少运行两次迁移并验证已有数据与约束。记录实际版本、命令和结果。 |
| 性能 | 分别测首次生成、增量补算和复用切片。已覆盖账期切换成员、模型或渠道筛选时，历史金额汇总访问原始日志表的次数为 **0**。首次补算记录扫描行数、耗时和超时重试结果，确认能在现有后台预算内分批完成。 |

## 状态跟踪

- 已确认的业务决定是将渠道诊断的上游成本归入平台管理员账单，以及保留无快照明细按导出时配置折算的行为。
- 旧诊断记录分类命中范围、首批支持的上游费用依据和大账期性能均待实施验证。本方案的测试矩阵和完成门槛属于计划。
