# 80-dev — 目标说明

## 目标

作为当前实施和问题处置的增量工作区，记录可执行方案、实际基线、验证证据和待收敛事项。

## 放什么

- 当日或当次实施方案；
- 已核对的当前代码事实与缺口；
- 按工作包拆分的优化方案、验证命令和完成门槛。

## 不放什么

- 长期产品口径 -> `10-product/`；
- 长期架构合同 -> `20-architecture/`；
- 一次性聊天、无当前价值的尝试过程或无证据推测；
- 未经授权的 `60-marketing/`、`70-research/` 或 `99-archive/` 内容。

## 命名格式

除本 README 外，文件必须使用无空格的 `YYYY-MM-DD-中文主题.md`，例如 `2026-08-08-Token对账中心实施方案.md`。

## 内容格式

文档至少包含“问题与目标 / 当前实际情况 / 优化方案”，frontmatter 至少包含 `status / owner`。验证结果与待同步到事实目录的结论写入优化方案或状态跟踪。

## 编写要求

- 已验证事实、已接受决策、未完成项和待确认假设必须明确分开。
- 实施状态只能在有代码、测试或运行证据时更新；文件存在不等于已验证。
- 每日检查当天增量，每周检查最近 7 天和更早未收敛文档；已验证产品、架构、工程或运维结论收敛到对应当前事实目录。
- 只列出已完全收敛文档的归档候选；未获用户明确授权不移动到 `99-archive/`。
