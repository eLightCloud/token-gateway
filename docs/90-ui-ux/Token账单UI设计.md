# Token 账单 UI 设计

## 页面目标与边界

`/reconciliation` 是仅 Root 可见的只读 Token 账单工作台。页面从现有数据库账单事实生成总览、分组和明细，供管理员在系统外人工核对。

页面必须明确告知“本页面只读，不会连接上游服务商”，不展示数据源、凭据、同步、采集健康、成本、差异处置、关账或快照等自动对账暗示。

## 信息架构

桌面端按以下固定顺序排列：

1. 标题“Token 账单”与说明“基于数据库账单事实进行人工核对”；
2. 本月、上月、自定义账期与起止日期；
3. 唯一主操作“导出当前账单”；
4. 客户账单、渠道用量、按上游三个一级视角；
5. 当前视角的筛选条件；
6. 额度、记录数、输入 Token、输出 Token 和 Token 合计；
7. 服务端分页的分组汇总表；
8. 点击汇总行后打开的右侧明细抽屉。

首屏不常驻原始明细，不在前端对当前明细页求全局合计。移动端保持相同阅读顺序，控件换行，表格和抽屉内明细可横向滚动。

## 视角与分组

- 客户账单：支持按客户、客户 × 模型、客户 × 渠道分组，并显示消费、退款与净额。
- 渠道用量：只统计消费事实，支持按渠道、渠道 × 模型分组。
- 按上游：只统计消费事实，支持“当前 API 地址 × 渠道”和“上游 × 模型”。同地址的不同渠道始终分行；模型视图继续保留地址、渠道、模型三重上下文。

明细抽屉必须显示当前复合主体的完整上下文，再加载交集范围内的原始账单记录。按上游一级行先展示当前渠道的模型汇总，再进入明细。

## 筛选、URL 与加载

筛选支持时间、账单类型（仅客户视角）、组织、模型、渠道和 Request ID。视角、维度、筛选和汇总页码进入 URL，确保刷新和分享后可复现；明细只在抽屉打开后请求。

`summary` 与 `groups` 可并行加载。必须提供加载、空数据、错误和分页状态；没有账单时显示空状态，不显示“已对平”。`LogConsumeEnabled` 当前关闭时显示阻断级“账单可能不完整”警告。

## 权限、导出与安全

- 侧边栏入口仅对 `ROLE.SUPER_ADMIN` 展示，后端所有端点使用 Root 权限。
- CSV 导出复用当前视角和筛选，不创建导出任务、artifact 或快照。
- 页面和 CSV 不展示/输出密钥、IP、`Log.Other` 原始对象、提示词、请求正文或响应正文。
