# 用户与组织实时模型折扣 UI 设计

## 状态与边界

本文是待实施的界面合同，不代表已有页面。业务规则唯一见 [产品设计](../10-product/用户与组织实时模型折扣产品设计.md)，数据和请求行为见 [架构设计](../20-architecture/用户与组织实时模型折扣架构设计.md)，实施与验证见 [实施方案](../80-dev/2026-11-05-用户与组织实时模型折扣实施方案.md)。

## 信息架构与入口

- 用户管理保留个人倍率入口，改用按模型聚合的实时折扣编辑区；代理客户仍使用所属代理的现有管理入口，不扩大平台管理员权限。
- 组织详情新增“实时计费折扣”区域，独立于现有组织渠道折扣及 Invoice 结算系数；不改名覆盖旧功能。新区域显示“用于请求预扣和最终结算；用户覆盖优先”。
- 组织实时配置、候选、历史和默认折扣预览仅平台 Root；普通 Admin、组织管理员及成员不获得管理入口。用户倍率的原有管理权限不变，组织配置权不允许越过代理客户管理边界。
- 沿用现有侧栏、布局、主题和移动端模式，不新增独立站点或改动主页。

## 模型规则列表

一模型一行，不展开为多条渠道价格行。列表使用搜索模型、添加模型、修改历史及批量草稿保存动作；一次保存仅限当前用户或组织。

| 列 | 展示与行为 |
|---|---|
| 模型 | 精确对外计费模型名，可复制或查看完整名称 |
| 适用渠道 | 前两个渠道名称与 ID，更多显示“另 N 个”；可展开查看状态及完整范围 |
| 计费倍率 | 如 `0.8× · 八折`、`1× · 原价`、`1.5× · 加价 50%` |
| 生效状态 | 显示渠道可用性。个人规则另显示启用开关，停用保留倍率和渠道，保存后恢复继承 |
| 操作 | 编辑；用户为“删除并恢复继承”，组织为“删除并恢复系统默认” |

添加模型时，已存在模型显示“已配置”并提供进入编辑的动作，不能添加第二条。没有适用规则或个人规则已停用时继承。启用规则的倍率 1 是显式原价。

## 编辑交互

使用项目 Dialog；列表中的“添加模型”和“编辑”打开同一种表单，字段按顺序呈现：

1. **模型**：可搜索单选。编辑已有规则时固定模型，避免切换模型后遗留错误渠道。
2. **适用渠道**：模型选定后加载候选，支持搜索名称/ID、多选、已选数量、全选当前可选项及清空。搜索时全选按钮明确标为“全选搜索结果”，保留范围外已选项；清空全部只修改草稿，零渠道不可提交。
3. **计费倍率**：只提供一个输入框，用户与组织均为大于 0、至多 5、最多两位小数；实时显示百分比和折扣/加价含义，渠道项内不提供倍率输入。1 明确说明“在所选渠道按原价”；用户模式补充“覆盖组织折扣”。校验错误紧邻字段，不静默补成 1 或舍入超精度输入。
4. **生效预览**：按下文对应的用户/组织上下文展示草稿结果；预览不依赖真实付费调用。

没有选择模型时禁用渠道选择；候选加载失败显示错误和重试，不显示成“无渠道”。渠道候选必须与服务端校验使用同一模型支持口径。新渠道不自动加入已有规则，全选不代表持续动态覆盖未来渠道。

停用、已删除或已移除模型支持的历史渠道保留名称/ID及状态，允许移除，不能在刷新或保存无关修改时静默丢失。新增选项不得选择不支持模型的渠道；不把暂不可用等同删除配置。

## 生效预览与最终用户展示

管理员预览按渠道分组。示例：用户 A 模型在 B/C 为 0.9，组织在 C/D 为 0.8：B/C 显示“0.9×，用户配置”；D 显示“0.8×，组织继承”；E 显示“1×，系统默认”。

- 用户编辑页绑定当前用户，使用用户草稿和当前组织配置，展示该用户逐渠道最终倍率。
- 组织编辑页的「组织默认折扣」仅列出组织草稿所覆盖的模型和渠道。成员的生效倍率在个人规则编辑器查看。
- 组织预览显示组织总版本、组织 ID 与生成时间。个人预览同时显示用户总版本。草稿变化立即重查；后台配置通过前台每 30 秒刷新、重新聚焦及重新联网时重查。发现后台版本变化后提示比较和主动重载，保留本地草稿与原保存版本，不自动变基；预览为当前状态解释，不保证未来请求命中同一渠道或版本。保存组织规则仅检查组织总版本，不因成员个人规则变化而覆盖其配置。

个人预览必须覆盖未选中的可用渠道，避免暗示选中范围就是可调用范围。无法加载继承数据时显示“预览失败”，不能伪造系统原价。界面明确提示“适用渠道只影响折扣，不限制请求路由；不同执行渠道可能使用不同倍率”。

无内部渠道查看权限的用户，包括代理客户，不展示渠道矩阵。模型广场按本人可用渠道聚合有效倍率范围，纳入组织继承和系统 1；日志显示实际消费倍率和来源。登录用户私有预览不能进入匿名价格缓存。

## 保存、删除、冲突与历史

- 修改草稿后标记未保存；列表保存将当前主体全部修改原子提交，表单“确定”仅写入草稿，明确区分按钮含义。
- 列表加载记录主体配置总版本，整份保存发送 `expected_revision`；新增、删除及重建都受同一版本保护。两人修改不同模型也可能冲突，禁止自动合并后覆盖。
- 保存中禁用重复保存及范围编辑；成功刷新当前规则、相关生效预览、本人价格展示和历史。关闭有改动的窗口须确认丢弃，失败保留草稿。
- 409 显示“配置已被他人修改”，提供主动加载最新版本；不得后台刷新后直接抹掉草稿或自动覆盖。切换用户/组织隔离草稿与缓存键。
- 删除需说明恢复继承的范围。用户删除不是设置原价；组织删除不修改成员的个人覆盖。
- 历史展示模型、倍率前后值、渠道增减、操作者名称/ID和时间；不可修改历史。用户无渠道查看权限时使用脱敏投影，并用服务端游标继续加载新旧版本的历史。

## 组件、响应式与可访问性

优先复用 `StaticDataTable`/现有数据表业务封装、`Dialog`、`ConfirmDialog`、模型选择器及 `MultiSelect`。`MultiSelect` 已有搜索、选中摘要和数量收敛能力；全选使用已有 Button 与选择状态组合，不另写通用多选控件。旧代理授权编辑器继续负责授权，实时折扣编辑器不合并采购倍率和权限复选框。

旧消费与实时编辑器分别记录脏态，外层关闭保护取两者的逻辑或。用户管理菜单的折扣弹窗作为菜单的同级组件挂载，菜单关闭不能卸载草稿或丢弃确认框。无改动编辑、倍率 `0.80` 与 `0.8` 等价及渠道顺序变化不能产生假未保存状态。

规则搜索只影响规则列表，不同时过滤生效预览。渠道搜索保留范围外选中项的名称/ID与失效提示。来源枚举未知时明确显示未知来源，不自动显示系统默认。

窄屏按模型卡片纵向展示，渠道摘要可展开；数量多时限制已选标签高度，不撑破弹窗。标签、校验提示与输入关联；所有渠道选择、清空和保存支持键盘，焦点保持可见；状态同时使用文字，不只依赖颜色。

实现文案仅维护 en/zh，数值展示复用现有格式化工具及 `toIntlLocale`。组织/用户模式共用业务编辑组件，由各自入口注入数据和保存动作，不构造第二套相同交互。

## UI 验收

覆盖模型重复添加、单模型多渠道单倍率、筛选全选、零渠道、超长名称、多渠道摘要、显式原价与恢复继承、预览全部来源、权限拒绝、加载失败、并发冲突、草稿隔离及未保存退出。交互、键盘焦点、窄屏和 en/zh 文案均需回归；静态类型检查不能代替这些行为测试。

另覆盖 0.01/5 两端值、三位小数拒绝、非 Root 组织管理拒绝、组织默认折扣预览、个人停用与重新启用、预览过期、两人改不同模型及删后重建的 409。界面说明信任请求可能免预扣，不能用“未暂扣额度”展示成免费调用。
