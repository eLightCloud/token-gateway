# 组织 Invoice 全部账户与入账对账优化方案

## 问题与目标

中关村学院（组织 ID `1`）的 2026 年 8 月 Invoice 存在两个已确认缺口：

1. Invoice 账户列由当期消费日志驱动，零消费、未登录或只入账未消费的组织账户没有展示和导出。
2. 当期管理员增加余额的历史事实没有进入结构化调额流水，导致 CSV 的“用户当期成功充值订单金额”显示为零。

本次目标是让 Invoice 页面与 CSV 共享同一组账户范围和财务摘要，同时保持组织账单只读，不改写用户余额、消费或退款事实。

## 已确认口径

### 账户范围

Invoice 的“全部账户”指：成员关系的计费窗口与选定账期存在时间交集的全部用户。

- 包含零消费、未登录、只入账未消费的账户；
- 包含账期内曾属于组织、但导出时已离开的账户；
- 用户存在多段成员关系时只展示一次，事件按多段窗口的并集归属；
- 消费仍严格按成员计费窗口归属；对已进入账期账户集合的用户，充值和调额按完整自然账期统计，包含加入组织前先行入账的金额。

### 入账与净变动

原“用户当期成功充值订单金额”同时混入了管理员正负调额，名称与数值语义不一致。新口径拆分为：

| 指标 | 定义 |
| --- | --- |
| 当期支付充值金额 | Invoice 账户在完整自然账期内的可识别成功钱包充值订单 |
| 当期管理员增加金额 | `delta_quota > 0` 的管理员调额 |
| 当期管理员扣减金额 | `delta_quota < 0` 的绝对值 |
| 当期全部入账金额 | 当期支付充值金额 + 当期管理员增加金额 |
| 当期钱包净变动 | 当期支付充值金额 + 全部管理员调额 |
| 当前剩余金额 | 查询或导出时主数据库 `users.quota` 的即时值 |

本次不自动把兑换码、奖励、退款返还或订阅付款归入“全部入账”；若产品未来改变该范围，必须先建立完整钱包事件流水。

## 优化方案

### 1. 唯一账户范围

新增独立的 Invoice 账户范围模块，复用现有 `activeAndHistoricalOrganizationMembers` 和 `logMembershipBounds` 的计费边界，输出与账期存在交集的去重账户 ID。

`GetOrganizationInvoice` 先生成账户范围，再将消费聚合金额投影到账户上。没有消费聚合的账户金额为零，但不得从 `accounts` 中删除。

### 2. 唯一财务摘要

新增独立的 Invoice 账户财务摘要模块，一次批量读取所有范围账户的：

- 成功支付充值订单；
- 当前结构化管理员调额；
- 经人工复核的历史调额事实；
- 用户即时余额。

先用成员计费窗口确定 Invoice 账户集合，再对该账户集合按完整自然账期批量查询充值和调额，以覆盖“先入账、后加入组织”的实际流程。页面 JSON 和 CSV 都直接使用该摘要，CSV 不再重新计算财务金额。

### 3. 历史调额回填

旧管理日志没有可信的 `balance_before/balance_after`，不伪造数据写入当前完整调额流水。新增只用于上线前历史的不可变事实表，保存：

- 原管理日志 ID（唯一，保证幂等）；
- 用户、操作人、`delta_quota`、发生时间；
- 复核人和复核时间。

命令行工具保留预览和可选的事实固化能力。产品端不以命令执行为前置：月度汇总首次构建时自动兼容精确的旧“管理员增加余额”事件，已发布汇总的后续查询不再扫描原始日志。无法精确识别的日志必须失败关闭。

### 4. 页面与 CSV

- Invoice API 在每个账户上返回财务摘要；
- 页面新增账户财务汇总表，按账户竖向展示，避免在 42 个横向账户列中增加更多补充行；
- 模型分类和模型交叉表仍展示全部账户，零消费单元格为零；
- CSV 保留现有交叉表，只追加“用户上期余额”、“用户当期充值金额”、“用户当期消费金额”和“用户当前余额”四行。其中当期充值包含支付充值、管理员加额及其他已识别正向入账。

## 文件级改动边界

| 范围 | 改动 |
| --- | --- |
| Model | 新增账户范围、统一财务摘要和历史调额事实模块；现有 Invoice 只做最窄接入 |
| Migration | 主数据库自动建立历史事实表，不自动从日志写入财务数据 |
| CLI | 保留预览/可选事实固化工具，不影响正常查账 |
| Controller/CSV | 改为消费统一 Invoice 财务摘要 |
| Frontend | 新增账户财务汇总表与七语言文案 |
| Docs | 实施完成后同步 `10-product` 中的旧口径 |

## 验证要求

### 账户和时间边界

- 零消费、零入账账户仍出现；
- 零消费、有入账账户出现并显示入账；
- 从未登录不影响账户出现；
- 对账期账户集合中的用户，加入组织前先行发生的当期入账仍计入；
- 多段成员窗口不重复计数。

### 财务指标

- 支付充值、管理员增加、管理员扣减、全部入账和净变动分别精确计算；
- 页面与 CSV 的账户顺序和金额一致；
- 历史回填重复执行不会重复入账；
- 中关村学院 2026 年 8 月经复核历史入账合计为 `$17,040`，其中 `renxiaom` 为 `$13,500`。

## 完成标准

1. Invoice JSON、页面和 CSV 都覆盖账期内全部组织账户；
2. 页面与 CSV 使用同一财务摘要，不存在两套计算；
3. 入账与扣减指标语义清晰，不再用“成功充值订单”代表管理员净调额；
4. 历史调额在首次汇总构建时自动计入；可选固化仍须可预览、可审计且幂等；
5. 不修改组织账单之外的钱包、充值、订阅、消费和退款主链路；
6. 相关测试、类型检查、lint、i18n 同步和构建通过后，才将本文状态改为 `done`。
