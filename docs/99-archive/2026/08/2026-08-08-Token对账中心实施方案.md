# Token 账单与人工对账中心实施方案

## 1. 实施目标

将当前被过度扩展为“自动上游对账平台”的实现，收敛为一个只读的 Token 账单工作台。修正后的功能只从现有业务数据库读取账单事实，供 `root` 查看、筛选、下钻和导出，与上游的比较由人工在系统外完成。

## 2. 强制边界

- 不修改 Relay 发送路径。
- 不修改渠道选择和 retry 路径。
- 不在预扣、结算、退款和异步任务路径增加账单采集回调。
- 不新增上游数据源、连接器、密钥、同步任务或成本模型。
- 不新增 attempt、usage、run、result、resolution、snapshot、capture 类业务表。
- 不改写现有账单记录。
- 只有证明现有事实落库错误时，才在该事实的原始业务路径单独修复。

## 3. 工作包

### WP-01 删除越界主链路接入

## 4. 删除清单

实施时应将下列概念从代码、API、UI、i18n 和测试中一并删除：

- reconciliation account / credential；
- source / connector / secret / sync；
- attempt / dispatch / capture / watermark / gap / node health；
- provider usage / upstream cost；
- model reconciliation mapping；
- run / partition / matching / result link / difference；
- responsibility allocation / resolution；
- close gate / snapshot / reopen；
- artifact store / export task / download token；
- shadow capture / workspace enabled / reconciliation mode。

## 5. 实施顺序

1. 先修正产品、架构与实施文档。
2. 删除所有主链路插桩，恢复中转与计费原路径。
3. 删除自动上游对账领域、表和任务。
4. 建立单一只读账单查询模块。
5. 实现 Root API 和 CSV 导出。
6. 按通过评审的视觉方案重做页面。
7. 完成一致性、权限、数据库兼容和前端构建验证。

## 6. 完成定义

只有同时满足以下条件才视为修正完成：

- 账单与直接查询现有数据库结果一致；
- 账单代码只出现在路由、控制器、只读查询服务、数据库查询和前端 feature 中；
- Relay、quota、text quota、task polling、channel test 不依赖账单模块；
- 不存在上游同步、成本、attempt、capture、run、resolution 和 snapshot 实现；
- 页面没有自动对账或自动关账的暗示；
- 账单页面任何异常都不影响客户请求、扣费、退款和异步任务。
