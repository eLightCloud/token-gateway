# 睿观系统模型接入分阶段实施计划

## 目标与范围

按[接入方案](../80-dev/2026-10-14-睿观系统模型接入方案.md)分阶段交付个人自动开户、企业随租户自动开户、员工独立 Key、一次性个人赠送、运营企业充值，以及 Vantage 系统模型治理和独立平台站点。

本计划在当前 token-gateway 仓库保存双方协作的阶段依赖，只有网关任务在本仓库实现。Vantage Identity、Credential、受控模型入口、Provider 接合及平台前端在 Vantage 仓库实现并按其权威文档验收；此处不创建跨仓库第二套身份或执行规范。

业务、安全、数据和接口语义唯一引用接入方案；本文件拥有本专项的任务状态、阶段退出门和证据。网关[路线图](./路线图.md)只登记专项入口，不复制任务完成度。外部分析与先前方案中的“企业人工开户”已被用户最新确认取代，本计划仅将充值列为运营人工操作。

## 当前状态

2026-10-14：网关专用接口、个人/企业开户、员工 Key、凭据生命周期、候选目录及运维配置页面已实现并完成本轮修复验证；**P0—P5 的跨仓库退出门仍未全部关闭**。真实数据库沙盒已有证据，实际部署边界、运营充值与模型联调尚未验收。阶段采用依赖及退出门排序，不虚构上线日期。

| 阶段 | 内容 | 依赖 | owner | 状态 / 退出门 |
| --- | --- | --- | --- | --- |
| P0 | 合同、部署和资金口径固定 | 无 | 双方后端 / 运营 | 进行中 / G0 |
| P1 | 专用安全入口与个人自动开户 | G0 | Lighting 后端 / Vantage Identity | 网关代码通过，环境与 Vantage 待验 / G1 |
| P2 | 企业自动开户、员工 Key 与运营充值纵切 | G1 | 双方后端 / 运营 | 网关开户通过，充值/归属/消费纵切待验 / G2 |
| P3 | 受控模型调用、凭据生命周期与迁移 | G2；迁移动作需业务授权 | Vantage Resource / Identity、Lighting 后端 | 网关生命周期通过，Vantage 待实施 / G3 |
| P4 | 目录治理、原生选择与独立平台站点 | G3 | Vantage 治理 / 前端、Lighting 目录 | 网关目录通过，治理与站点待验 / G4 |
| P5 | 数据库、安全、多端与灰度发布验收 | G1—G4 | 双方工程 / 安全 / 运营 | 三库已验证，端到端灰度待验 / G5 |

三数据库与安全验证随相关阶段执行，P5 汇总最终候选证据，不能等到 P5 才首次检查。具体发布范围只能包含已经关闭退出门的能力。

## P0：固定接入合同和实施基线

### 工作项

- [ ] T00：复核双方当前 commit、已有改动、实际扩展点及模块版本；记录管理口令、模型 Token 和浏览器会话的不同用途。
- [ ] T01：固定资源 ID、成员关系 ID、账户类型、请求/响应、幂等恢复、错误码及状态合同；明确企业开户 API 允许创建，但不允许充值或调额。
- [ ] T02：确定 Vantage 后端多个 IPv4 出口、HTTPS 和应用端口隔离规则；配置通过运维页面更新，来源只检查 TCP 对端、不读取代理头；启用前必须配置合法口令和白名单。
- [ ] T03：由运营核对 100 CNY 计费额度换算口径；固定主库赠送事实、企业零额度及财务可追溯方式，检查全局赠送配置的隔离。
- [ ] T04：固定新增绑定、轮换记录的跨数据库约束及迁移位置；选择现有普通开户、消费、Token 及日志查询作为兼容回归基线。
- [ ] T05：登记 Vantage 预算责任需收敛、人员迁移授权、自动化服务身份等缺口；未定事项只能阻塞依赖它的动作，不妨碍个人和企业基础开户。

### 交付与 G0

产出双方可实现的最小合同、部署配置清单和数据库设计；只包含占位配置与脱敏样例。**G0** 要求账号类型与赠送边界无歧义、请求不能控制资金或指定任意内部账户、来源限制可实际部署、恢复及唯一性方案可覆盖三种数据库。业务未决项明确归属和阻塞动作。

## P2：企业自动开户与共享余额纵切

### 工作项

- [ ] T20：租户开通事务保存企业开户意图；Lighting 按稳定租户资源键自动创建零额度账户，重试不覆盖已有账户、运营充值或状态。
- [ ] T21：员工加入按稳定成员关系创建独立 Token；企业尚未就绪时保持 pending，后台恢复使用同一关系标识。
- [ ] T22：形成运营账户查询及受控充值路径，优先复用现有后台；记录企业账户与租户的准确对应，不新建充值资金 API。
- [ ] T23：复用消费日志的 `token_id` 和历史绑定实现受控员工归属查询；企业与员工的查询范围分开，不改写组织 Invoice 或个人扣费链。
- [ ] T24：用一个企业账户、两名员工完成真实普通模型调用；验证 Key 独立、共享余额、并发扣费、余额不足与运营充值后原 Key 可用。
- [ ] T25：执行 A03、A04、A05、A09；特别将全局新用户赠送设为非零后验证企业和员工无赠送，并验证已有财务数据与日志库范围。

### 交付与 G2

交付租户自动开户、员工 Key 和运营充值/归属查询纵切。**G2** 要求一个租户只绑定一个企业账户、两个员工只使用各自 Key、企业初始零余额、员工无个人赠送、真实消费归属正确、并发扣费及重复操作无异常；开户与资金状态分别展示，已充值账户不会因重试被清零。本阶段数据库验证通过。

运营手动充值只在受控验证账户或已批准的上线账户执行，记录实际入账方式和结果；文档编写不代表授权操作真实资金。

## P3：系统模型受控入口与凭据生命周期

### 工作项

- [ ] T30：Vantage 新增 Lighting 接入适配并沿公开 Provider 协议接合受控入口；根据当前可信人员、租户及关系解析 Key，不接收客户端付费账户或任意上游目标。

- [ ] T34：验证至少一个实际支持工具调用的模型及流式链路；覆盖真实错误、usage、取消/断连以及采用的长连接后续请求。
- [ ] T35：执行 A05、A06、A08、A10 及本阶段 A09；对实际改动的鉴权与生命周期登记 OWASP 控制、回归证据和未解决项。

### 交付与 G3

交付工作台到 Lighting 的实际系统调用链和已定稿的生命周期动作。**G3** 要求 Key 不进入客户端，服务端按当前关系选择准确付费账户，轮换及撤销生效，迁移期间无个人回退，真实工具/流式/错误和结算证据成立。迁移授权未定或某 transport 未验证时，对应入口保持未开放，不以模拟成功替代。

企业自动化暂不开放员工凭据借用；服务身份的独立合同与原生后台执行验证另列范围。
