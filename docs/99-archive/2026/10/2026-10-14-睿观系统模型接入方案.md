# 睿观系统模型接入方案

## 问题与目标

Vantage 用户登录后无需另行注册 Lighting 或填写系统模型 Key；企业共享一个 Lighting 计费账户，每名员工使用独立 Key。Lighting 继续拥有余额、赠送、充值、预扣、结算和退款，Vantage 拥有应用身份及系统模型治理。

本文规定接入合同；网关已实现其中的专用接口、账户与凭据生命周期，并完成本地及真实三数据库验证。部署和跨仓库业务交付仍需阶段验收。阶段状态唯一见[分阶段实施计划](../50-planning/2026-10-14-睿观系统模型接入分阶段实施计划.md)。落实并验证后再将稳定事实同步到产品、架构和运维主题。

需求来源是 Vantage 仓库的 `docs/80-dev/2026-10-14-系统模型接入与平台管理端分析.md` 及本次会话的后续确认。后续确认优先：企业账户随租户自动开通，员工 Key 自动生成，只有充值由运营手动进行；不继承早先“企业人工开户或绑定”的方案。

### 已确认的业务规则

| 场景 | 自动处理 | 资金规则 |
| --- | --- | --- |
| 个人自主注册 | 加入 Vantage 默认租户，创建个人 Lighting 账户及默认 Key | 一次性赠送 100 RMB 计费额度 |
| 企业租户开通 | 创建并绑定一个企业 Lighting 计费账户 | 初始额度为零，不参加个人注册赠送 |
| 企业员工加入 | 在企业计费账户下创建独立员工 Key | 共享企业余额，不另建员工钱包或赠送 |
| 企业充值 | 由 Lighting 运营人员通过现有后台操作 | 按现有受控充值或调额流程入账 |
| 默认租户人员迁入企业 | 转为企业成员，系统模型改用企业员工 Key | 旧个人账户及余额保留，不能继续以个人 Key 作为系统凭据 |
| Lighting 开通失败 | 人员或租户创建结果保留，后台继续重试 | 模型显示待开通，不回退其他付费账户 |

平台管理站点单独部署，复用 Vantage 后端和独立平台身份。平台维护候选模型、上架、租户授权、申请审核和平台默认；租户管理员申请候选模型及设置企业默认。个人自定义 Provider 继续沿 ZCode 原生能力。

### 工程取舍

- 接入安全采用专用强口令、Vantage 后端来源限制和 HTTPS，不增加 OAuth、JWT 签发、请求签名或新的登录会话系统。
- 企业计费账户复用现有 `User` 钱包；员工凭据复用现有 `Token`，不建立组织钱包或第二套结算引擎。
- 首期只自动创建新受管账户。关联已经存在的 Lighting 企业账户另行设计，不允许接口自动认领同名或同邮箱账户。
- Lighting 管理接口只供 Vantage 后端调用；客户端系统模型请求经 Vantage 受控入口，不下发 Lighting Key。
- 本次不修改源 Vantage 分析文件，也不把本文作为其身份或原生执行规范的替代合同。

## 优化方案

### 1. 唯一 owner 与调用边界

| 责任 | owner | 边界 |
| --- | --- | --- |
| 人员注册、租户开通、成员迁移和停用 | Vantage Identity | 持久保存人员、租户及成员关系事实，发出可信开通意图 |
| 上架、租户授权、申请与默认模型 | Vantage 模型治理 / Authorization | 每个实际系统模型请求重新检查当前权限 |
| 账户、凭据及外部标识绑定 | Lighting Vantage 接入服务 | 只接受专用接入身份，服务端解析内部账户 |
| Lighting Key 安全使用 | Vantage Credential / Resource Access | 凭据不进入 Renderer、Provider 页面、prompt 或客户日志 |
| 余额、赠送、充值及扣费 | Lighting 现有资金链 | 不让 Vantage 指定金额或操作资金 API |
| 模型配置、个人选择和执行 | ZCode 公开 Provider 服务 | 复用 facade；不足时补通用扩展点，不穿透私有存储 |

```text
开通：Vantage Identity -> 持久开通意图 -> Vantage 后端 -> Lighting 专用接入 API
调用：ZCode Provider -> Vantage 受控模型入口 -> 当前个人/员工 Token -> Lighting Relay
充值：Lighting 运营后台 -> 企业计费 User 钱包 -> 现有财务事实
```

专用接入口令与模型调用 Token 是两种凭据。前者不能调用模型或获得后台管理员权限，后者不能调用接入管理接口。

### 2. 简洁的服务端安全措施

1. 超级管理员在 **系统设置 → 运维 → Vantage 接入**（`/system-settings/operations/vantage`）维护启用开关、专用应用口令、多个来源 IPv4。复用已有超级管理员认证和审计，不增加认证系统；专用应用口令不能操作该配置接口。
2. 页面提供密码学安全随机源生成的 32 字节密钥，以 64 位十六进制文本交付。手工口令至少 32 字节，无共用默认值，不使用用户密码或管理员 PAT。Lighting 只持久化 SHA-256 摘要并恒定时间比较；读取配置只返回是否已设置，口令留空保存保持原值。新口令仅在管理员当前编辑表单中显示和复制，保存成功后清空，Vantage 后端另行安全保存。
3. 来源白名单只接受完整 IPv4，允许多个地址并去重；拒绝 IPv6、CIDR 和域名。逐请求仅检查 TCP 对端地址，不读取 `X-Forwarded-For` 等代理头，不要求配置 `TRUSTED_PROXIES`。普通反向代理部署时，对端是代理地址；若需在网关区分 Vantage 出口，入口须保留 TCP 来源，或由受限专用入口执行相应来源限制，不能把共享代理地址当作 Vantage 身份证明。
4. Vantage 到受控接入端点必须使用 HTTPS 并校验证书；TLS 终止后的链路及应用端口须限制访问。共享出口只能证明来源网络，应用口令与来源限制必须同时成立。
5. 配置整体保存在已有 `options` 表的一个敏感记录中，不新建表。每次专用管理请求读取已提交配置，不使用进程缓存、轮询或环境变量回退。保存成功后所有网关实例的后续请求生效，无需重启；已开始的请求继续使用其读取到的配置。专用路由始终注册，默认关闭返回 503；启用必须有口令和至少一个合法 IPv4。非法保存返回 400 并保持原配置，配置读取故障返回 503，不放开访问。
6. 复用现有请求体限制、对象绑定及状态校验、安全错误处理和低敏审计。按用户确认，Vantage 专用接口没有限流中间件、开关或预算配置，流量控制由已有外部措施负责。业务请求只接收合同字段，拒绝 `user_id`、角色、余额、赠送金额、任意上游 URL 等越权字段。
7. 配置及秘密交付响应使用 `Cache-Control: no-store`；应用口令及摘要不进入通用配置读取响应、审计或错误日志。通用配置写入口拒绝覆盖专用配置记录，避免绕过专用校验；普通业务状态响应不回显 Token 明文。
8. 口令轮换通过页面保存新口令，协调更新 Vantage 后端；网关下一次请求拒绝旧口令，不引入多口令或刷新令牌系统。同一业务操作仍可恢复。首次发布此实现后需在页面完成初始化，旧 `VANTAGE_*` 环境配置不再作为有效来源。

配置接口为 `GET/PUT /api/option/vantage_integration`，仅超级管理员可用。GET 返回 `enabled`、`allowed_ipv4`、`secret_configured`；PUT 接收 `enabled`、`allowed_ipv4` 和可留空的 `secret`，禁止设置摘要或其他字段。保存还要求有效后台会话和 `X-Security-Proof`（范围 `vantage.integration.settings.write`）；proof 复用现有限时、单次再认证，绑定当前会话，已启用 MFA 时不得退回密码。PAT 或接入口令不能代替该证明。
这是针对一个可信应用后端的接入机制，不是对外多应用认证平台。仅有口令不能保证进程来源，必须同时落实网络访问边界和最小操作权限。平台管理站点的浏览器认证仍由 Vantage 现有平台会话、强认证、Origin 和 CSRF 负责。

### 3. 个人赠送与企业账户初始化

新增独立受管开户服务，显式设置账户类型和初始额度，不直接使用会覆盖初始额度的通用 `User.Insert` / `InsertWithTx`，也不调用会再次生成通用赠送记录的后处理路径。已有注册、OAuth 和管理员开户行为保持原合同；必要接线保持最小。

受管账户的后台角色固定为普通账户。账户显示信息可更新，但不会改变外部绑定；内部用户名需符合当前长度和唯一性限制。不给 Vantage 员工分配可共享的 Lighting 登录密码，具体无本地密码或独立随机密码初始化方式由实现核对现有认证边界后选择，并验证不能以接入口令登录这些账户。

个人开户的主库事务同时保存 `User`、个人账户绑定、一次性赠送事实和默认 `Token` / 凭据绑定。企业开户事务只保存零余额的 `User` 和企业绑定；员工 Key 在独立事务中创建。事务失败不产生可见的部分开户，也不把用户业务注册失败与 Lighting 开户失败混为一件事。

个人赠送的业务金额固定为 **100 CNY 计费额度**，不根据用户请求、支付折扣或购买倍率变化。建议按现有人民币余额展示口径换算：`100 / USDExchangeRate × QuotaPerUnit`，采用 decimal 运算及 `common.WalletQuotaFromDecimalStrict`。校验配置有限、正数、结果在钱包范围内且大于零；非法换算拒绝开户，不能悄悄少送或送零。阶段 P0 由运营核对该口径与现有站点额度定义。

在个人绑定中保存赠送 CNY、换算快照、实际 quota、时间和赠送操作标识，事实提交后不随配置变化重算。不能仅用缓存、系统日志或“当前余额等于某个数”判断是否赠送。企业绑定的赠送事实为零，员工创建和凭据轮换从不触发赠送。

主库赠送事实与余额在同一事务提交；辅助审计或独立日志库写入失败不能导致重新赠送，应从持久事实恢复记录。不能声称主库与独立日志库共享同一事务。

### 4. 接入接口建议

以下为当前网关实现的 v1 合同，尚未代表部署已启用。统一前缀为 `/api/integrations/vantage/v1`。

| 方法与相对路径 | 输入重点 | 成功行为 |
| --- | --- | --- |
| `PUT /personal-accounts/{subject}` | 稳定个人主体引用、低敏显示信息 | 确保个人账户及默认 Key；首次赠送，重试恢复 |
| `PUT /enterprise-accounts/{tenant}` | 稳定租户引用、低敏显示信息 | 确保企业账户，初始余额零；已有账户不覆盖余额 |
| `PUT /enterprise-accounts/{tenant}/members/{subject}/credentials` | 稳定成员关系引用 `membership_ref` | 为当前成员关系确保一个员工 Key |
| `GET /accounts/{account_type}/{external_ref}` | 类型为 `personal` 或 `enterprise`，外部引用为单路径段 | 查询类型、状态和关联引用，不返回秘密 |
| `GET /credentials/{credential_ref}` | 受管凭据引用 | 查询状态、代次和归属，不返回秘密 |
| `POST /credentials/{credential_ref}/rotate` | `Idempotency-Key` 及预期凭据代次 | 幂等轮换，恢复同一次操作结果 |
| `DELETE /credentials/{credential_ref}` | 受管凭据引用 | 幂等撤销，重复请求不生成新凭据 |
| `DELETE /enterprise-accounts/{tenant}/members/{subject}/credentials/{membership_ref}` | 稳定成员关系引用 | 撤销整段成员关系，即使 Key 尚未创建也保存撤销事实 |
| `GET /models` | 有界分页参数或目录修订 | 返回供 Vantage 同步的候选目录安全投影 |

只在开户、确保凭据和轮换的受控响应中向 Vantage 后端交付 Key；响应丢失后恢复同一操作结果。已撤销或已被轮换的凭据不能因为旧请求重放重新激活、泄露旧 Key 或再开一个 Key，应返回当前状态及明确冲突。

首次创建返回 201，幂等恢复返回 200；请求非法 400，认证失败 401，来源或对象范围拒绝 403，未知受管对象 404，关系/版本/重放冲突 409，服务暂不可用 503。错误含稳定 `code`、低敏 `message` 和 `request_id`；`success`、`created`、对象引用与凭据状态含义固定。同一幂等标识配不同业务对象或变更意图必须拒绝。

操作不得读取、认领或改动不属于该接入命名空间的账户和 Token，不提供充值、调额、指定赠送、任意账户绑定或后台管理 API。凭据状态与余额是否充足分别表达，不以 Token 无限额度代表账户余额无限。

账户响应中的 `ref` 继续使用 `personal/{subject}` 或 `enterprise/{tenant}`；查询时按上述两个路径段传递，不能把含 `/` 的引用放进单个 Gin 路径参数。

### 5. 最小数据结构与恢复

主库新增以下领域记录，具体表名在 P0 固定。使用字符串有界引用、整数金额和普通 TEXT，避免方言专属 JSON、部分索引及无界状态 payload。

| 记录 | 持久事实 | 唯一性与用途 |
| --- | --- | --- |
| 账户绑定 | 应用命名空间、个人/企业类型、外部主体或租户、内部 `UserId`、状态、个人赠送事实 | 命名空间＋账户类型＋外部引用唯一；内部受管账户绑定唯一 |
| 凭据绑定 | 账户绑定引用、主体、成员关系、代次、可空 `TokenId`、状态、创建/撤销时间 | 同一关系每个代次唯一；每个 Token 对应一个历史绑定；尚未开通时也可保存关系撤销事实 |
| 凭据轮换操作 | 操作标识、原凭据、预期代次、意图摘要、结果凭据引用 | 同一操作标识唯一，保存响应丢失后的恢复依据 |

个人开户和企业开户用稳定资源键去重，无需另建通用工作流或消息平台。并发通过主库唯一约束和必要行锁串行化，重复请求读取已提交事实；`model/` 中行锁沿用 `lockForUpdate(tx)`，不得只靠 Redis 锁。当前有效凭据指针及历史记录的唯一性须验证三种数据库。

凭据明文继续由现有 Token 存储负责，不在新绑定和轮换记录重复保存。历史绑定不删除或改挂其他员工；按 `token_id` 关联员工消费，无需改写消费事实。普通员工不获得企业账户的所有 Token 或消费查询权限。日志数据库与主库分开时，分步查询受控 Token 范围，不进行跨库 join；涉及已有日志索引调整时另按数据库门验证。

Vantage 在自己的人员、租户或成员事务中保存开通意图和当前资格版本，提交后调用 Lighting；重启后能恢复 pending/unknown 操作。超时先查询或用同一资源键恢复，不盲目生成新标识。Lighting 不拥有 Vantage 登录资格，失败不会撤销已合法创建的人员。

成员关系撤销不能依赖 Vantage 已经收到 `credential_ref`。开通尚在途时，按稳定关系引用先持久保存撤销事实；同关系开通与撤销在 Lighting 串行裁决，撤销先到则拒绝开户，开户先到则撤销已创建 Token。Vantage 写回开通结果前再次检查人员当前资格版本，旧结果不能变为当前凭据；无需增设通用事件总线。

企业开户可早于员工 Key。已开户、Key 已就绪但余额为零时返回“已开通，余额不足”，由运营充值；不得显示“待开户”，充值后无须重新生成 Key。

网关轮换、单凭据撤销、成员确保和成员撤销均先锁账户再处理凭据，保持同一锁序；等锁后轮换操作与恢复结果使用当前读，避免 MySQL 旧快照误报失效。停用 Token 前复用既有缓存 fence，提交后及幂等恢复时失效缓存；缓存操作失败返回 5xx，调用方重试以恢复持久事实和缓存，不能将该错误理解为数据库一定未提交。不新增恢复队列或第二套缓存协议。

### 6. 迁移、停用和轮换

- 默认租户人员迁入企业时，Vantage 当前成员事实先切换并阻断旧个人系统凭据；企业 Key 未就绪时仍拒绝回退。已持久的旧开通意图不能覆盖后来更高版本的成员事实。
- 旧个人 Lighting 账户、余额和赠送事实保留。Vantage 专用旧 Key 按其生命周期撤销，不撤销用户其他个人 Key，也不转移或扣回个人余额。
- 员工离职后撤销对应成员关系 Key；重新加入需新的 `membership_ref`。确保接口不能恢复已撤销关系，旧请求晚到不能成为当前系统凭据。
- 企业暂停由 Vantage 即时拒绝后续系统请求，并持久保存需执行的凭据撤销或账户停用意图。恢复后凭据安排必须显式，不根据旧缓存自动复活。
- 轮换更新结果指针与旧 Token 状态，复用现有缓存失效；业务幂等记录与 Token 变化必须一致提交，响应丢失不会重复轮换。
- 现有 HTTP、SSE、Responses WebSocket 等实际采用的 transport 均覆盖后续请求再授权。已开始且可能收费的请求沿现有结算语义处理，不将下架或客户断连解释为自动免费。

谁可以发起人员迁移、需要本人或管理员何种确认，以及企业迁出后的身份恢复，尚未确定。P3 在开放对应动作前解决这些业务边界，不按邮箱相同自动认领。

### 7. 系统模型目录、调用与管理端

Lighting 候选目录从实际模型、路由和元数据能力提供安全投影，区分已验证能力、声明及未知。提供稳定模型 ID、品牌显示、协议端点、供应状态及修订/更新时间；不暴露渠道 Key、内部 URL、价格管理字段或其他账户信息。`/v1/models` 的当前 Token 可调用列表不能直接代替完整候选目录。需分页时不能拿截断页当完整目录。

当前投影以具体 `model_name` 为稳定 ID，合并精确元数据和渠道配置模型；前缀/后缀等规则只用于复用现有元数据匹配，不作为可调用模型条目。`status` 保留元数据可见性，`route_available` 表示至少一条渠道与能力同时启用的路由，不代表该租户已授权或真实调用已成功。`endpoints` 接受已有数组及对象格式，仅投影协议名称；工具/流式能力没有实测时仍需独立验收。`revision` 为安全投影内容的 SHA-256 字符串，客户端只按不透明版本比较；删除、同秒修改和路由启停均可改变版本，分页之间版本不一致时重取完整目录。

Vantage 平台上架、租户授权和 Lighting 供应状态是三个事实。新候选默认不上架，同步失败保留有效目录，明确撤除与请求失败分开处理；模型广场隐藏状态不等于系统调用撤权。

系统模型入口根据可信当前主体、租户、当前凭据绑定、上架及授权裁决，再使用对应 Lighting Token。客户端不能覆盖付费账户、Key、租户或上游目标。Token 模型限制可作为访问上限，但批量更新 Key 不能替代 Vantage 的实时裁决。

平台管理站点在 Vantage 独立部署，首期模型专题包含候选同步、上/下架、租户授权、平台默认、申请审核及开通状态。租户管理提供候选申请和企业默认；工作台原生选择区区分系统与个人来源，说明待开通、余额不足、无授权、停用和加载失败。查询失败不能显示为空列表。

默认模型必须在相应租户可用范围内。建议已有有效个人选择继续沿用，配置默认只影响首次选择；失效明确提示修复，不静默切换。具体活动会话行为用固定 ZCode 版本的公开能力验证，不据本文声称已支持。

Vantage 现行架构中企业预算的预留/结算责任与本接入的 Lighting 资金 owner 需要显式收敛；不再对同一费用建立 Vantage 余额和第二次扣费。如仍需企业预算，应另界定为准入约束，不能作为本轮隐含任务。企业自动化的服务身份凭据也另行定稿，首期不借用员工 Key 开放后台任务。

### 9. 验收与发布边界

| 编号 | 必须证明的行为 |
| --- | --- |
| A01 | 非允许来源即使持有正确口令仍拒绝；错误/缺失口令、伪造代理头、直连应用端口和越权方法均不可绕过 |
| A02 | 个人并发开户、超时重试和进程重启只产生一个账户、一个初始 Key、一次 100 CNY 赠送；配置变化不追溯重算 |
| A03 | 企业租户重复开通只创建一个零余额账户；全局赠送非零时企业与员工仍不获赠送；重试不覆盖充值后的余额 |
| A04 | 两名员工 Key 独立并共享企业余额，真实并发消费沿已有链路正确预扣/结算，运营充值后原 Key 直接可用 |
| A05 | 响应丢失可恢复；轮换和撤销重试不产生新凭据；跨账户、跨租户及未受管 Token 操作拒绝 |
| A06 | 迁移、离职、企业暂停及旧事件晚到不恢复旧权限；历史 Token 归属不被更换，个人账户余额保留 |
| A07 | 下架或撤权后 HTTP 和采用的长连接第二次模型请求拒绝；默认失效不换模型；目录故障不清空有效列表 |
| A08 | 工具调用、流式、错误、usage 及取消具备实际协议证据；凭据与客户正文不进入页面/审计；个人 Provider 独立可用 |
| A09 | 真实 SQLite、MySQL、PostgreSQL 覆盖新库、最新发布版代表数据升级、重复启动和并发唯一性；旧用户/Token/财务事实及索引保留 |
| A10 | Key 始终不进入客户端；专用管理口令不获后台或模型权限；平台身份与租户管理身份不能互相替代 |

按[计费规则](../../.agents/rules/billing.md)验证完整资金链。数据库验收记录精确版本、实际命令和结果；日志库共享路径受影响时覆盖独立日志库，涉及 ClickHouse 时追加其验证。构建、mock 或单一方言都不代替数据库门。
