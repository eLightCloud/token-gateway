# 模型优惠渠道准入实施方案

## 问题与目标

模型 A 在 Q1 设置优惠后，调用只能从 Q1 选路。Q1 停用、删除或撤权时，请求在当前限制下失败。模型 B 没有优惠规则时，沿用原有授权和路由。生产环境本次首次启用新配置，运营在切换后重新配置优惠，发布验收以空优惠基线为准。

## 当前实际情况

代理客户的渠道资格由代理授权、客户授权及原路由候选取交集。倍率曾仅影响计价，现由同一个请求快照固定计价来源和允许渠道。旧授权记录的默认数值为 1，无法表达显式消费规则。

## 优化方案

### 规则优先级和渠道交集

| 顺序 | 生效规则 |
| --- | --- |
| 1 | 已启用的个人精确模型名 |
| 2 | 已启用的个人路由匹配名 |
| 3 | 已启用的组织精确模型名 |
| 4 | 已启用的组织路由匹配名 |
| 5 | 基础倍率 1 和既有路由 |

个人精确规则停用后继续按优先级查找，可能命中个人路由匹配名。代理客户的模型授权仍按精确模型名。已启用的显式消费倍率 1 有完整渠道范围。

采购侧计算已配置倍率的渠道集合，包括显式 1。渠道授权独立判断，撤权、停用和删除均保留采购规则的限制。实际候选为原分组、令牌和渠道可用性条件、采购范围、代理和客户授权以及生效消费范围的交集。采购范围内没有候选时保持拒绝。清空模型最后一个采购倍率后，恢复基本授权范围，已有消费约束继续生效。允许管理员清除已删除渠道的采购倍率或撤销该渠道授权，保留历史。

### 术语与接口

- 默认倍率指未设置规则时的基础倍率 1。显式原价指已配置的 1 倍率及其渠道范围。
- 采购 API 用 `ratio: "1", ratio_configured: true` 设置显式原价。`true` 要求提供有效倍率。`false` 接受省略、空字符串或值为 1 的有效十进制字符串。旧客户端回传非空 1 会保留已有显式状态，省略或清空倍率会清除显式状态。采购表的 `ProcurementBaseRatioConfigured` 可空字段保存显式原价标记。
- `active` 是主库统一启用实时消费规则的状态。请求快照冻结规则、倍率、版本和渠道范围，重试沿用该范围。已提交任务使用自己的计费事实结算。WebSocket 每次新调用重读配置，已有连接的固定渠道必须满足当前范围。

### 失败与恢复

范围内无可用候选或固定渠道处于范围外时，返回 HTTP 503，错误码 `pricing_channel_unavailable`，使用服务端现有本地化的无可用渠道文案。任务返回相同错误码并停止重试。已有渠道停用、严格亲和绑定和其他路由错误保留各自状态。路由缓存、亲和和指定渠道均须经过范围过滤。服务端日志可按 `pricing channel unavailable` 和请求 ID 排查。

规则本身的渠道集合不能为空。规则和授权、状态或分组的交集可能为空。保存前预览给出警告，经确认可保存。用户预览按账号可用分组计算，组织默认预览按组织草稿展示各组的渠道状态，采购影响预览展示采购侧范围变化。模型列表按适用分组隐藏规则范围内无启用渠道的模型。

### 首次发布与回滚

1. 暂停优惠和采购配置写入，核对目标环境没有待承接的旧优惠记录；对仍存在的非默认旧消费记录逐项确认后再继续。
2. 迁移主库并验证字段、索引和优惠空基线，逐一更新 API、任务及 WebSocket 服务实例。确认旧实例已退出入口和配置写入路径后，再执行 Root 的 `freeze`、`activate`，开放新配置。
3. 放行前用单一构建验证显式 1、撤权后空交集、清空恢复、WebSocket 后续调用以及旧任务结算。记录构建摘要和各实例版本。
4. 出现故障先暂停配置写入，优先发布能解释当前规则和快照的修复版本。需要回退到旧二进制时，先隔离受影响的新请求并保留现有数据库及历史事实。旧版本无法执行本次渠道约束，且重写矩阵时可能丢失显式标记。待兼容版本恢复并核实规则后，再重新放行。

### 本地网关与浏览器验证

- 使用 `START_DEPS=0 BACKEND_PORT=3320 FRONTEND_PORT=3321 ./start.sh` 和独立 SQLite 库运行网关与前端。通过 Chrome 登录管理端，向实际聊天 API 发请求，以两个独立的本地上游 HTTP 服务记录命中次数。
- 默认选高优先级 Q2。界面保存 Q1 的显式原价后只命中 Q1，未配置模型继续走 Q2。Q1 返回 500 时三次请求均命中 Q1，Q2 零请求。撤权、停用及删除 Q1 时返回 `503 pricing_channel_unavailable`，两条上游均为零请求。清空倍率或清理已删除渠道的倍率后，Q2 和模型列表恢复。组织规则、个人覆盖及停用个人规则后的组织继承均实际发起调用验证。
- 浏览器验证了采购撤权影响提示、删除渠道后清除采购倍率，以及组织优惠空交集的保存确认。实时优惠和采购预览改用全局 API 限流，节省关键写入额度。关键写入限额设为 6 时，两类预览接口各连续调用 8 次均返回 200；界面确认后的保存返回 200，继续写入达到限额后返回 429。
- 修正 `start.sh` 缺少前端构建时的嵌入资源路径，匹配 Go 当前的 `web/dist/index.html`。本地共记录 20 项通过，保留请求命中记录和浏览器截图。
