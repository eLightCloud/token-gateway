# 模型广场访客与客户展示实施方案

## 问题与目标

系统管理新增两个默认开启的展示开关。模型广场依据服务端识别的访问身份选择一条规则，列表和详情使用同一份目录。

| 访问身份 | 生效配置 | 开启 | 关闭 |
| --- | --- | --- | --- |
| 未登录访客 | 仅展示国内模型 | 公开目录中的全部国内厂商模型 | 原公开目录中的全部模型 |
| 已登录普通消费账号，包括代理体系下的客户（`agent_customer`） | 仅展示享有优惠的模型 | 该账号在可用渠道上享有优惠的模型，包含国内和海外模型 | 该账号原本有权查看的全部模型 |
| 代理运营账号（`agent`）、Admin 或 Root | 无 | 该账号原本有权查看的全部模型 | 该账号原本有权查看的全部模型 |

两个开关独立生效。访客目录只按厂商归属筛选。已登录普通客户可以看到自己享有优惠的海外模型。普通客户含存量账号，优惠筛选开启时，没有任何符合条件的优惠就展示空列表。代理运营账号和管理员在四种开关组合下均保有各自的原目录。

本次范围为模型广场及其模型详情。模块启用状态、登录要求、用户分组和经销商权限仍先行判断。Playground、密钥配置、SDK 模型发现、模型调用、实际计价和结算沿用各自的业务规则。

## 实施前的代码基础

- 模型广场列表与详情共用 `usePricingData` 和 `GET /api/pricing`。同一查询还服务于后台的模型倍率编辑器、模型定价表单，以及用量日志的账单列和详情对话框。用量日志会通过它读取历史模型的计费展示数据。见[目录查询](../../../../web/src/features/pricing/hooks/use-pricing-data.ts)、[倍率编辑器](../../../../web/src/features/system-settings/models/model-ratio-visual-editor.tsx)、[定价表单](../../../../web/src/features/system-settings/models/model-pricing-sheet.tsx)、[账单列](../../../../web/src/features/usage-logs/components/columns/common-logs-columns.tsx)、[用量详情](../../../../web/src/features/usage-logs/components/dialogs/details-dialog.tsx)。
- 模型广场已有公开访问、要求登录和关闭三种访问设置。现有中间件能解析登录身份，`GET /api/pricing` 已声明个人访问令牌规则，控制器已处理可用分组和经销商目录范围。见[访问控制](../../../../middleware/header_nav.go)、[令牌路由规则](../../../../middleware/access_token_routes.go)、[定价接口](../../../../controller/pricing.go)、[经销商目录](../../../../controller/reseller_visibility.go)。
- 目录条目已有 `vendor_id`，厂商记录没有地区字段。对于部分缺少元数据的模型，目录会匹配默认厂商，优先采用同名数据库厂商，否则使用可用于展示的负数 ID。因此，同一个厂商在不同环境或补建记录前后可能使用不同 ID。见[定价目录](../../../../model/pricing.go)、[模型元数据匹配](../../../../model/model_meta.go)、[厂商定义](../../../../model/vendor_meta.go)、[默认厂商映射](../../../../model/pricing_default.go)。
- 项目已有批量个人定价快照和渠道可用性检查。已启用的实时定价按个人规则、组织级实时定价规则和系统默认倍率解析。代理运营账号调用客户快照查询会返回 `ErrResellerForbidden`。见[个人定价查询](../../../../model/reseller_pricing.go)、[实时定价入口](../../../../model/realtime_pricing.go)、[消费规则解析](../../../../model/pricing_channel_scope.go)、[渠道可用性](../../../../model/pricing_scope_availability.go)。
- 前端全局关闭窗口聚焦刷新，原定价查询的缓存有效期为五分钟。见[全局查询配置](../../../../web/src/lib/query-client.ts)、[原定价查询](../../../../web/src/features/pricing/hooks/use-pricing-data.ts)。

## 优化方案

### 系统配置与默认值

在「系统管理 → 运营设置 → 系统行为」复用现有表单和保存机制。通过独立的 `model_visibility` 配置模块提供默认值，使用现有 Root Option 接口持久化。旧安装缺少配置时默认开启，已保存的 `false` 在重启后继续生效。同一节点上的目录配置写入、运行时发布和数据库重载使用同一把锁。节点间继续通过现有 Option 同步。本方案复用现有选项存储，无需新增表或字段。

| 配置键 | 默认值 | 页面文案 | 说明文案 |
| --- | --- | --- | --- |
| `model_visibility.domestic_only` | `true` | 仅展示国内模型 | 仅影响未登录访客的模型广场 |
| `model_visibility.discounted_only` | `true` | 仅展示享有优惠的模型 | 仅影响已登录普通客户的模型广场 |

### 厂商归属与管理员维护

厂商归属按模型元数据和现有目录的厂商映射确定。系统内置常见国内和海外厂商的标准名称及明确别名，如 DeepSeek、Moonshot/Kimi、阿里巴巴/阿里云百炼、智谱、OpenAI、Anthropic。匹配时去除厂商名称首尾空白并忽略大小写。正式厂商记录与同名内置展示厂商共用分类。未匹配的自定义厂商显示为「未归类」。模型缺少厂商归属时，需先在模型管理中绑定厂商。

生效归属依次取管理员覆盖、旧 `model_visibility.domestic_vendor_names` 中的国内标记、内置厂商归属。升级后旧名单中的自定义国内厂商继续生效，空名单也能使用内置归属。管理员可覆盖为国内、海外或未归类，并可清除覆盖以恢复自动识别。归属覆盖按规范化的厂商名称存储在独立 Option `model_visibility.vendor_regions` 中。厂商改名后按新名称重新识别，需要时在新名称下设置覆盖。

在「模型管理 → 厂商」增加「厂商归属」入口。管理员选择厂商后可查看当前归属和识别来源，并预览当「仅展示国内模型」开启时，该厂商会纳入或移出访客目录的模型。候选厂商来自现有目录，包括正式记录和内置展示厂商。预览使用与匿名目录相同的基础分组范围。实际访客可访问范围仍由广场的启用、登录和筛选开关决定。

通过 `GET /api/vendors/catalog-regions` 读取归属与影响范围，通过 `PUT /api/vendors/catalog-regions` 保存单个厂商的归属。两条路由沿用厂商管理的 Admin 门禁及令牌的 `model:read` / `model:write` 规则。保存前校验厂商存在及归属枚举，逐厂商更新同一 Option 中的覆盖，串行化读改写并沿用现有同步机制。通用 Root Option 入口的授权维持原规则，管理员可直接在厂商管理界面完成维护。系统行为保留两项展示开关，并引导管理员查看厂商归属。旧空名单提示由说明文字替换。

### 服务端目录与身份分流

1. 新增模型广场专用 `GET /api/pricing/catalog`，沿用现有模块访问控制和目录响应合同，并为新路径声明与原 `GET /api/pricing` 一致的个人访问令牌规则。现有定价接口继续服务原调用方。目录分支和筛选主体放在独立文件，路由和原入口只做必要接入。
2. **未登录访客。** 从已有匿名目录开始。国内开关开启时按生效的厂商归属筛选，关闭时返回原公开目录。
3. **Admin、Root 和代理运营账号。** 从服务端认证上下文取得身份。管理员按已验证角色识别，代理运营账号按现有 `ResellerUserKind` 识别。先完成这两类豁免判断，再进入客户优惠逻辑。豁免账号获得原目录，也保留原有分组与访问范围，代理运营账号无需调用客户快照。现有代理后台访问边界仅增加此只读路径，并继续要求账户已激活、已启用且完成安全设置。
4. **已登录普通客户。** 普通消费账号和 `agent_customer` 均进入该分支。优惠开关关闭时直接返回该账号的原目录。开启时批量获取候选模型的生效个人定价快照。模型至少有一个处于该账号可用分组且有效授权、已启用的渠道，其生效客户消费倍率低于 `model.ResellerRatioScale`，才进入结果。沿用历史消费规则和已启用的实时定价规则。实时定价按现有优先级应用个人覆盖及组织级实时定价，显式原价、加价和不可用渠道均无法凭自身命中。批量复用渠道可用性检查。
5. 代理体系下客户的原目录限制和优惠筛选复用同一份定价快照，并保留现有经销商权限投影及 `BillingPluginVariants` 清空行为。读取失败走现有错误处理。
6. 开关关闭或账号豁免时返回对应原目录的完整响应。启用筛选时只裁剪响应副本中的模型及对应厂商筛选项，可附带筛选模式供空态使用。目录在模块访问校验前设置 `Cache-Control: private, no-store`，覆盖成功响应及鉴权拒绝。个人优惠结果只用于模型可见性。

### 前端接入

- 新增广场专用查询 hook 和查询键，仅模型广场列表及详情使用。现有 `usePricingData`、`['pricing']` 和旧 API 保留给用量日志与后台定价。广场详情直链根据同一份目录查找模型，沿用模型不可见时的处理。
- 广场查询键区分匿名身份和已登录用户 ID。复用会话切换的查询清理机制，在当前身份可用后请求对应目录。保存开关后使当前前端实例中的广场查询失效。专用查询显式设置 `refetchOnWindowFocus: 'always'` 和 `refetchOnMount: 'always'`。广场额外监听原生窗口聚焦事件，覆盖两个窗口同时可见时的切换。其他已打开页面在服务节点同步配置后的下一次聚焦或重新进入时刷新。
- 广场查询收到 HTTP 401 或 403 后停止使用已缓存的目录，列表和详情显示加载失败及重试入口。代理运营账号在广场卡片和详情中跳过性能请求，沿用现有性能接口授权。
- 已登录普通客户因优惠筛选而得到空目录时显示「暂无符合条件的优惠模型」。访客空目录及页面搜索、筛选产生的空列表沿用通用空态。新增文案只维护 `en` 和 `zh`。见[会话切换](../../../../web/src/routes/__root.tsx)、[前端约定](../../../../web/AGENTS.md)。

### 实施顺序与发布

1. 新增配置模块和目录 API，完成身份分流、厂商匹配及优惠判断的回归测试。
2. 接入系统设置和广场专用查询，验证空态、同会话刷新和跨窗口刷新。
3. 先部署目录和厂商归属 API，验证无自定义覆盖时匿名目录能命中内置国内厂商。发布前用管理员账号确认能预览、保存和恢复归属，再用普通客户样本核对优惠空态和海外优惠模型。
4. 如果需要恢复某类账号的原目录，关闭对应开关。需要回滚时，先回退前端到旧接口，再撤下专用目录入口。

## 验证与完成标准

| 验证场景 | 预期结果 |
| --- | --- |
| 四种开关组合 | 访客只随国内开关变化，开启时展示公开目录中的全部国内厂商模型。普通客户只随优惠开关变化，开启时可见享有优惠的海外模型 |
| Admin、Root、代理运营账号 | 每种开关组合下均获得本账号的原目录，代理运营账号可正常打开详情，列表和详情均跳过性能请求 |
| 关闭对应开关 | 访客和普通客户与同一身份调用原定价接口的目录逐项一致。覆盖已有授权但未打折的渠道，继续遵循原接口的授权和收录规则。代理运营账号通过新增只读路径访问完整目录 |
| 普通客户及代理体系下的客户 | 两类账号均受优惠开关约束。无优惠时返回空目录。覆盖组织级实时定价、个人覆盖为原价、加价及仅有优惠渠道停用或撤权 |
| 厂商归属 | 空旧名单使用内置识别，同名展示厂商和正式记录都能命中，旧名单自定义厂商继续可见。管理员可预览、保存和恢复归属，普通客户及代理运营账号无法写入 |
| 模块访问与请求凭据 | 匿名、浏览器会话和个人访问令牌在公开、要求登录、关闭模式下遵循现有访问合同。收到 HTTP 401 或 403 后，列表和详情撤下缓存目录 |
| 详情直链和会话切换 | 列表与详情规则一致。登录、退出及切换账号后使用当前身份的目录 |
| 开关保存、重启与双窗口 | 默认开启，显式关闭重启后保留。并发保存和重载后，本节点目录使用已提交的值。节点同步后，在另一窗口聚焦或重新进入时获取新目录 |
| 既有调用方 | 后台定价和历史用量详情仍读取原查询，原有模型调用入口通过回归验证 |

后端运行 `go test ./controller ./middleware ./model ./setting/... ./router`，覆盖配置默认值、解析和目录业务链路。本实施涉及选项持久化与批量渠道可用性查询，须在真实 SQLite、MySQL 和 PostgreSQL 实例上运行受影响场景，记录版本、命令和结果。前端从 `web/` 运行 `bun run test src/features/models src/features/pricing src/features/system-settings src/features/usage-logs`、`bun run typecheck`（Bun 未提供 `bun check` 时执行 `bunx tsgo -b`）、`bun run i18n:sync` 和 `bun run build`。如同步新增遗留语言条目，丢弃本次同步对 `zh-TW`、`fr`、`ru`、`ja`、`vi` 的改动，保留已有工作区改动。用浏览器核验四种组合、身份切换、详情直链、双窗口刷新和空态。
